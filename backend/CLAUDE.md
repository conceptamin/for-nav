# backend 작업 규칙

울산 외국인 의료 내비게이터의 API 서버(FastAPI)를 만드는 폴더다. 지금은 프론트 브라우저 안의 규칙·템플릿·mock을 그대로 옮긴 목업 서버이고, 나중에 LLM 호출과 학습 모델(`modeling/`)을 여기에 붙인다.
무엇을 만드는지(API 계약, 폴더 구조, 공통 규칙, 나중에 붙일 자리)는 `README.md`가 정하고, **무엇을 언제 만드는지는 `backlog/` 문서가 정한다.** 이 문서는 그 둘을 코드로 옮길 때 지키는 규칙이다.

브랜치·커밋·PR 규칙은 루트 `CLAUDE.md`를 따른다. 브랜치 영역은 `backend/`이다.

## 읽는 순서

1. 루트 `CLAUDE.md`
2. `backend/README.md` — API 목록과 요청·응답 예시, 폴더 구조, 공통 규칙, "나중에 붙일 자리". 여기에 없는 경로·필드를 새로 넣지 않는다.
3. `backend/backlog/` — 작업 항목. 사용자가 지정한 항목 하나만 구현한다.
4. 프론트와 맞춰야 할 때는 `frontend/src/domain/*.ts`(규칙·템플릿·타입의 원본), `frontend/scripts/dump-fixtures.ts`(동기화 테스트 입력 목록)
5. 모델을 붙일 때는 `modeling/README.md`, `modeling/models/*/metadata.json`, `modeling/src/fornav_modeling/predict.py`

## backlog 문서로 일한다

- `backlog/` 안의 문서 하나가 작업 항목 하나다. 파일 이름은 `NN-short-name.md`(예: `01-api-client-switch.md`)로 쓰고, 번호가 작은 것이 먼저다.
- 사용자가 항목을 말하지 않으면 미완료 항목 중 번호가 가장 작은 것을 고르고, 시작 전에 어느 항목을 하는지 말한다. `의존:`에 적힌 항목이 완료되지 않았으면 시작하지 않고 사용자에게 알린다.
- `backlog/`에 맞는 항목이 없으면 구현을 시작하지 않는다. `README.md`의 "구현 순서"와 "나중에 붙일 자리"를 근거로 아래 형식의 문서를 먼저 쓰고, 사용자가 확인한 뒤 구현한다.
- **지정된 항목의 범위만 구현한다.** 하다가 발견한 다른 일은 새 backlog 문서로 만들거나 기존 문서의 `## 메모`에 적고, 지금 작업에 섞지 않는다.
- 문서의 `## 완료 기준`을 그대로 검증한다. 기준이 모호하거나 검증할 방법이 없으면 구현 전에 사용자에게 묻는다.
- 끝나면 그 문서의 `## 결과`에 실행한 명령과 결과, 바뀐 API(경로·요청·응답), 테스트 수, 내린 결정과 이유를 적고 `상태:`를 바꾼다. 결과 기록은 코드와 같은 PR에 넣는다.
- backlog 문서와 `README.md`가 어긋나면 멈추고 사용자에게 묻는다. 임의로 한쪽을 고치지 않는다.

### backlog 문서 형식

```markdown
# NN. <제목>

상태: 대기 | 진행 중 | 완료 | 보류
의존: <먼저 끝나야 하는 항목 번호, 없으면 "없음">

## 목표
무엇을 왜 만드는지 두세 문장

## 범위
- 하는 것
- 하지 않는 것

## API·파일
추가·변경되는 경로와 요청·응답 형태, 만들거나 고치는 파일

## 완료 기준
- [ ] 검증할 수 있는 문장으로 쓴다 (예: `uv run pytest` 통과, `curl /api/...` 응답이 README 예시와 같음, `parity.json` 재생성 후 동기화 테스트 통과)

## 결과
(구현 후 작성) 실행 명령 → 결과, 바뀐 API, 결정 사항, 남은 문제

## 메모
```

## 스택과 폴더

- Python 3.12 + uv. FastAPI + Pydantic v2를 기준으로 하고, 버전은 `pyproject.toml`에 고정해 `uv.lock`을 커밋한다. 의존성을 더할 때는 backlog 문서에 이유를 적는다.
- 검사 도구는 ruff·pytest다. **ruff 설정의 기준은 이 폴더의 `pyproject.toml`이다.** `modeling/`이 이 설정을 따르므로, 바꿀 때는 두 폴더를 함께 고친다. `E501`을 끈 이유(어휘·템플릿 문장을 프론트와 한 줄씩 대조)는 유지한다.
- 폴더 구조는 `README.md`의 "폴더 구조"를 따른다. 새 모듈·폴더가 필요하면 backlog 문서에 이유를 적고 `README.md`의 구조 표를 함께 고친다.
- **로직은 `rules/`·`templates/`·`data/`, 경로는 `routers/`.** 라우터는 요청을 받아 함수를 부르고 응답을 돌려주는 얇은 파일로 유지한다. 라우터에 규칙·문구를 넣으면 동기화 테스트로 검증할 수 없다.
- 시각은 `clock.now()`로만 얻는다. `datetime.now()`를 직접 부르지 않는다. 테스트에서 시각을 고정할 수 있어야 한다.
- 상태는 `store.py`의 메모리 저장소 하나다. 전역 변수나 모듈 수준 캐시를 따로 두지 않는다.

## 설계에서 바꾸지 않는 것

- **API 계약은 프론트 타입과 1:1이다.** JSON 필드는 camelCase(`CamelModel`의 `alias_generator`), 파이썬 코드는 snake_case다. 열거값은 `vocab.py`의 `Literal`로 두어 잘못된 값은 422로 거절한다. 기존 응답 필드의 이름·타입·의미를 바꾸지 않고, 더할 때는 선택 필드로 더한다.
- **열거값의 단일 출처는 `vocab.py`다.** `BodyPart`, `Symptom`, `Department`(10종) 등을 바꾸면 프론트와 `modeling/`이 함께 깨진다. 바꿔야 하면 사용자에게 묻고, 승인되면 backlog 문서 `## 메모`에 영향 범위를 적는다.
- **프론트가 원본이다.** 규칙·템플릿·mock은 `frontend/src/domain/*.ts`를 옮긴 것이다. 서버와 프론트가 어긋나면 서버를 고친다. 프론트 쪽이 틀렸다고 판단되면 서버를 임의로 다르게 만들지 않고 사용자에게 묻는다.
- **`tests/fixtures/parity.json`은 손으로 고치지 않는다.** 항상 `README.md`의 "프론트 동기화 테스트" 명령으로 프론트 코드에서 다시 만든다. 기대값을 서버 출력에 맞추는 방향으로 고치지 않는다.
- **규칙·템플릿은 결정적이다.** 난수·현재 시각·LLM·외부 호출을 넣지 않는다. 시각이 필요한 곳(`createdAt`, 운영 시간 외 판정, 나이)만 `clock`을 쓰고, 계산은 모두 `Asia/Seoul` 기준이다.
- **진단 표현을 넣지 않는다.** 템플릿을 옮기거나 고칠 때 문구를 바꾸지 않고, 병명·추측 문장을 새로 넣지 않는다.
- **진료과는 규칙표가 먼저다.** 규칙표가 명시적으로 정한 조합은 규칙표 그대로이고, 모델은 막연한 분기만 바꾼다. 모델 결과는 `TriageResult.model` 같은 선택 필드로만 더한다.
- **응급 여부를 판정하지 않는다.** 틀린 판정이 헛된 확신을 주지 않게 응급 규칙·보조 점수·응급도 모델을 지웠다(사용자 결정, 2026-10-31, backlog 26). 119는 프론트가 판정 없이 늘 보이는 버튼으로 안내한다. 응급 판정을 다시 넣으려면 사용자에게 먼저 묻는다.
- **서버가 계산한다.** 센터 사례의 요약·긴급도·운영 시간 외 여부·id·접수 시각은 클라이언트가 보낸 값을 믿지 않고 같은 입력으로 다시 만든다.
- **개인 단위 기록을 내보내지 않는다.** `/api/center/stats`는 집계만 돌려주고 5건 미만 칸은 `null`로 가린다. 원천 레코드를 돌려주는 경로를 만들지 않는다.
- **서버는 근로자 회원 정보를 저장하지 않는다.** 근로자 상태(언어, 동의, 입력, 프로필, 리포트)는 브라우저에 둔다. 근로자 Google 로그인(backlog 21)은 `sub`에서 만든 계정 키와 세션 해시만 저장하고, 이름·이메일·사진은 저장하지도 응답에 넣지도 않는다. 푸시 기기 토큰(backlog 28)은 계정이 아니라 사례에만 묶어 마지막 등록 뒤 30일 보존한다. 연락처·자유 입력·요청 본문·ID 토큰·푸시 기기 토큰·알림 문구는 로그에 남기지 않는다.

## 프론트·모델링과의 경계

- `frontend/` 코드는 이 폴더의 작업에서 고치지 않는다. 프론트의 API 전환(`src/api/`, Vite 프록시)은 `frontend/` 브랜치로 따로 한다. 예외는 `frontend/scripts/dump-fixtures.ts`의 **입력 목록 추가**다. 동기화 테스트의 일부이므로 `parity.json` 재생성과 함께 같은 PR에 넣는다.
- `modeling/` 코드는 이 폴더의 작업에서 고치지 않는다. 모델링은 아티팩트와 "입력 dict → 출력 dict" 순수 함수를 주고, 서버는 그것을 부른다. 모델링 쪽 스키마를 바꿔야 하면 backlog 문서 `## 메모`에 적고 사용자에게 알린다.
- 진료과 추천 경로(`/api/triage`)는 프론트가 실패 시 브라우저 규칙으로 대체한다. 서버 규칙이 프론트 규칙과 다르면 온라인·오프라인 결과가 달라지므로, 이 경로의 동기화 테스트는 반드시 통과시킨다. 자유 입력 추출(`/api/extract`)도 실패하거나 시간 제한을 넘기면 프론트가 브라우저 키워드 추출로 대체한다.

## LLM과 모델을 붙일 때

`README.md`의 "나중에 붙일 자리" 표에 있는 자리에만 붙인다. 붙이는 작업마다 backlog 문서 하나를 둔다.

- **실패하면 지금 템플릿·규칙으로 돌아간다.** LLM이 느리거나(타임아웃) 형식이 틀리면 기본 템플릿을 그대로 쓰고, 응답에 어느 쪽을 썼는지 알 수 있는 선택 필드를 둔다. LLM 실패가 API 실패가 되지 않게 한다.
- **LLM 출력은 JSON 스키마로 고정한다.** `/api/extract`의 추출값은 `vocab.py`의 열거값으로 검증하고, 벗어난 값은 버린다. LLM이 쓴 문장은 진단·병명이 들어 있지 않은지 검사한 뒤 내보낸다.
- **원문을 남기지 않는다.** 요청 본문, 자유 입력, LLM 프롬프트·응답은 로그에 남기지 않는다. 오류는 `request_id`로 추적한다.
- **API 키·모델 이름·타임아웃은 환경 변수로 받는다.** 코드에 쓰지 않고, `.env`는 커밋하지 않는다. 키가 없으면 LLM 자리를 건너뛰고 템플릿으로 동작해야 한다(발표장 네트워크 문제 대비).
- **모델 아티팩트는 불러올 때 코드를 실행하지 않는 형식만 읽는다.** LightGBM 텍스트 모델, JSON. pickle·joblib은 읽지 않는다. 아티팩트 옆 `metadata.json`의 버전·피처 순서·임계값을 그대로 쓰고 서버 코드에 다시 적지 않는다.
- 테스트는 LLM과 모델을 가짜로 바꿔 돌린다. 네트워크 없이 `uv run pytest`가 통과해야 하고, CI도 그렇게 돈다.

## 검사와 커밋

```sh
cd backend
uv sync
uv run ruff check . && uv run ruff format --check .
uv run pytest
```

프론트 규칙·템플릿·mock을 옮기거나 동기화 테스트 입력을 더했을 때는 기대값을 다시 만든 뒤 테스트를 돌린다.

```sh
cd frontend
npx rolldown scripts/dump-fixtures.ts --file /tmp/dump.mjs --format esm && TZ=Asia/Seoul node /tmp/dump.mjs > ../backend/tests/fixtures/parity.json
```

- 커밋 메시지의 `테스트:` 줄에 위 명령 결과를 적는다. 문서만 바꿨으면 그렇게 적는다.
- 경로를 더하거나 바꿨으면 `tests/test_api.py`에 상태 코드·응답 형태 테스트를 더하고, `README.md`의 API 표와 요청·응답 예시를 같은 PR에서 고친다.
- 규칙·템플릿을 바꿨으면 `tests/test_parity.py`가 그 분기를 지나는지 확인한다. 입력 목록에 없으면 `dump-fixtures.ts`에 더한다.
- CI의 `backend` 작업(`.github/workflows/ci.yml`)은 위 세 명령을 그대로 돈다. CI 단계를 바꾸는 것은 `chore/` 영역의 별도 작업이다.
