# 화면을 그리는 규칙

`src/styles.css` 한 파일과 `src/components/`의 공통 조각으로 화면을 그릴 때 지키는 규칙이다. 모양의 기준은 **클레이모피즘(Claymorphism)** 이다. 점토 인형처럼 동글동글하고 푹신한 면이 화면 바닥 위에 올라앉아 있고, 누르면 점토가 눌리듯 안으로 들어간다. 여기에 없는 모양을 새로 그릴 때는 이 문서를 먼저 고친다. 무엇을 보여 주는지는 `README.md`, 코드 규칙은 `CLAUDE.md`가 정한다.

지금 `styles.css`는 평면 카드(흰 배경 + 얇은 테두리 + 2겹 그림자) 스타일이다. 이 문서대로 옮기는 일은 backlog 항목 하나(클레이모피즘 적용)로 한꺼번에 하고, backlog 04(토큰 밖 색상 정리, 끝남) 다음에 한다. 적용 전에 새 화면을 그릴 때는 지금 `styles.css`의 클래스를 그대로 쓰고 클레이 모양을 화면 쪽에서 따로 흉내 내지 않는다. 적용 항목이 클래스 단위로 한 번에 바꾼다.

## 두 영역의 원칙

| 영역 | 경로 | 기준 | 원칙 |
|---|---|---|---|
| 근로자 | `/` ~ `/my`, `/guide` | 모바일 우선. 360px 폭에서 설계하고 `.w-shell`은 480px까지만 넓어진다 | **한 손으로, 큰 글씨로, 글을 다 읽지 못해도 누를 수 있게.** 화면 하나에 묻는 것은 하나다. 119는 언제나 한 번 누르면 걸린다 |
| 센터 | `/center*` | PC 우선. `.c-main`은 1280px, 900px 이하에서 한 열로 접힌다 | **밀도와 한눈에 보이는 상태.** 표·칩·KPI로 많은 사례를 비교한다. 담당자는 한국어를 읽는다 |
| 응급 | `/emergency` | 근로자 영역이지만 따로 취급 | 빨간 전면 히어로 하나와 전화 버튼 하나. 다른 정보는 그 아래로 내린다. 하단 119 띠는 이 화면에서만 숨긴다(버튼이 중복되므로) |

근로자 화면의 공통 틀은 `WorkerLayout`(헤더 + 언어 선택 + 하단 119 띠), 센터 화면은 `CenterLayout`(상단 브랜드 + 탭 메뉴)이다. 화면 컴포넌트는 틀을 다시 그리지 않는다.

## 클레이모피즘

점토로 빚은 인형의 느낌을 CSS로 옮긴 것이다. 세 가지가 전부다.

1. **큰 둥글기.** 모서리가 보이지 않는다. 카드 20px, 버튼·칩·입력란 16px, 응급 전화 버튼과 홈 메뉴 항목 28px. 직각 모서리는 표의 셀과 구분선뿐이다.
2. **푹신한 3D 안쪽 그림자.** 빛은 항상 **왼쪽 위**에서 온다. 면의 왼쪽 위 안쪽 가장자리에 흰 하이라이트, 오른쪽 아래 안쪽 가장자리에 어두운 음영을 `inset` 그림자로 넣어 가운데가 부풀어 보이게 한다. 그 아래로 부드러운 바깥 그림자 하나를 깔아 바닥에서 떠 있게 한다. 이 셋을 합친 것이 `--clay`다.
3. **누르면 들어간다.** 눌린 상태(`:active`, `aria-pressed="true"`, 입력란)는 바깥 그림자를 없애고 안쪽 그림자의 방향을 뒤집어(왼쪽 위가 어둡고 오른쪽 아래가 밝다) 점토가 눌려 들어간 모양이 된다. 이것이 `--clay-in`이다.

면은 **테두리로 모양을 만들지 않는다.** 지금의 `1.5px solid var(--line)` 테두리는 전부 안쪽 그림자로 바꾼다. 테두리를 남기는 곳은 포커스 윤곽, 표의 줄, 3언어 줄·리포트 행의 구분선뿐이다.

### 세 가지 면

모든 조각은 아래 셋 중 하나다. 새 조각을 그릴 때 먼저 어느 면인지 정하고 그 토큰을 쓴다. `box-shadow`에 값을 직접 쓰지 않는다.

| 면 | 토큰 | 뜻 | 쓰는 곳 |
|---|---|---|---|
| 떠 있음 | `--clay` / `--clay-sm` | 바닥 위에 올라앉은 점토 덩어리. 누를 수 있거나 내용을 담는 것 | 카드, 버튼, 칩, 홈 메뉴, 진료과 상자, 응급 전화 버튼, 하단 119 띠, KPI, 패널, 표 상자 |
| 들어감 | `--clay-in` | 점토를 눌러 만든 홈. 값을 받거나 눌린 것 | 입력란, textarea, select, 눌린 버튼(`:active`), 선택된 칩·토글·필터, 단계 점 트랙, 모국어 원문 상자, 막대 트랙 |
| 평평 | 없음 | 그림자 없이 파스텔 배경만. 시선을 끌지 않아야 하는 것 | 안내 상자(`notice`), 긴급도·상태 칩(`pill`), 헤더, 표의 행, 각주 |

색이 있는 면(브랜드 버튼, 응급 히어로, 119 띠)은 흰 하이라이트가 흰 면에서보다 약하게 보여야 하므로 `--clay-color` / `--clay-color-sm`을 쓴다. 하이라이트와 음영의 알파만 다르고 방향·크기는 같다.

### 비활성

`disabled`는 떠 있음을 유지한 채 `opacity: 0.45`로 흐리게만 한다. 그림자를 평평하게 만들지 않는다(서버 응답을 기다리는 동안 버튼이 사라진 것처럼 보이면 안 된다).

## 토큰

색·둥글기·그림자·글자 크기는 `:root`의 CSS 변수로만 정한다. 새 색이 필요하면 **토큰을 먼저 더하고** 그 토큰을 쓴다. 클래스 안에 16진수 색이나 `box-shadow` 값을 직접 쓰지 않는다.

파스텔 배경(`*-bg`, `--brand-2`)은 평평한 면과 들어간 면의 바탕이다. 그 위 글자는 각각의 진한 색(`--ok`, `--warn`, `--danger-2`, `--brand`)이고 대비 4.5:1을 지킨다.

### 둥글기

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--radius` | `20px` | 카드, 패널, KPI, 표 상자, 진료과 상자, 응급 히어로 |
| `--radius-sm` | `16px` | 버튼, 칩, 입력란, 안내 상자, 체크 한 줄, 토글, 필터 |
| `--radius-lg` | `28px` | 응급 전화 버튼, 홈 메뉴 항목, 하단 119 버튼 |
| `999px` | 토큰 없음 | 긴급도·상태 칩(`pill`), Demo 배지, 단계 점 |

면의 높이가 둥글기의 2배보다 작으면 알약 모양이 된다. 48px 버튼에 16px은 괜찮고, 36px 센터 필터에는 `--radius-sm` 대신 12px을 쓴다(아래 센터 표).

### 그림자

빛의 방향(왼쪽 위)과 세 면의 구분은 이 토큰이 전부 정한다. 값은 `:root`에만 있다.

```css
:root {
  /* 재료 */
  --clay-light: rgb(255 255 255 / 85%);   /* 왼쪽 위 하이라이트 */
  --clay-dark: rgb(18 35 46 / 12%);        /* 오른쪽 아래 음영 */
  --clay-drop: rgb(18 35 46 / 10%);        /* 바닥 그림자 */

  /* 떠 있음: 카드·패널·KPI·메뉴·진료과 상자 */
  --clay:
    0 8px 16px var(--clay-drop),
    inset 6px 6px 12px var(--clay-light),
    inset -6px -6px 12px var(--clay-dark);

  /* 떠 있음(작게): 버튼·칩·체크·토글·필터 */
  --clay-sm:
    0 4px 8px var(--clay-drop),
    inset 3px 3px 6px var(--clay-light),
    inset -3px -3px 6px var(--clay-dark);

  /* 들어감: 입력란·눌린 버튼·선택된 칩·트랙 */
  --clay-in:
    inset 4px 4px 8px var(--clay-dark),
    inset -3px -3px 6px var(--clay-light);

  /* 색이 있는 면: 브랜드 버튼·응급 히어로·119 띠 */
  --clay-color:
    0 8px 16px var(--clay-drop),
    inset 4px 4px 10px rgb(255 255 255 / 35%),
    inset -4px -4px 10px rgb(0 0 0 / 20%);
  --clay-color-sm:
    0 4px 8px var(--clay-drop),
    inset 3px 3px 6px rgb(255 255 255 / 35%),
    inset -3px -3px 6px rgb(0 0 0 / 20%);
  --clay-color-in:
    inset 4px 4px 8px rgb(0 0 0 / 22%),
    inset -3px -3px 6px rgb(255 255 255 / 25%);
}
```

- 안쪽 그림자의 양수 오프셋(`6px 6px`)은 왼쪽 위 안쪽 가장자리에, 음수 오프셋(`-6px -6px`)은 오른쪽 아래 안쪽 가장자리에 생긴다. 하이라이트는 양수, 음영은 음수가 "왼쪽 위에서 오는 빛"이다. 들어감은 그 반대다.
- 바깥 그림자는 하나뿐이고 아래로만(`0 8px`) 떨어진다. 옆이나 위로 퍼지는 그림자, 여러 겹의 바깥 그림자를 만들지 않는다.
- 안쪽 그림자가 가장자리 6px(작은 면 3px)을 차지하므로 **글자가 음영 위에 놓이지 않게** 면의 안쪽 여백은 가로 12px 아래로 내리지 않는다.
- 옛 `--shadow`(2겹 바깥 그림자)는 없앤다. 쓰던 곳은 전부 `--clay`나 `--clay-sm`이 된다.

### 눌림의 예

```css
.card { background: var(--card); border-radius: var(--radius); box-shadow: var(--clay); padding: 16px; }

.btn { background: var(--brand); color: var(--on-brand); border: 0; border-radius: var(--radius-sm); box-shadow: var(--clay-color-sm); }
.btn:active { box-shadow: var(--clay-color-in); }
.btn.secondary { background: var(--card); color: var(--brand); box-shadow: var(--clay-sm); }
.btn.secondary:active { box-shadow: var(--clay-in); }
.btn.ghost { background: transparent; box-shadow: none; }           /* 평평. 되돌아가기 */

.chip { background: var(--card); border: 0; border-radius: var(--radius-sm); box-shadow: var(--clay-sm); }
.chip[aria-pressed='true'] { background: var(--brand-2); box-shadow: var(--clay-in); font-weight: 700; }
.chip[aria-pressed='true']::before { content: '✓'; color: var(--brand); }

input[type='text'], textarea, select.input { background: var(--card); border: 0; border-radius: var(--radius-sm); box-shadow: var(--clay-in); }
```

눌림은 `:active`에서 즉시 바뀌고 되돌아온다. `transition`을 달지 않는다("하지 않는 것"). `:hover`에는 아무것도 하지 않는다. 근로자는 손가락으로 누르므로 호버가 없고, 센터 표의 행 강조만 예외다.

### 색의 의미

- **근로자 화면에서 빨강은 119와 응급에만 쓴다.** "심해지면 119" 안내(`Worse119`), 응급 히어로, 하단 띠, 위험 버튼(삭제)만 빨강이다. 오류 문구는 빨강 안내(`notice.danger`)를 쓰되 119 안내보다 눈에 띄게 만들지 않는다.
- 센터 화면에서는 긴급도 "높음" 칩이 빨강이다. 담당자에게는 자연스러운 신호이고, 센터 화면에는 119 버튼이 없어 혼동이 없다.
- 브랜드색은 선택됨과 주 동작이다. 장식으로 쓰지 않는다.
- `warn`은 "확인이 필요하다"는 뜻이다. 제도 안내, 운영 시간 외, 진행 중 상태가 여기에 속한다.
- `ok`는 끝났거나 해당된다는 뜻이다.
- **그림자는 뜻을 전하지 않는다.** 떠 있음과 들어감은 "누를 수 있다"와 "눌렸다·값을 받는다"의 느낌일 뿐이고, 선택됨은 ✓와 굵기, 상태는 글자가 전한다.

## 글자

- 글꼴은 **시스템 글꼴**이다. `font-family`에 적힌 Pretendard·Noto Sans KR은 기기에 있을 때만 쓰이고, 웹폰트를 내려받지 않는다. 발표장 네트워크에 기대지 않고, 베트남어 성조 글리프도 시스템 글꼴이 안전하다. 클레이모피즘 예시에 흔한 둥근 전용 글꼴(Nunito 등)도 들이지 않는다. 둥근 느낌은 면이 내고 글자는 읽히는 쪽을 택한다.
- 기본 크기 1rem(16px), 줄 간격 1.5. 아래 단계만 쓴다.

| 단계 | 크기 | 쓰는 곳 |
|---|---|---|
| 한국어 크게 | 1.6rem / 1.45rem / 1.2rem | 진료과 이름(`.dept .ko`), 접수 창구 문장(`.ko-big`), 3언어 줄의 한국어(`.line .ko`). 창구 직원이 휴대폰 화면을 건너 읽는 크기다 |
| 응급 | 1.7rem / 1.5rem | 응급 전화 버튼, 응급 히어로 제목 |
| 제목 | 1.45rem / 1.15rem / 1rem | h1 / h2 / h3. 화면에 h1은 하나다 |
| 본문 | 1rem | 본문, 버튼, 칩(0.98rem) |
| 보조 | 0.92rem / 0.85rem | 안내 상자, 발음·모국어 줄, 작은 설명 |
| 최소 | 0.82rem | 각주(`.footer-note`), 센터 칩. 이보다 작게 쓰지 않는다. 예외는 헤더의 "Demo" 배지(0.72rem) 하나다 |
| 센터 숫자 | 1.8rem | KPI 수치 |

- 한국어로 고정된 글(접수 창구 문장, 전화 스크립트, 센터 화면)에는 `lang="ko"`를 단다. 근로자가 고른 언어의 글에는 문서 언어를 따르게 둔다.
- 버튼·칩·메뉴 제목은 굵게(700 이상)다. 푹신한 면 위에 가는 글자는 떠 보인다.

| 요소 | 최소 높이 |
|---|---|
| 응급 전화 버튼(`.em-call`) | 76px |

## 화면 유형별 규칙

| 유형 | 화면 | 구성 순서 |
|---|---|---|
| 입력 | S-02, S-03, S-05, S-11 항목 선택, S-12 | h1 → (단계 점) → 질문 하나와 칩·입력란 → 안내 상자 → 아래에 되돌아가기(ghost) + 다음(block) |
| 결과 | S-07, S-08, S-09, S-10 | h1 → 핵심 결과를 크게(진료과·경로·한국어 문장) → 다음 행동 버튼(지도·전화·접수) → `Worse119` → `PolicyDisclaimer`(제도 정보가 있을 때) |
| 응급 | S-06 | `.em-hero`(제목·이유) + `.em-call` → 응급실 지도 → 그 아래 홈으로 돌아가는 ghost 버튼 |
| 리포트 | S-11 | 언어 토글 → `.report-row` 목록 → 저장·삭제 |
| 센터 목록 | C-01 | KPI 4개 → 필터 → 표. 새 사례는 맨 위 |
| 센터 상세 | C-02 | 긴급도·상태 칩 → 2열(요약·연락 / 원문·상태 변경) |
| 센터 통계 | C-03 | 기간·구군 필터 → KPI → 막대·도넛 |

- 응급으로 가는 길은 어느 화면에서도 두 번 이상 누르지 않는다. 하단 띠 한 번, 응급 화면에서는 전화 버튼 한 번.
- 결과 화면은 스크롤 없이 첫 화면에 핵심 결과와 첫 행동 버튼이 보여야 한다(360×640 기준). 둥글기와 그림자 때문에 카드 간격이 16px로 늘었으므로 적용 후 다시 확인한다.
- 입력 화면에서 화면이 바뀌면 맨 위로 올린다(`WorkerLayout`이 처리).
- 한 화면에 떠 있는 면은 **세로로 쌓인 몇 덩어리**까지다. 화면 전체가 푹신하면 아무것도 눈에 띄지 않는다. 핵심 결과 카드 하나, 행동 버튼, 그 아래 평평한 안내가 기본 리듬이다.

## 접근성

- **색만으로 뜻을 전하지 않는다.** 선택됨은 ✓ + 들어감 + 굵기, 긴급도·상태는 칩 글자, 응급은 글과 전화 아이콘. 그림자(떠 있음·들어감)만으로도 뜻을 전하지 않는다. 그림자는 고대비 모드나 저화질 화면에서 사라질 수 있다.
- 고르는 버튼은 `button` + `aria-pressed`. `div`에 클릭을 달지 않는다.
- 아이콘은 이모지이고 전부 `aria-hidden`이다. **뜻은 항상 옆 글자가 전한다.** 기기마다 모양이 다른 것은 감수한다. SVG 아이콘 세트로 바꾸는 것은 별도 항목이다.
- 입력란에는 보이는 `label`을 둔다. 헤더의 언어 선택처럼 레이블을 보일 자리가 없을 때만 `aria-label`.
- 포커스 윤곽(`:focus-visible`, 3px)은 끄지 않는다. `outline-offset: 2px`로 면 바깥에 그려 둥글기·그림자와 겹치지 않게 한다. 입력란은 테두리가 없으므로 포커스 윤곽이 유일한 "지금 여기" 표시다.
- 장식용 요소(단계 점, 막대 트랙)는 `aria-hidden`이고 같은 정보를 글로 둔다.
- 한국어 고정 글에 `lang="ko"`, 집계 그림에 `role="img"` + `aria-label`.
- 대비는 본문 `--ink`/`--card` 기준으로 WCAG AA 이상을 지킨다. 새 토큰을 더할 때 글자색은 배경 위 4.5:1을 확인한다. 안쪽 음영이 깔린 가장자리에는 글자를 두지 않으므로 대비는 바탕색 기준으로 잰다.
- 입력란(들어감)과 그 바탕 카드(떠 있음)는 둘 다 `--card`색이다. 입력란의 경계는 안쪽 그림자뿐이므로, 카드 안에서 입력란 위에는 보이는 `label`을 반드시 둔다(위 규칙과 같다).

## 하지 않는 것

- UI 라이브러리, CSS 모듈, CSS-in-JS, Tailwind. `styles.css` 한 파일과 클래스 이름으로 끝낸다.
- 다크 모드. `prefers-color-scheme`을 보지 않는다.
- 애니메이션·전환 효과. 상태 변화는 즉시 바뀐다. 눌림(`:active`)도 `transition` 없이 그림자만 바뀐다. `transform: scale()`로 눌림을 흉내 내지 않는다.
- 토큰 밖 색상 하드코딩, 임의 글자 크기, 8px 단위 밖 간격, 토큰 밖 `box-shadow`·`border-radius` 값.
- 면의 테두리(`border`). 모양은 그림자가 만든다. 예외는 포커스 윤곽, 표의 줄, 구분선.
- 그라데이션 채움, 블러(`backdrop-filter`), 반투명 유리(글래스모피즘), 바탕과 같은 색의 면(뉴모피즘). 점토는 불투명하고 바닥보다 밝다.
- 3D 변형(`perspective`, `rotate`), 여러 방향의 빛. 빛은 왼쪽 위 하나다.
- 둥근 전용 글꼴, 두꺼운 외곽선 글자, 그림자 글자(`text-shadow`).
- 새 인라인 `style`. 지금 있는 것(버튼 사이 `marginTop` 몇 곳)은 간격만이고 색은 없다. 더 늘리지 않고, 반복되면 수식 클래스로 옮긴다.
- 웹폰트 내려받기, 외부 아이콘 CDN.
- 스피너·스켈레톤·토스트·모달. 확인이 필요하면 `window.confirm`(센터 데모 초기화처럼) 하나로 끝낸다.
- 근로자 화면에서 가로 스크롤, 고정 폭 표, 호버에만 나타나는 정보.

## 새 스타일을 더하는 절차

1. 위 컴포넌트 표의 것으로 그릴 수 있는지 먼저 본다. 변형이 필요하면 기존 클래스에 수식 클래스(`.btn.big`처럼)를 더한다.
2. 세 가지 면 중 어느 것인지 정한다(떠 있음 / 들어감 / 평평). 떠 있음이면 카드 크기인지(`--clay`) 버튼 크기인지(`--clay-sm`), 색이 있는지(`--clay-color*`)를 정한다. 눌리는 것이면 눌린 모양(`--clay-in`)도 같이 정한다.
3. 새 색·크기가 필요하면 `:root` 토큰을 먼저 더하고 이 문서의 토큰 표에 적는다. 그림자는 새 토큰을 만들지 않고 위 여섯 가지 중에서 고른다. 일곱 번째가 필요하면 이 문서의 "세 가지 면"부터 고친다.
4. 클래스는 `styles.css`의 해당 섹션 주석(`/* ---------- 공통 요소 ---------- */` 같은) 아래에 둔다. 근로자 전용은 `w-`, 센터 전용은 `c-` 접두, 양쪽 공통은 접두 없이.
5. 이 문서의 컴포넌트 표나 화면 유형 표에 한 줄을 더하고 "면" 열을 채운다. 문서에 없는 모양은 다음 사람이 다시 만들게 된다.
6. 360px 폭(근로자) 또는 1280px·900px 아래(센터)에서 직접 보고, en·vi·ko 세 언어로 글이 넘치지 않는지 확인한다. 베트남어가 가장 길다. 둥글기가 크므로 긴 베트남어가 모서리 안쪽 음영에 걸리지 않는지도 본다.

## 클레이모피즘 적용 항목이 할 일

이 문서대로 `styles.css`를 옮기는 backlog 항목의 범위다. 문서를 고칠 때 같이 고친다.

- `:root` 밖에는 16진수 색이 없다(backlog 04). 색은 토큰 이름을 그대로 쓰고, 바꿀 것은 `:root` 값과 `box-shadow`·`border`·`border-radius`뿐이다
- `:root`: `--bg`·`--card`·파스텔 값 교체, `--radius-sm`·`--radius-lg` 추가, `--shadow` 제거와 `--clay*` 여섯 토큰 추가
- 떠 있음: `.card`, `.btn`(+ `secondary`·`danger`), `.chip`, `.check`, `.menu a`, `.dept`, `.em-hero`, `.em-call`, `.bar-119 a`, `.kpi`, `.table-wrap`, `.panel`, `.filters button`, `.toggle`
- 들어감: `input`·`textarea`·`select.input`, `.chip[aria-pressed='true']`, `.check:has(:checked)`, `.steps span`, `.menu a .ico`, `.native-box`, `.bar-track`, `.c-header nav a.active`, 떠 있는 것들의 `:active`
- 테두리 제거: `.btn`, `.chip`, `.check`, `.dept`, `.toggle`, `.filters`, 입력란
- 둥글기 교체: 위 표의 토큰대로
- 간격: `.card`·`.menu`·`.kpi`·`.panel` 사이 16px
- 확인: 360px에서 `/home`, `/intake`, `/result`, `/visit/desk`, `/report/new`, `/report/:id`, `/emergency`, 1280px·900px 아래에서 `/center`, `/center/stats`, en·vi·ko. 결과 화면의 첫 화면 규칙(360×640)
