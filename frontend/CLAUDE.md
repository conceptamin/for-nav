# for-nav 작업 규칙

울산 외국인 의료 내비게이터 데모 앱(Vite + React + TypeScript)이다. 실행 방법과 화면 구성은 `README.md`에 있다.

## 새 작업은 반드시 새 브랜치에서 시작한다

AI도 사람과 같은 규칙을 따른다. 아래 순서를 건너뛰지 않는다.

1. **작업 전에 현재 브랜치를 확인한다.** `git status`, `git branch --show-current`
2. **새 작업이면 최신 `main`에서 새 브랜치를 만든다.** 사용자가 브랜치를 따로 말하지 않아도 만든다.
   ```sh
   git fetch origin
   git switch -c <영역>/<짧은-설명> origin/main
   ```
3. **커밋하지 않은 변경이 있으면 브랜치를 바꾸기 전에 멈추고 사용자에게 묻는다.** 임의로 `stash`, `reset`, `checkout --`로 지우거나 옮기지 않는다.
4. 작업이 끝나면 그 브랜치에서 커밋하고 PR을 연다(`gh pr create --base main`).

### 언제 새 브랜치를 만드는가

| 상황 | 할 일 |
|---|---|
| `main`에 있다 | 무조건 새 브랜치를 만든다. `main`에서는 파일을 고치지 않는다. |
| 다른 주제의 브랜치에 있다 | 새 브랜치를 만든다. 지금 브랜치에 다른 주제를 섞지 않는다. |
| 이미 병합된 브랜치에 있다 | 새 브랜치를 만든다. 병합된 브랜치에서 이어서 작업하지 않는다. |
| 같은 주제의 작업 중인 브랜치에 있다 | 그 브랜치에서 계속한다. 애매하면 사용자에게 묻는다. |

### 브랜치 이름

```text
<영역>/<짧은-설명>      예: frontend/report-toggle, docs/claude-md, chore/ci-build
```

| 영역 | 언제 |
|---|---|
| `frontend` | 화면·컴포넌트·클라이언트 로직(`src/`) |
| `backend` | API·규칙 엔진·LLM 호출 |
| `modeling` | 모델·데이터·평가 |
| `docs` | `README.md`, `CLAUDE.md` 등 문서 |
| `chore` | CI, `.github/`, 빌드·저장소 설정 |

- 설명은 영어 소문자와 `-`로 짧게 쓴다.
- 브랜치 하나에는 한 주제만 담는다. 여러 영역을 건드리면 주된 영역을 쓴다.

## 하지 않는 것

- `main`에 직접 커밋하거나 push하지 않는다.
- 강제 push(`--force`), 훅·룰셋 우회(`--no-verify`)를 하지 않는다.
- PR 병합(`gh pr merge`)과 브랜치 삭제는 사용자가 요청할 때만 한다.

## 커밋 메시지

```text
<무엇을 위해 무엇을 바꾸는지 한 줄>

- <파일·폴더>: <바꾼 내용>

테스트: <실행한 명령> → <결과>
```

- 한국어 평서형(`~한다`)으로, 마침표 없이 쓴다. `feat:` 같은 type 접두사는 쓰지 않는다.
- 커밋 전에 `npm run build`(타입 검사 + 빌드)를 돌리고 결과를 `테스트:` 줄에 적는다. 문서만 바꿨으면 그렇게 적는다.
- PR 본문은 `.github/pull_request_template.md`가 있으면 그 형식을 따른다.
