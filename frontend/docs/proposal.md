# for-nav 프론트 기획서

기준일: 2026-10-24 · 목표 기획 · 기준: [공통 기획서](../../docs/proposal.md)

## 1. 목표와 기반

외국인 주민의 모국어 텍스트 상담과 센터 상담사의 접수·후속 업무를 연결한다. React·TypeScript·Vite 기반과 [phase-01](phase-01.md)의 실행·검증 기록은 유지한다. 아래 화면은 목표이며 현재 구현된 경로나 API를 의미하지 않는다.

## 2. 화면

| 대상 | 화면 | 핵심 |
|---|---|---|
| 사용자 | 언어 선택·상담 시작 | “어떤 도움이 필요하세요?”, 자유 입력·유형 버튼 |
| 사용자 | 채팅 | 한 번에 한 질문, 모름·건너뛰기·수정, AI·직원 표시 |
| 사용자 | 요약·보험 확인 | 출처·시점·조회 범위, 미가입과 미확인 구분 |
| 사용자 | 전달 확인 | 모국어 요약 수정, 전달 항목 선택과 동의 |
| 사용자 | 진행·후속 상담 | 실제 접수 상태, 직원 추가 질문, 결과 |
| 상담사 | 접수 목록 | 유형·담당자·상태 |
| 상담사 | 상세 | 한국어 요약·원문·번역, 확인 항목, 응대·연계 기록 |

가입 시 건강정보를 일괄 요구하지 않는다. 연락처 등은 회신에 필요한 때 수집한다. 보험 확인은 관련 상담에서 제안하며 거절·조회 실패에도 진행한다. 긴급 도움 경로를 로그인·설문 뒤에 숨기지 않는다. 음성 입력은 MVP에서 제외한다.

## 3. 상태·동의·언어

서버의 상담 건 상태와 실제 조회·접수 결과를 표시한다. 조회 실패를 미가입으로, 요청 전송을 접수 완료로 표현하지 않는다. 원문·번역·사용자 수정본의 관계를 확인할 수 있게 한다.

외부 AI 전송, 보험 조회, 센터 전달의 동의 목적을 구분한다. 인증정보는 채팅에서 입력받지 않는다. 상담사의 접근은 인증·권한 검사를 전제로 한다. 저장·보관·삭제 정책은 새 계약에서 확정하며 기존 기기 전용 저장 규칙을 새 설계로 그대로 옮기지 않는다.

정적 UI는 언어 파일로 관리한다. 동적 대화·번역은 검증된 서버 출력으로 표시하며 en·vi 등 우선 언어와 검수 방식은 센터와 확정한다. 360px 사용자 화면, 44px 이상 터치 영역, 키보드 조작, 색상 외 상태 표시를 유지한다. 외부 분석 도구에 상담 내용을 보내지 않는다.

## 4. 완료 기준 초안

- 비부상 상담(예약·서류·통역)도 접수·응대·종결까지 완료된다.
- 이미 답한 정보 수정, 모름·건너뛰기, 번역 오류 수정이 가능하다.
- 사용자 진술과 조회로 확인된 보험 정보를 구분한다.
- 동의 없이 센터로 전달하지 않으며 제외 항목이 전달되지 않는다.
- 직원 추가 질문과 사용자 답변이 같은 상담 건에 연결된다.
- 인증 실패·AI 실패·조회 실패·중복 접수 재시도를 검증한다.
- 권한 없는 상담 접근을 막고 사용자 화면·상담사 화면을 각각 E2E 검증한다.

## 5. 전환

[이전 phase-02](phase-02.md)는 보존된 과거 계획이다. 새 [백엔드 기획](../../backend/docs/proposal.md)의 인증·상담 API 계약 확정 후 경로·타입·저장 방식과 새 phase를 작성한다. 기존 API v1과 fixtures는 이번 문서 개정에서 바꾸지 않는다. 성과 지표는 공통 기획서 8장을 따른다.
