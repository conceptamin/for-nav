# 조선소 AI 운행 지원 서비스 프론트엔드 기술 기획서

작성일: 2026-10-17 · 수정일: 2026-10-18 · 상태: 구현 전 설계안

## 1. 목표와 범위

가상 조선소에서 운전자에게 길·접근·대기 안내를 제공하고, 관리자가 차량 흐름과 통제 구간을 확인하는 반응형 웹 앱을 만든다. 차량 3~5대, 협소 구간 1개, 대기 공간 2곳을 MVP 기준으로 한다.

기존 AI 기술 기획서의 CatBoost 시간 예측, 차량별 온라인 보정, 다익스트라 경로 탐색을 화면과 연결한다. 모델 학습과 통행 순서 결정은 브라우저에서 수행하지 않는다.

## 2. 기술 스택

| 영역 | 선택 | 선택 이유 |
|---|---|---|
| UI | React + TypeScript | 화면 컴포넌트 재사용, 계약 기반 타입 검사 |
| 개발·빌드 | Vite | 로컬 개발 및 정적 웹 배포 |
| 패키지 관리 | npm (`package-lock.json`) | Node 기본 도구로 별도 설치 없이 잠금 파일 재현 |
| 페이지 이동 | React Router | 운전자·관제·시연 화면 구분 |
| 스타일 | CSS Modules + CSS 변수 | 작은 화면 수에 맞는 단순한 스타일 관리 |
| 지도 | Canvas 2D + Konva + react-konva | 지도·경로·차량의 레이어 렌더링과 객체 이벤트 처리 |
| 서버 조회 | TanStack Query + fetch | 지도·설정·결과 조회, 캐시와 오류 관리 |
| 실시간 상태 | 브라우저 WebSocket + 전용 store | 스냅샷 및 차량·예약 상태 동기화 |
| 상태 구독 | React useSyncExternalStore | 실시간 상태의 화면 구독 |
| 런타임 검증 | Zod | 백엔드 Pydantic JSON Schema에서 생성한 스키마로 수신 데이터 검증 |
| API 타입 | openapi-typescript | 백엔드 OpenAPI에서 REST 타입 생성 |
| 테스트 | Vitest + React Testing Library, Playwright | 상태 처리 단위 테스트와 핵심 사용자 흐름 E2E |
| 품질 | TypeScript, ESLint | 타입 오류·정적 오류 검사 |

패키지는 구현 시작 시 호환되는 안정 버전을 선택하고 npm `package-lock.json`으로 고정한다. 현재 문서는 설치나 구현 완료를 의미하지 않는다. React와 react-konva의 메이저 버전 호환성을 확인한다. 지도 편집기를 만들지 않으므로 React Flow는 MVP 필수 의존성으로 넣지 않는다. 외부 지도 타일·지오코딩·CDN 없이 로컬 자산으로 구성한다.

## 3. 화면 구성

| 경로 | 대상 | 핵심 기능 |
|---|---|---|
| `/driver/:vehicleId` | 운전자 | 목적지 선택, 현재 경로, 접근·대기 안내 |
| `/control` | 관리자 | 전체 지도, 차량 목록, 구간 상태, 도로 통제 |
| `/demo` | 발표자 | 시나리오 선택, 실행·일시정지·종료, 모드 비교 |
| `/runs/:runId` | 관리자·발표자 | 예측 오차·대기 시간·동시 진입·후진 결과 |

역할에 따라 서버가 접근을 제한한다. URL의 vehicleId를 바꿔도 다른 차량의 정보에 접근할 수 없어야 한다.

로그인 화면은 없다. 앱을 설치·실행하면 서버가 차량을 배정한 세션을 발급하고 운전자 화면은 그 차량으로 이동한다. 실제 단말기 등록·인증은 시나리오 가정으로만 둔다([백엔드 기획서 9장](../../backend/docs/proposal.md)).

### 3.1. 운전자 화면

상단에는 연결 상태와 자기 차량 상태, 중앙에는 지도와 다음 행동, 하단에는 목적지·안내 확인을 배치한다.

- 기본: 목적지 없이도 접근 경고 표시.
- 길 안내: 목적지 검색·선택 후 서버가 반환한 경로 표시.
- 대기: 이유, 지정 대기 위치, 상대 차량 상태 표시.
- 예약: 통과 순서가 배정됐음을 표시하되 ‘안전 보장’으로 표현하지 않음.
- 정보 부족: 도착 시간을 `--`로 표시하고 확인 중 문구 제공.
- 연결 끊김: 차량 애니메이션·초 단위 카운트다운 중지, 기존 통과 안내 비활성화.

‘안내 확인’은 메시지 수신 확인이며 실제 정지·이탈 증거가 아니다. 실제 상태는 차량 에이전트/시뮬레이터 이벤트로 확인한다. 운행 중 입력을 최소화하며 복잡한 설정은 정차 상태에서만 노출한다.

### 3.2. 관제 화면

전체 지도와 차량 상태 목록, 선택 구간의 예약·점유·불확실 상태, 최근 이벤트를 표시한다. 관리자는 도로 통제와 작업 우선순위를 변경할 수 있다. 변경 요청 중에는 진행 상태를 표시하고 서버 확정 후 지도에 적용한다. 임의 점유 해제 기능은 MVP에서 제공하지 않는다.

### 3.3. 시연 화면

시나리오와 시드, 예측 모드, 통행 조정 적용 여부를 선택해 실행한다. 이미 실행 중인 시나리오를 덮어쓰지 않는다. ‘안내 전후’와 ‘모델 보정 전후’는 별도 비교로 제공해 두 효과를 혼동하지 않도록 한다.

## 4. 가상 지도와 차량 표현

지도는 미터 단위의 로컬 좌표계이며 `x_m`, `y_m`, `map_version`을 사용한다. 실제 지리 좌표나 실제 조선소 배치를 필요로 하지 않는다.

### 4.1. Canvas 선택과 UI 경계

지도 렌더러는 React Konva로 구현한다. 차량 이동·경로 강조·확대와 이동을 같은 2D 장면에서 처리한다. 현재 차량 3~5대에서는 SVG도 충분할 수 있으며, Canvas의 성능 우위를 검증한 것으로 주장하지 않는다. 지속적인 차량 애니메이션과 향후 시나리오 확장을 고려한 설계 선택이다.

지도만 Canvas로 그리고 목적지 입력, 안내 카드, 모달, 버튼, 차량 목록은 일반 React DOM으로 구현한다. 통행 판단과 지도 데이터는 렌더러에서 분리한다.

### 4.2. 레이어 구성

하나의 Stage 안에 세 개의 Layer로 시작한다. 차량마다 별도 Layer를 만들지 않는다.

| Layer | 내용 | 갱신 시점 |
|---|---|---|
| StaticMapLayer | 도로·작업장·대기 지점·고정 라벨 | 지도 버전 또는 viewport 변경 |
| RouteOverlayLayer | 경로·통제·협소 구간 상태·선택 표시 | 경로·통제·예약·선택 변경 |
| VehicleLayer | 차량·진행 방향·차량 라벨 | 이동 애니메이션·차량 상태 변경 |

정적 도형은 기본 `listening={false}`로 두고, 선택 가능한 도로·차량 등 필요한 객체에만 이벤트를 연결한다. 도로 선택용 hit 영역은 RouteOverlayLayer에 둔다. 캐싱은 복잡한 정적 그룹에 한정해 프로파일링 후 적용하고, 지도 변경 시 무효화한다.

### 4.3. 좌표·확대·선택

- 서버 좌표는 미터 단위 원본으로 유지한다. MVP 로컬 좌표는 x가 오른쪽, y가 위쪽인 좌표계로 고정한다.
- `worldToScreen`과 `screenToWorld`에서 y 반전, 배율, 이동량을 일관되게 처리한다. 서버·공통 계약에도 동일한 축 방향을 명시한다.
- 도로 길이는 화면 픽셀 길이로 재계산하지 않고 `length_m`를 사용한다.
- ResizeObserver로 viewport 크기를 갱신하고 초기에는 전체 지도 맞춤을 적용한다.
- 포인터 기준 확대와 지도 이동을 지원하며 최소·최대 확대 비율을 제한한다.
- 차량 클릭/터치로 선택하고 DOM 상세 패널을 연다. 지도 이동과 클릭은 이동 거리 기준으로 구분한다.
- 차량을 드래그해서 실제 위치를 변경하지 못하게 한다.
- 작은 차량의 터치 hit 영역을 확대하되 실제 차량 크기나 충돌 판단에는 영향을 주지 않는다.
- 좁은 화면과 큰 글자에서는 지도 라벨을 줄이고 DOM 목록에서 전체 정보를 제공한다.

### 4.4. 차량 애니메이션과 상태 소유권

상태 수신은 기본 5Hz, 그리기는 브라우저 프레임 주기에 맞춘다. 한 개의 Konva.Animation 루프가 차량 표시 위치를 갱신하고 매 프레임 React 전체 상태를 변경하지 않는다. React는 차량 생성·삭제·선택·상태를 담당하고, 보간 중 x/y/rotation은 전용 렌더러가 담당해 서로 덮어쓰지 않도록 한다.

최근 두 유효 관측값을 짧게 버퍼링한 뒤 그 사이에서만 보간한다. 도로 모서리를 직선으로 가로지르지 않도록 간선 geometry와 경로를 따라 보간한다. 경로가 불명확하면 직선 이동을 꾸미지 않고 최신 관측 위치를 표시한다. 이 표시 지연은 도착 시간 계산에 다시 반영하지 않는다.

새 관측값이 없으면 마지막 위치에서 멈춘다. 미래 위치로 외삽하지 않는다. STALE/연결 끊김/재동기화/일시정지 시 애니메이션과 카운트다운을 중지한다. 다시 시작할 때 오래된 프레임을 몰아서 재생하지 않고 새 스냅샷에 맞춘다. 화면 보간 위치는 통행 판단이나 서버 입력에 사용하지 않는다.

배경 탭에서 애니메이션을 중지하고 복귀 시 신선도를 재확인한다. unmount와 run 변경 시 Animation·이벤트·ResizeObserver를 정리한다.

### 4.5. 해상도와 렌더링 비용

Stage는 실제 viewport 크기로 유지하고 지도 전체 크기의 거대한 Canvas를 만들지 않는다. Konva의 기본 고해상도 처리를 먼저 사용하고 저성능 장치에서만 pixel ratio 제한을 실측 후 적용한다. CSS 픽셀과 내부 bitmap 픽셀을 혼용하지 않으며 자체 코드로 DPR 배율을 중복 적용하지 않는다.

반복적인 그림자·필터·점멸을 최소화한다. 색상과 텍스트·아이콘을 함께 사용하고 선택·대기·오래된 정보 상태를 구분한다. 단순 도형까지 모두 캐싱하거나 레이어를 과도하게 늘리지 않는다.

## 5. 상태 관리

| 상태 | 관리 위치 |
|---|---|
| 지도·차량 등록 정보·결과 | TanStack Query |
| 차량 이동·안내·예약 | WebSocket store |
| 지도 확대·선택 차량·모달 | 로컬 React 상태 |
| 권한·연결·동기화 상태 | 앱 세션 상태 |

통행 관련 상태의 원본은 서버다. 프론트가 임의로 통과 순서를 계산하거나 예상 이탈 시각만으로 대기를 해제하지 않는다. API 성공 응답과 WebSocket 변경 모두 버전을 포함하고, 오래된 버전은 버린다.

### 연결 복구

- WebSocket 연결 후 전체 스냅샷을 적용한다.
- 클라이언트별 단조 증가 `seq`로 중복·누락을 확인한다.
- 누락 시 `resync.request`를 보내고 새 스냅샷 전까지 통행 안내를 제한한다.
- 재접속 시 지수 백오프와 지터를 사용한다. 새 연결에서는 새 스냅샷부터 시작한다.
- 실행 ID가 바뀌면 기존 차량·예약·모델 그래프를 비운다.
- 일시정지는 연결 끊김과 구분해 표시한다. 시뮬레이션 시간과 네트워크 시간을 혼용하지 않는다.

## 6. API 연동 흐름

1. 세션이 없으면 `POST /sessions`로 발급받고, `/me`로 역할과 배정 차량을 확인한 뒤 권한에 맞는 지도와 차량 정보를 조회한다.
2. `/api/v1/ws`에 연결하고 전체 상태를 수신한다.
3. 목적지 선택 시 목적지 변경 API를 호출한다.
4. 응답의 경로 버전과 경로를 표시한다. 경로 없음은 별도 상태로 표시한다.
5. `guidance.changed` 이벤트로 대기·예약 안내를 갱신한다.
6. 안내 확인은 안내 ID와 버전을 포함해 전송한다. 이전 안내의 확인은 최신 안내에 적용하지 않는다.
7. 관리 명령은 idempotency key와 expected version을 포함한다.

REST와 WebSocket 필드 정의는 공통 API·이벤트 계약을 따른다. 임의로 필드를 추가하거나 단위를 바꾸지 않는다.

## 7. 인터페이스와 접근성

- 모바일 360px부터 관제 데스크톱 1440px까지 대응.
- 주요 터치 영역은 48px 이상을 목표로 한다.
- 적색·녹색만으로 상태를 표현하지 않는다.
- Canvas 도형 자체를 접근 가능한 버튼으로 가정하지 않는다. 차량·도로 선택과 예약 확인은 키보드로 조작 가능한 DOM 목록에서도 수행할 수 있게 한다.
- 핵심 안내는 DOM의 live region에서 상태 변화 시 전달하고 위치 갱신마다 반복하지 않는다.
- 지도 컨테이너에 설명을 제공하고 확대·축소·전체 보기 DOM 버튼을 둔다. 브라우저 페이지 확대를 막지 않는다.
- 키보드 포커스와 대화상자 닫기 동작을 지원한다.
- 경고는 상태가 바뀔 때 전달하고 위치 갱신마다 반복하지 않는다.
- 소리 안내는 선택 기능이며 핵심 정보는 화면으로도 전달한다.
- 기본 지도는 north-up에 대응하는 고정 방향으로 두어 불필요한 회전을 줄인다.

## 8. 컴포넌트·폴더 구성

```text
frontend/src/
  app/                 # 라우팅, 세션, providers
  api/                 # REST client, 생성 타입, WS schema
  realtime/            # 연결·재동기화·상태 store
  features/
    driver/            # 목적지·안내·연결 상태
    control/           # 차량 목록·통제·예약 패널
    demo/              # 실행 관리·비교 화면
  map/                 # Konva Stage·레이어·좌표 변환·애니메이션
  components/          # 공통 UI
  styles/              # CSS 변수·기본 스타일
  tests/
```

`YardMap`, `StaticMapLayer`, `VehicleLayer`, `VehicleMarker`, `RouteOverlayLayer`, `GuidanceCard`, `ConnectionBanner`, `ReservationPanel`, `RunComparison`을 주요 컴포넌트로 둔다.

## 9. 성능·테스트·완료 기준

수치는 해커톤 검증 목표이며 현재 측정 결과가 아니다.

- 기준 노트북, 차량 5대에서 화면 30FPS 이상을 목표로 측정.
- 수신 후 화면 반영 지연 p95 200ms 이하를 목표로 측정.
- 타입 검사·lint·프로덕션 빌드 통과.
- 좌표 왕복 변환·y축 반전·확대 기준점·경로상 보간 단위 테스트.
- WebSocket 중복·역순·누락·재접속 처리 단위 테스트.
- Canvas hit 영역·터치 선택·확대 후 객체 선택은 실제 브라우저에서 E2E로 검증.
- 프레임 시각을 고정한 스크린샷으로 레이어 순서와 고해상도 표시를 확인. Canvas mock만으로 렌더링 성공을 판단하지 않음.
- 차량 선택의 DOM 대안, 키보드 조작, 화면 복귀 후 재동기화 확인.
- 화면 반복 진입·이탈 시 애니메이션 루프와 이벤트가 중복되지 않는지 확인.
- 목적지 설정 → 경로 표시 → 대기 안내 → 이탈 확인 후 안내 갱신 E2E.
- 목적지 미입력 경고, 경로 없음, 도로 통제, 서버 재시작 E2E.
- 연결 끊김 후 오래된 통과 안내가 활성 상태로 남지 않는지 확인.
- 운전자와 관리자 화면이 동일한 예약 버전을 반영하는지 확인.

## 10. 개발 순서

1. 공통 계약과 고정 fixture 확정
2. Canvas 지도·운전자·관제 기본 화면
3. REST 목적지·통제 기능 연결
4. WebSocket 스냅샷·갱신·복구 연결
5. 시뮬레이션과 비교 화면 연결
6. 실패 상황·반응형·통합 테스트

개발 서버는 Vite proxy로 `/api`와 WebSocket을 백엔드에 연결한다. 데모 배포는 Vite 빌드 결과를 FastAPI에서 같은 origin으로 제공한다. SPA fallback은 `/api` 경로를 가로채지 않아야 한다.
