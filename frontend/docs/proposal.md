# for-nav 프론트 기획서

작성일: 2026-10-21 · 기준 문서: 울산 외국인 근로자 산업보건 내비게이터 기획안(보완판 2)

## 1. 목적과 결정

다친 직후의 외국인 근로자가 휴대폰 브라우저에서 모국어로 상황을 말하고, 응급 여부 → 먼저 상담할 곳 → 지금 열린 곳 → 의사에게 보여 줄 한국어 카드까지 한 흐름으로 가게 한다.

화면 기술은 **React 모바일 웹**으로 정했다(2026-10-21). Flutter는 이틀 안에 첫 흐름 화면(phase-02의 6개)을 만들 인력이 없어 제외했다. 기존 `frontend/` 실행·검증 기반([phase-01](phase-01.md))을 그대로 쓴다.

- [공통 API 계약](../../docs/api-contract.md)
- [백엔드 기획서](../../backend/docs/proposal.md)

## 2. 화면

| 경로 | 화면 | 핵심 |
|---|---|---|
| `/` | 언어 선택 | `en`·`vi`. 고른 언어는 기기에 기억 |
| `/consent` | 고지·동의 | 외부 AI 전송, 서버 미저장, 기기 저장을 모국어로 설명. 동의 전 다음 화면으로 가지 않음 |
| `/describe` | 상황 말하기 | 텍스트 입력(음성은 해커톤). `/triage` 호출 후 빈 항목만 버튼으로 되묻기 |
| `/emergency` | 119 | 응급이면 어느 화면에서든 즉시 이동. 119 전화 버튼, 한국어로 보여 줄 한 줄 문장 |
| `/route` | 비용 경로 | Q1→Q2→Q3 한 화면에 한 질문. 필요 없는 질문은 건너뜀. 결과·연결 기관·안내 문구 |
| `/nearby` | 지금 갈 수 있는 곳 | 퇴근 시각·구·군 선택 → 진료과별 열린 의원·약국·응급실 (해커톤) |
| `/card` | 요약 카드 | 항목 선택(기본 모두 포함) → 동의 → 한국어 카드. 의사에게 화면을 그대로 보여 줌 |
| `/guide` | 산재 상담 안내 | 절차, 보관할 것, 연락처 |
| `/records` | 내 기록 | 날짜가 찍힌 모국어·한국어 기록. 기기에만 저장, 삭제 가능 |

모든 화면 상단 또는 하단에 "증상이 심해지면 119"를 고정해서 보인다. 제도·기관 정보를 보이는 결과 화면(`/route`, `/guide`, `/nearby`) 아래에는 "지원 여부는 각 기관이 최종 결정합니다"와 정보 기준일이 있다.

## 3. 데모 흐름 (3분)

1. 동구 조선소 근로자가 베트남어로 "오늘 오후 용접하고 나서 눈이 너무 아파요. 보안경은 잠깐 벗었어요."라고 입력한다.
2. 응급 신호 없음, "심해지면 119" 표시. 비어 있는 "일하다 다쳤나요?"를 버튼으로 되묻는다.
3. 비용 경로: "일하다 생긴 증상이므로 산재 상담을 먼저 받아 보세요."
4. 오후 7시 기준으로 열린 안과와 응급실을 보인다.
5. 요약 카드에서 근로자가 "보호구 착용 여부"를 넣을지 직접 고르고 동의하면 한국어 카드가 나온다.

## 4. 상태와 저장

- 서버 상태는 계약 응답 그대로 쓰고 프론트에서 응급·경로를 다시 계산하지 않는다. 응답은 Zod로 검증하고, 검증 실패는 오류로 보인다(빈 값으로 채우지 않음).
- 기기 저장: 언어, 동의 여부, 기록(입력 원문, 추출된 맥락, 카드, 시각). 저장소 접근이 막혀도 흐름은 동작해야 한다.
- 서버나 외부 분석 도구로 기록을 보내지 않는다.

## 5. 문구와 번역

- 근로자에게 보이는 문구는 `src/i18n/en.json`, `src/i18n/vi.json`(경로는 phase-02에서 확정)에 둔다. 키가 빠지면 테스트가 실패한다.
- 베트남어는 번역 후 역번역 검사와 서로 다른 LLM 2개로 교차 확인한다. 발표에서 "원어민 평가는 다음 단계"로 밝힌다.
- 진단·판정처럼 읽히는 말("산재입니다", "괜찮습니다")을 쓰지 않는다.

## 6. 접근성과 기기

- 360px 폭 기준, 한 손 조작, 터치 영역 44px 이상, 큰 글자. 색상만으로 상태를 전달하지 않는다.
- 119 버튼은 `tel:119` 링크다. 데모 기기에서 동작을 확인한다.
- 음성 녹음은 HTTPS 또는 localhost에서만 된다. 해커톤 데모 기기에서 결정 당일 30분 시험으로 확인한다.

## 8. 측정

안내 소요 시간: 시나리오 3개(용접 후 눈 통증, 프레스 손 부상, 건강보험 없는 비업무 질환), 근로자 역할 참가자 5명. 직접 검색했을 때와 앱을 썼을 때 "먼저 상담할 곳과 지금 열린 병원"을 찾기까지의 시간 중앙값을 비교한다. 측정 전 결과를 적지 않는다.
