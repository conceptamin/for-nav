# 53. 하단 채팅 아이콘에 안 읽은 수 배지, 시트는 채팅 목록부터

상태: 완료
의존: 46(요청 상태·새 메시지 점), 47(채팅 메신저 모양), 52 request-sent-no-auto-sheet(보내도 시트를 저절로 열지 않는다)

## 목표
2026-10-31 사용자 요청: "홈화면 플로팅 챗 아이콘 위에 대화가 왔으면 왔다는 뱃지 표시가 있어야 하고, 채팅 목록을 먼저 보여 주고 누를 수 있게 해야 한다."
지금 독의 새 메시지 표시는 숫자 없는 10px 점(backlog 46)이라 눈에 잘 띄지 않고, 시트는 완료가 아닌 가장 최근 요청의 대화로 바로 들어가 다른 요청의 대화로 갈 길이 S-13뿐이다. 흔한 메신저처럼 아이콘에 안 읽은 수를 숫자로 보이고, 시트를 열면 내 요청(대화방) 목록부터 보이게 한다.

## 범위
- 하는 것
  - **독 채팅 아이콘의 숫자 배지**(SEED notification-badge Large, 사용자 결정 2026-10-31 "숫자 배지"): 사례마다 `센터 메시지 수 − 내가 본 수`를 더한 값. 0이면 없다. 10 이상은 `9+`. 119와 헷갈리지 않게 빨강이 아니라 진한 틸(`--brand-fg`) 바탕 + 흰 글자(새 토큰 `--on-brand-fg`) + `--card-solid` 2px 테. 점(`.bar-chat-dot`)은 이 배지로 바꾼다. `aria-label`은 "센터와 대화 · 새 메시지 N"
  - `domain/centerCase.ts`: `unreadCount(view, seen)`. `hasUnread`는 이것으로 다시 쓴다
  - **시트는 채팅 목록부터**(사용자 결정 2026-10-31 "요청이 1개 이상이면 항상"): 독 아이콘으로 열면 다시 붙을 수 있는 내 요청(토큰이 있고 서버가 아는 것)이 하나라도 있으면 목록. 하나도 없으면 지금처럼 새 요청 대화
    - 목록 머리: 센터 마크 + "센터와 대화" + ✕
    - 맨 위 `＋ 지원센터에 문의`(새 요청 대화로), 그 아래 요청 줄(S-13과 같은 줄: 요청 번호·보낸 날·상태 칩·안 읽은 수 배지). 순서는 최근에 보낸 것부터. 줄을 누르면 그 요청의 대화
    - 상태를 읽지 못했으면 목록 아래 `caseStatusFailed` 한 줄(S-13과 같다)
  - **대화·새 요청 머리에 ←**(시작 쪽, RTL은 뒤집힌다): 목록으로 돌아간다. 목록에 보일 요청이 없으면 ←도 없다
  - S-13 요청 줄·푸시 알림·S-12 전송 완료 화면의 `💬 센터와 대화` 버튼은 목록을 건너뛰고 그 요청의 대화를 바로 연다(← 로 목록). S-12 버튼은 지금 "가장 최근 요청"을 열던 것을 그 요청 id로 연다. 보낸 직후 저절로 열지 않는 것은 52 request-sent-no-auto-sheet 그대로다
  - 목록을 보는 동안에도 마지막으로 연 요청의 채팅·통화는 숨겨 둔 채 붙어 있다(통화 중 시트를 닫았다 다시 열어도 끊기지 않는다). 다른 요청을 누르면 앞 요청의 연결은 닫힌다
  - 읽음·본 수는 그 요청의 대화가 보일 때만 보낸다(목록을 보는 동안 온 글은 안 읽은 수에 남는다)
  - S-13 요청 줄의 "새 메시지" 칩을 같은 숫자 배지로 바꾼다(시트 목록과 한 조각, `MyCaseRow`)
  - 쓰지 않게 되는 "지난 요청은 완료" 한 줄(`casePrevDone`)과 `useOpenCenterSheet`를 지운다. 완료된 요청은 목록에 보이고 새 요청은 목록 맨 위 버튼으로 연다
  - `design.md`(독 채팅 아이콘, 센터 채팅 시트, notification-badge, 새 토큰), `README.md`(S-12·S-13 설명, my-cases 표 행)
- 하지 않는 것
  - 목록 줄에 마지막 메시지 미리보기 글. `POST /api/center/my-cases`가 글을 주지 않는다(backend 27 응답 변경이 필요해 메모로 남긴다)
  - 단독 모드 목록. 단독 모드는 채팅 토큰이 없어 다시 붙을 요청이 없으므로 지금처럼 늘 새 요청 대화다
  - 시트 열고 닫는 움직임, 목록에서 요청 지우기·숨기기, 새 문구 키

## 결과
- `cd frontend && npm run build` → 통과(청크 크기 경고만 기존과 같다), `cd app-front && npm run build` → 통과
- 브라우저 확인: Playwright 헤드리스 Chromium 360×740, 저장소에 데모 계정·프로필을 넣어 시작
  - API 모드(이 브랜치 백엔드 :8791 + Vite 프록시) en: 요청이 없을 때 독 아이콘 → 목록 없이 새 요청 대화, ← 없음 → 보내면 그 대화에 머물고 ←가 생긴다 → 닫고 다시 열면 요청 줄 1개 목록(아래 칸 없음) → `＋ 지원센터에 문의`로 두 번째 요청. 센터 WebSocket으로 첫 요청에 3개, 두 번째에 9개를 보내니 15초 안에 홈 독에 `9+`, `aria-label` "Chat with the centre · New message 12". 목록 줄 배지 9·3 → 3인 줄을 누르면 그 대화(머리 요청 번호·상태, 입력줄) → ←로 목록, 그 줄 배지가 사라진다. 목록을 보는 동안 그 요청에 1개를 더 보내면 16초 뒤 줄 배지 1(읽음으로 세지 않음). S-13에서 9인 줄을 누르면 목록 없이 그 대화가 열리고, 닫은 뒤 독 배지는 1. 콘솔 오류 없음
  - vi·ko·ar·my·ru: 목록·대화에서 가로 넘침 없음. ar에서 ←·배지·독 좌우가 뒤집힌다
  - 단독 모드 en: 독 아이콘 → 지금처럼 새 요청 대화, 보낸 뒤 `talkOffline` 줄, 다시 열어도 목록·←·배지 없음
- 결정
  - 시트를 열 때 목록/대화를 고르는 일을 효과가 아니라 렌더 중에 한다. 효과로 하면 지난번 대화가 한 번 그려지며 그 요청의 글이 읽은 것으로 세어졌다(확인 중 발견)
  - 첫 요청을 보내면 목록이 막 생기지만 보던 대화에 머문다(목록으로 튀지 않게)
  - 레이아웃이 시트에 넘기는 고른 사례는 여는 차례마다 새 객체(`{ id }`)다. 같은 사례를 다시 골라도 그 대화로 돌아가게 하려는 것이다
  - S-12 전송 완료 화면의 `💬 센터와 대화` 버튼은 "가장 최근 요청"이 아니라 그 요청 id로 시트를 연다(`useOpenCenterSheet` 삭제, `openCase` 사용). main에 먼저 들어간 52 request-sent-no-auto-sheet(PR #182)를 따라 보낸 직후 저절로 열지는 않는다
  - 번호 52가 이미 쓰여 있어(52 coverage-reset-on-home, 52 request-sent-no-auto-sheet) 이 항목은 53이다
  - 새 요청 버튼 문구는 새 키 없이 홈 메뉴와 같은 `cenTitle`("지원센터에 문의")을 쓴다
  - 쓰지 않게 된 `casePrevDone`(20개 언어)·`hasUnread`·`.bar-chat-dot`·`.pill.unread`를 지웠다
- 남은 문제
  - 다른 요청의 줄을 누르면 앞 요청의 통화가 끊긴다(칸을 하나만 붙여 둔다)
  - 목록을 보는 동안 센터가 거는 전화는 시트 안에 보이지 않는다(전에도 통화 화면이 아니면 보이지 않았다. 앱은 푸시가 알린다)
