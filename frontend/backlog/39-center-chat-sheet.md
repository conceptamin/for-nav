# 39. 하단 채팅 아이콘이 화면 위 채팅 시트를 열게

상태: 완료
의존: 29 센터 연락 방법, 33 하단 독

## 목표
2026-10-31 사용자 결정: 센터에 연락하려고 하단 독의 채팅 아이콘을 누르면 페이지(`/center-chat`)로 옮겨 가지 않고, 지금 화면 위에 채팅 시트가 올라와 그 안에서 채팅으로 진행한다. 아직 보낸 요청이 없으면 요청(종류 고르기 → 보낼 내용 → 전송 동의 → 보내기)도 시트 안의 대화로 묻고, 보내면 같은 시트가 바로 센터 채팅으로 이어진다.

## 범위
- 하는 것
  - 하단 독의 채팅 아이콘(`.bar-chat`)을 링크에서 버튼으로 바꾼다. 누르면 시트를 열고 닫는다(`aria-expanded`). 열려 있으면 지금 화면 표시(`--brand-2` + `--glass-in`)와 같은 눌린 모양
  - 새 `components/CenterSheet.tsx`: 독 바로 위에 떠 있는 유리 시트. 머리(제목 `chatTitle` + 통화 전환 버튼 + ✕ 닫기), 그 아래 대화
    - 보낸 요청이 없으면: 안내 말풍선(`cenIntro`) → `cenType` 말풍선 + 요청 종류 칩(여러 개) → 고르면 보낼 내용 말풍선(`cenPreview` + 요약, `cenPreviewKo`, 제도 결과가 있으면 최종 결정 문구) → 전송 동의 체크 → 📨 보내기. 실패하면 실패 문구 + 다시 시도(S-12와 같다)
    - 보낸 뒤: 고른 종류가 내 말풍선으로 남고 "✅ 센터에 보냈어요" 말풍선 + 운영 시간 안/밖 안내, 요청 번호 줄, 그 아래 채팅 패널(`ChatPanel`)
    - 이미 보낸 요청(토큰이 있는 가장 최근 것)이 있으면 요청 번호 줄과 채팅 패널만
    - 머리의 📞 버튼(요청이 있고 통화를 쓸 수 있을 때만): 누르면 채팅 자리가 통화 패널(`CallPanel`)로 바뀌고 버튼이 💬로 바뀌어 채팅으로 돌아간다
    - 단독 모드: 요청 대화와 전송은 그대로 되고, 보낸 뒤 채팅 자리에 `talkOffline` 한 줄
  - 시트는 한 번 열면 닫아도 숨기기만 한다(채팅 연결·통화가 끊기지 않는다). 로그인이 풀리면 사라진다
  - 시트가 열려 있으면 뒤 화면에 옅은 막(`--scrim`)이 깔리고, 막을 누르거나 Esc를 누르면 닫힌다. 119 독은 막 위에 그대로 보이고 눌린다
  - `/center-chat` 경로와 `CenterChatPage`를 지운다(frontend·app-front 둘 다). 옛 주소는 알 수 없는 경로 규칙으로 `/`에 간다
  - i18n: 새 키 `close`(닫기)를 20개 언어에 넣는다
  - `design.md`: "모달은 만들지 않는다" 규칙의 예외(사용자 결정)와 시트 모양, `--scrim` 토큰. `README.md` 화면 구성
- 하지 않는 것
  - S-12 `/center-request` 페이지(홈 메뉴에서 가는 요청 화면과 전송 완료 화면). 그대로 둔다
  - 시트 안에서 두 번째 요청 보내기. 이미 요청이 있으면 시트는 그 요청의 채팅만 보인다(새 요청은 S-12)
  - 애니메이션(올라오는 움직임), 끌어서 높이 바꾸기(snap point)
  - 백엔드 계약, `domain/`

## 화면·파일
- 경로: `/center-chat` 삭제. 시트는 하단 독이 있는 모든 근로자 화면(로그인·프로필 뒤, 응급 화면 제외)
- API: 그대로(`POST /api/center/cases`, `POST /api/report/center`, 채팅·통화 WebSocket)
- 파일: 새 `src/components/CenterSheet.tsx`, `src/components/WorkerLayout.tsx`, `src/pages/worker/CenterRequest.tsx`, `src/main.tsx`, `src/styles.css`, `src/i18n/*.ts`(20개), `README.md`, `design.md`, `app-front/src/main.tsx`

## 결과
- `cd frontend && npm run build` → 통과(청크 크기 경고만 기존과 같다), `cd app-front && npm run build` → 통과
- 브라우저 확인: 이 맥에 Google Chrome이 없어 Claude in Chrome 대신 Playwright 헤드리스 Chromium으로 360×740에서 확인했다(상태는 저장소에 데모 계정·프로필을 넣어 시작)
  - 단독 모드(dev 5191) en·vi·ko·ar: 홈에서 채팅 아이콘 → 주소 그대로 시트 열림(`aria-expanded=true`), 종류 2개 → 요약 말풍선, 동의 전 보내기 막힘, 보내기 → 요청 번호 + `talkOffline` 한 줄, 보낸 뒤에도 주소 그대로. ✕·Esc·막(앱 바 자리)·아이콘 모두 닫힘, 다시 열면 대화가 남아 있음. 119 가운데 점의 맨 위 요소가 119 링크(막 위에서 눌림), 시트 아래 끝이 독 위 끝보다 위, 가로 넘침 없음, 콘솔 오류 없음. ar은 제목·말풍선·독 좌우가 뒤집힘. `/center-chat`은 `/`로 감
  - API 모드(dev 5192 + 로컬 백엔드 :8000, `WORKER_AUTH` off) en: 증상 없이 종류를 고르고 1.5초 기다려도 `POST /api/report/center`가 1번만 나감. 보내기 → 같은 시트에 채팅 연결, 글을 보내면 내 말풍선으로 돌아옴. 📞 → 제목 "Call the centre" + 통화 패널, 💬 → 채팅. 새로 고침 후 다시 열면 칩 없이 `chatIntro` + 요청 번호 + 지난 글이 있는 채팅
- 결정
  - 시트는 독을 덮지 않고 독 바로 위에 뜬다. 119 버튼이 늘 보여야 하고(CLAUDE.md), 채팅 아이콘을 다시 누르면 닫히는 위젯처럼 쓰려는 것이다
  - 시트 안 요청에는 S-12의 "연락 방법"(통화·채팅) 질문을 넣지 않는다. 시트는 채팅으로 이어지고 통화는 머리의 📞로 언제든 바꾼다
  - 요청 미리보기·전송을 `useSendCenterRequest`로 묶어 S-12 페이지와 시트가 같이 쓴다. 통화·채팅 문구 묶음(`workerChatLabels`·`workerCallLabels`)과 운영 시간 안내(`CenterHoursNotice`)도 같다
  - 증상 없이 들어왔을 때의 대체 입력을 언어마다 한 번만 만들게 했다. backlog 29 "남은 문제"(S-12 미리보기가 끝없이 다시 요청됨)가 S-12 페이지에서도 함께 풀린다
  - `/center-chat` 경로는 지웠다. 옛 주소는 알 수 없는 경로 규칙으로 `/`에 간다

## 메모
- design.md는 모달·애니메이션을 만들지 않는다고 정했다. 이 시트는 사용자 결정으로 둔 예외이고, 애니메이션은 여전히 없다
- 새 키 `close`의 vi 문구는 원어민 검수가 필요하다. en·vi를 뺀 17개 언어는 기계 번역 초안이다(backlog 16)
- S-12 증상 없이 들어오면 요약 미리보기가 끝없이 다시 요청되는 문제(backlog 29 남은 문제)는 공용 훅에서 대체 입력을 한 번만 만들어 시트와 S-12 페이지 둘 다 피한다
