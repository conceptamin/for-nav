# 15. 온보딩·앱 바 레이아웃 정리(심토미 기준)

상태: 완료
의존: 없음(12 위에서 했다)

## 목표
2026-10-29 사용자 피드백: 심토미 앱 캡처(알림 권한 → 로그인 → 약관 동의 → 생년월일 → 성별)와 견주면 우리 화면 배치가 지저분하다. **클레이모피즘은 유지하고 배치만 고친다.** 360px 캡처로 확인한 문제는 다섯 가지였다.

1. 앱 바 제목과 본문 h1이 같은 글자로 두 번 보인다(동의 "시작하기 전에", 프로필 "간단 프로필", 증상 입력)
2. 로고 화면(S-01·S-03 로그인) 위에 앱 이름이 든 브랜드색 헤더가 또 있다. 심토미 로그인 화면에는 앱 바가 없다
3. 동의·프로필에 단계 숫자 원(2, 4)이 혼자 떠 있다. 심토미 약관 화면에는 단계가 없다
4. 동의 항목이 체크 카드 + 따로 떠 있는 › 버튼, 두 조각이다. 심토미는 한 줄이다
5. 프로필 성별이 세로 두 줄이다. 심토미는 가로 2칸이다

## 범위
- 하는 것
  - 앱 바: 화면 이름을 지운다. `/home`은 앱 이름, 그 밖은 ← 하나 + 오른쪽 언어 선택. 화면 이름은 본문 h1 하나다. `useScreenBar`의 `title`은 브라우저 탭 제목(`document.title`)에만 쓴다. 앱 바는 브랜드색 띠가 아니라 바닥색 위의 평평한 자리로 바꾼다(← 하나뿐인 진한 띠는 비어 보인다). 언어 선택은 `--clay-sm`로 작게 떠 있다
  - 로고 화면 S-01·S-03(로그인 단계)은 앱 바를 숨긴다(`hidden: true`). S-03 프로필 단계에서는 ← 가 있다
  - 온보딩의 단계 원(`Steps`, 1·2·3·4)을 동의·프로필에서 뺀다. S-05 증상 입력의 단계 원은 그대로다
  - 동의 항목 줄 `.check-row`를 한 면으로: 줄이 떠 있고 안의 체크 레이블은 평평, › 는 줄 안에. 체크되면 줄 전체가 들어간다(CSS만)
  - `SingleSelect`에 `inline` 옵션을 더해 성별·음주·흡연을 가로 칸(`.options.inline`)으로
  - `/my`에 본문 h1 `내 정보`(앱 바에서 빠졌으므로)
  - `design.md`: `.w-header`·`.check-row` 행, 세로 네 층의 앱 바·단계 행, 온보딩 세 화면 표, 선택지 목록 행, 홈과 내 화면의 앱 바 행, 입력 유형 행을 고치고 "Figma와 다르게 그리는 것"의 앱 바 행을 지운다(이제 Figma와 같다)
- 하지 않는 것
  - 클레이모피즘(그림자·둥글기·면) 변경. 색 토큰도 그대로다
  - 하단 119 띠. 제품 규칙이다
  - 프로필을 심토미처럼 질문 하나씩 화면으로 나누기. 한 화면 그대로다
  - 로고 이미지(14), 앱 이름(13)

## 결과
- 실행(2026-10-29, 브랜치 `frontend/clean-layout`)
  - `npm run build` → 통과
  - 로컬 Playwright Chromium(360×800, 세션·기기 저장소를 넣어 가드 통과)으로 `/`, `/consent`, `/signup`(로그인·프로필), `/home`, `/intake`, `/my`를 ko·vi로 찍어 전후를 비교했다. 위 다섯 문제가 사라졌고 가로 넘침 없음. en은 vi보다 짧아 따로 찍지 않았다
- 결정 사항
  - **앱 바를 브랜드색 띠에서 바닥색 평평으로 바꿨다.** 클레이모피즘의 세 면 규칙 안에서 "평평"은 그대로이고 색만 바닥색이다. 화면 이름이 빠진 뒤 ← 하나만 든 진한 띠가 화면에서 가장 무거운 요소가 됐기 때문이다. 심토미·Figma도 흰 앱 바다. 되돌리려면 `.w-header`의 `background`·`color` 두 줄이다
  - S-03 로그인에서 ← 가 없어졌다(앱 바 숨김). 동의를 마친 뒤라 되돌아갈 일이 드물고, 언어는 S-01에서 막 골랐다. 심토미 로그인도 ← 가 없다
  - 온보딩 단계 원을 뺀 이유: 네 단계 중 화면에 보이는 것은 2(동의)와 4(프로필)뿐이라 "2/4"·"4/4"가 혼자 떠 있었다. 언어·로그인은 단계로 느껴지지 않는다
  - `useScreenBar`의 `title`을 지우지 않고 탭 제목으로 돌렸다. 화면이 등록하는 API는 그대로다
- 남은 문제
  - 없음. 프로필을 질문 하나씩 화면으로 나누는 것은 하지 않기로 했다(범위)
