## 결정이 필요한 것

1. **중국어 두 개.** 간체(`zh-CN`)·번체(`zh-TW`)로 본다. 권장: 그대로.
2. **범위.** `Lang`은 화면 문구뿐 아니라 `domain/`의 어휘(`Term`), 접수 창구·전화 스크립트·의료진 리포트 모국어 줄, API 요청의 `language`에 모두 쓰인다. 백엔드 `vocab.py`의 `Lang = Literal["en","vi","ko"]`가 이 값을 검사한다.
   - **A. 전부 20개 언어(권장).** `Lang`을 20개로 넓히고 i18n 문구·어휘·템플릿 문장을 모두 번역한다. `parity.json`을 다시 만들면 백엔드 테스트가 깨지므로 `backend/` 브랜치에서 `vocab.py`·템플릿을 같이 옮겨야 CI가 통과한다(이 폴더 작업에서는 백엔드를 고치지 않는다).
   - **B. 화면 문구만 20개, 내용 언어는 3개.** 근로자가 고른 화면 언어(20개)와 `domain/`이 쓰는 내용 언어(en·vi·ko)를 나눈다. 새 언어는 내용 언어를 영어로 둔다. 백엔드·`parity.json`은 그대로지만, 어휘(부위·증상·진료과)와 창구·리포트 모국어 줄이 새 언어에서 영어로 보이고, 센터에는 "영어 사용 근로자"로 잡힌다.
3. **발음 표기.** 지금은 영어 사용자에게 로마자(`roman`), 베트남어 사용자에게 베트남식(`viPron`)을 보인다. 새 언어는 로마자로 둔다. 문자권별 한글 발음 표기(키릴·데바나가리 등)는 원어민 검수와 함께 후속 항목으로 남긴다.
4. **언어 선택 화면(S-01).** 버튼 20개를 세로로 쌓으면 화면 세 장 길이다. 권장: 2열 격자(모국어 이름 + 작은 글씨 영어 이름, 국기 이모지 없음). `design.md` "온보딩 세 화면"을 먼저 고친다. 앱 바·`/my`의 언어 선택은 지금처럼 `select`.

## 결과
- `npm run build` → 통과. 번들 428KB → 870KB(gzip 258KB). 20개 언어 문구가 한 번들에 들어 있다
- 구조 변경 검증: 언어를 늘리기 전에 en·vi를 `domain/lang/`으로 옮기고 `parity.json`을 다시 만들어 기존 것과 비교했다. 달라진 것은 전화 스크립트 FAQ 질문 형태(아래 결정 2) 하나뿐이다
- 20개 언어로 다시 만든 `parity.json`: en·vi·ko 사례(triage 252건, desk 120, call 15, clinician 45, center 60)는 출력이 그대로이고, 새 언어 사례가 뒤에 붙었다. 새 언어 응급 예문 187건(17개 언어 × 11 사유)이 모두 의도한 사유 하나로만 응급 판정된다
- 응급 키워드 교차 검사: 한 언어의 키워드가 다른 19개 언어의 화면 문구·어휘·문장 틀에 걸리는지 봤다. 걸린 것은 같은 뜻 3건(ja·zh-TW `嘔吐`, fr `vomi`가 en `vomiting`)뿐이다
- 브라우저(headless Chromium, 360×780): S-01 2열 격자, `/home`·`/consent`를 ar·my·si·km·ne·ru·th·ja로, `/visit/desk`·`/visit/call`을 fr·ar·ne·zh-CN으로 봤다. 가로 넘침 없음. 아랍어에서 한국어 줄의 마침표가 앞으로 넘어가 `[lang='ko']`에 `direction: ltr`을 줬다
- `cd backend && uv run pytest` → 2566 통과(백엔드 이전 전에는 1562 실패). 서버는 언어 묶음을 `scripts/dump-lang-packs.ts`로 내보낸 `backend/app/lang/packs.json`에서 읽는다

### 결정
1. 언어 코드: `ko ne ru mn my vi si ar en uz ja zh-CN zh-TW kk km ky th fr tl id`. `LANGS` 순서는 en·vi·ko를 앞에 두어 기존 기대값 순서를 지키고, 화면 순서는 `LANGUAGE_OPTIONS`(국기 목록 순)가 정한다
2. 전화 스크립트 FAQ 질문 `q`를 `{ko, en, vi}`에서 `{ko, native}`로 바꿨다. 20개 언어를 다 싣지 않고 접수 창구 서류(`docsKo`)와 같은 형태로 맞췄다. **API 계약 변경**이다(백엔드 `Faq.q: Tri`)
3. 어휘·문장 틀은 `{이름}`·`{이름:lower}` 자리표시 문자열이다(`templates.ts`의 `fill`). 함수가 아니라 문자열이라 백엔드로 그대로 옮길 수 있다
4. 응급 키워드도 언어 묶음에 두고 `triage.ts`가 합친다. 새 언어 자유 입력에서도 응급을 잡기 위해서다. 한국어 키워드는 `triage.ts`에 그대로 있다
5. 자유 입력 추출 사전(부위·증상·시점 키워드)은 새 언어를 넣지 않았다. 새 언어 자유 입력은 추출되지 않고 버튼으로 다시 묻는다(지금 동작). API 모드에서는 LLM 추출이 맡는다
6. 새 언어 발음 표기는 로마자(`roman`)다

## 메모
- 새 언어 문구는 기계 번역 초안이다. 의료 안내라 언어마다 원어민 검수가 필요하다. 번역하며 확인이 필요하다고 적어 둔 것:
  - 진료과 이름(직업환경의학과·가정의학과는 대부분 언어에 딱 맞는 말이 없다), 근로복지공단 등 기관 이름, 구군 이름 음역(특히 my·km)
  - 응급 키워드 중 넓을 수 있는 것: ja `ひどい`·`中毒`(食中毒), th `สลบ`·`พูดไม่ชัด`, ar `جانب واحد`, uz `qattiq`(심각도), ru `оторвало`·`отрезало`, zh `摔下来`
  - 우즈베크어는 라틴 문자 키워드만 있다. 키릴로 쓰는 사용자 키워드는 후속
  - 미얀마어는 표준 유니코드 입력만 잡는다(Zawgyi 인코딩은 못 잡는다)
- 백엔드 이전은 `backend/backlog/11-languages-20.md`. 언어 묶음을 고치면 `dump-lang-packs.ts`로 `packs.json`을 다시 만들어야 서버와 맞는다
- `modeling/src/fornav_modeling/schema.py`의 `Lang`은 en·vi·ko 그대로라 `modeling/tests/test_schema.py` 3건이 실패한다(CI 밖). `language`는 모델 피처가 아니다
- 앱 바·센터 요청 화면의 `select`도 20개가 된다. 바꾸지 않았다
- RTL에서 `›` 같은 방향 기호는 뒤집지 않았다. 아랍어 원어민 검수 때 함께 본다
- 번들이 두 배가 됐다. 언어 파일을 고른 언어만 불러오게(dynamic import) 나누는 일은 후속
