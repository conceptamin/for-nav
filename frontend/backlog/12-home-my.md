# 12. 홈(S-04)과 내 화면(S-13)을 개인 화면으로 보강

상태: 완료(브라우저 확인은 PR 검토에서)
의존: 없음(11과 독립. 둘 다 `WorkerLayout`을 조금 건드리지만 겹치는 줄이 없다)

## 목표
홈 `/home`은 인사 한 줄과 메뉴 다섯 개, 내 화면 `/my`는 "내 메모" 목록과 전체 삭제뿐이라 "내 앱"이라는 느낌이 없다(2026-10-29 프론트 피드백 2번: "홈 화면 및 개인 화면 부재, 심토미 참고"). 가입 때 받는 프로필(생년월일·성별·키·몸무게·음주·흡연)을 어디에도 보여 주지 않고, 최근 메모로 가는 길도 홈에 없다. 홈에 **지금 나**(프로필 요약·최근 메모)를 올리고, 내 화면을 **프로필·설정·내 기록**이 있는 개인 화면으로 만든다. 서버 계정은 없으므로 전부 브라우저 안 상태(`AppState`)로 그린다.

## 범위
- 하는 것
  - **배치를 `design.md`에 먼저 적는다.** "화면 골격(Figma 기준)"은 S-04·S-13을 "Figma에 없는 화면"으로 두고 있다. Figma 파일(conceptamin, "Simtomi")에 홈·마이 화면이 있으면 그 배치를 "온보딩 세 화면" 표처럼 한 표로 적고, 없으면 아래 안을 적는다. 어느 쪽이든 사용자가 표를 확인한 뒤 코드로 옮긴다
  - **홈 S-04** (위에서 아래로)
    1. 앱 바: 지금처럼 앱 이름(로고 자리) + 언어 선택
    2. 인사 h1(`homeHello`) 아래 **나 한 줄**(`.row.link`): 회원이면 `👤 남성 · 1990 ›` → `/my`, 비회원이면 `👤 비회원 · 프로필 만들기 ›` → `/signup`. `t()`에 치환이 없으므로 "1990년생" 같은 문장을 만들지 않고 성별 글자(`term(SEXES[sex])`)와 출생 연도 숫자를 ` · `로 잇는다. 세 언어에서 어순 문제가 없다. 지금의 `pill.low` 회원/비회원 링크를 이 줄이 대신한다
    3. 주 동작 `아파요 / 다쳤어요`(`.menu .primary`) — 그대로 맨 위
    4. **최근 메모 한 줄**: `app.reports[0]`이 있을 때만. `🩺 최근 메모 · 10/28 · 손 부기 ›` → `/report/:id`. 없으면 줄 자체가 없다
    5. 나머지 메뉴(`병원 이용 방법`, `보험과 지원`, `지원센터에 문의`, `내 정보`) — `내 메모` 항목의 이름을 `내 정보`로 바꾸고 부제를 `프로필, 설정, 내 메모`로
  - **내 화면 S-13** `/my` — 제목 `내 메모` → `내 정보`. 앱 바 ← 는 `/home`
    1. **프로필 카드**: 회원이면 생년월일·성별, 그리고 값이 있는 것만 키·몸무게·음주·흡연(`Profile`의 `null`은 줄을 만들지 않는다) + `프로필 수정`(`btn secondary block`) → `/signup?next=/my`(`SignupPage`가 이미 `app.profile`로 채워 연다). 비회원이면 `프로필을 만들면 지원센터에 요청을 보내고 메모를 이 휴대폰에 남길 수 있습니다.` + `프로필 만들기`(`btn block`) → `/signup?next=/my`
    2. **설정 카드**: 언어 한 줄(현재 언어 이름 + 앱 바와 같은 `select`). 그 외 설정은 없다
    3. **내 메모**(h2) — 지금 목록 그대로(`.row.link`)
    4. **센터로 보낸 요청**(h2) — 지금처럼 id 목록. 있을 때만
    5. `이 휴대폰에 있는 내 정보 모두 지우기` — 지금 그대로 맨 아래. 지우면 프로필 카드가 비회원 모양으로 바뀐다
  - `README.md` 화면 구성 표의 S-01~S-04, S-12·S-13 설명과 `design.md` 화면 유형별 규칙 표(홈·내 화면 행 추가), 컴포넌트 표(`.row.link` 쓰는 곳에 S-04·S-13)를 같은 PR에서 고친다
  - 새 문구 키(en·vi·ko): `homeMeGuest`, `homeRecent`, `menuMy`·`menuMySub` 값 변경, `myTitle` 값 변경, `myProfile`, `myProfileEdit`, `myProfileGuestHint`, `myProfileCreate`, `mySettings`, `myLanguage`, `myReports`
- 하지 않는 것
  - 서버 계정·실제 로그인·프로필 서버 저장. 상태의 경계(`README.md`)대로 전부 브라우저다
  - 메모 편집·이름 붙이기·개별 삭제. 전체 삭제만 있는 지금 동작을 유지한다
  - 센터 요청의 처리 상태 보기. 근로자는 센터 사례를 읽는 API가 없다
  - 알림·푸시·배지 수. 웹 데모에 알림이 없다
  - 홈의 메뉴를 격자나 탭 바로 바꾸기. `.menu` 세로 목록 그대로다
  - 진단 표현. 최근 메모 줄에는 증상 글자(`valueNative`)만 보이고 판정은 보이지 않는다
  - 로고. 앱 바의 로고는 별도 항목이다

    - 비회원 홈: `👤 Guest · Create a profile ›` → `/signup`. 최근 메모 줄 없음. `/my`: 비회원 안내 + 프로필 카드에 안내 문단과 `Create a profile` → `/signup?next=/my`, 설정(언어 select), 내 메모(없음), 지우기

    - 회원 vi 홈: `👤 Nữ · 1988 ›`, 최근 메모 줄 없음. `/my`: `.report-row` 두 줄만(null 항목 줄 없음), 센터 요청 카드 없음
- 확인하지 못한 것(PR 검토 때 브라우저에서 본다): 360px en·vi·ko 가로 넘침, `/my`에서 `프로필 수정` → 저장 → `/my`로 돌아오기, `/my` 언어 select가 앱 바와 같이 바뀌는 것, 지우기 뒤 비회원 모양, 동의 전 `/my` → `/consent` 가드. 정적 렌더링은 상태 변화를 못 본다
- 결정 사항
  - **`clearMyData`가 `mode`를 `guest`로 남긴다**(`src/state/AppState.tsx`). 전에는 `mode`가 `null`로 돌아가 `/my`에서 지우면 진입 순서 가드가 `/signup`으로 보냈고 "지웠습니다"가 보이지 않았다. 완료 기준("지우기 뒤 `/my`가 비회원 모양")을 맞추려면 비회원으로 남아야 한다. 언어·동의는 전처럼 남긴다. `state/`는 범위에 없었지만 이 한 줄 없이는 기준을 못 맞춘다
  - 프로필 카드의 줄은 새 클래스 대신 `.report-row`(레이블 작게 + 값 크게)를 쓴다. 설정의 언어는 `.field` + `select.input`(레이블 위). `design.md` 표와 컴포넌트 표의 "쓰는 곳"을 그에 맞췄다
  - 홈의 덩어리 간격은 새 수식 클래스 `.stack.wide`(16px, 카드 간격과 같다) 하나로 해결했다. 인라인 `style`은 기존 h1 `margin: 0` 하나만 남겼다
  - `/signup?next=/my`로 들어온 회원(프로필 있음)은 로그인 화면을 건너뛰고 프로필 단계로 바로 간다(`editing`). ←는 `next`로 돌아간다. 비회원이 같은 경로로 오면 전처럼 로그인 화면이다
  - 문구 키: `homeMeGuest`·`myLanguage`는 만들지 않고 `myProfileCreate`·`changeLang`을 다시 쓴다. `modeMember`는 쓰는 곳이 없어져 지웠다. 더한 키는 `homeRecent`, `myProfile`, `myProfileEdit`, `myProfileCreate`, `myProfileGuestHint`, `mySettings`, `myReports`
  - 홈 `내 정보` 메뉴 아이콘을 📄에서 👤로 바꿨다(메모가 아니라 사람에 관한 화면)
