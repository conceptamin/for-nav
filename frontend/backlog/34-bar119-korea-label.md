# 34. 하단 119 문구에 "한국의 응급번호"를 드러내기

상태: 완료
의존: 없음(문구만 바꾼다. 33 하단 독과 따로 병합해도 된다)

## 목표
2026-10-31 사용자 질문: "나라마다 119 전화번호가 다른데 밑에 표기를 119로 하는 게 맞을까." 사용자는 국적과 관계없이 한국에 있으므로 거는 번호는 119가 맞다(본국 번호를 보이면 한국에서 구급차가 오지 않는다). 다만 외국인은 119가 한국 번호인지 모르거나 본국 번호를 먼저 떠올릴 수 있으므로, 하단 119 버튼 문구에 "한국"을 넣어 왜 이 번호인지 바로 알게 한다.

## 범위
- 하는 것
  - i18n `bar119` 19개 언어(ko 제외)를 "한국의 응급(구급): 119" 꼴로 바꾼다
  - 언어를 고르기 전 문구(`WorkerLayout`)를 `119 · Korea Emergency · Cấp cứu`로 바꾼다
- 하지 않는 것
  - ko 문구(`응급 상황이면 119`). 한국어 사용자에게는 설명이 필요 없다
  - 다른 119 문구(`call119`, `worse119`, 응급 화면)와 112 안내
  - 번호 자체 변경

## 화면·파일

- 파일: `src/i18n/*.ts`(19개), `src/components/WorkerLayout.tsx`

## 결과
- `cd frontend && npm run build` → 통과, `cd app-front && npm run build` → 통과
- 브라우저(dev 서버 5180, 데모 로그인 상태, 지금 main의 하단 띠)
  - 360px `/home`: 앱 바 언어 목록으로 20개 언어를 차례로 바꾸며 119 버튼 높이를 쟀다. 모두 44px, 가로 넘침 없음(가장 넓은 ru·mn·uz·kk·ky·vi가 248px)
  - 375px `/home` vi: `Cấp cứu tại Hàn Quốc: 119`
- 결정
  - "전화하세요" 동사를 빼고 "한국 응급: 119" 꼴로 썼다. 버튼이 전화 링크이고 전화 아이콘이 있어 동작은 드러나며, 넣은 "한국" 만큼 길이를 줄였다
  - kk·ky·uz는 "구급(차)" 뜻의 말(жедел жәрдем, тез жардам, tez yordam)을 썼다. 의료 앱이고 119가 구급차를 부르는 번호라는 점이 더 잘 전해진다
  - 작업 중 33(하단 독, PR #132)이 main에 병합되어 이 브랜치에 main을 병합했다(언어 고르기 전 문구 줄이 겹쳐 독 쪽 마크업에 새 문구를 넣었다). 독에서 다시 쟀다: 360px `/home`에서 20개 언어 모두 119 버튼 44px 안, 가로 넘침 없음. 17개 언어는 한 줄, ru·mn·kk는 두 줄로 접힌다

## 메모
- en·vi를 포함한 19개 언어 새 문구는 원어민 검수가 필요하다. en·vi를 뺀 17개 언어는 기계 번역 초안이다(backlog 16)
- 119가 외국어 통역을 연결해 준다는 안내를 더할지는 지원 언어·범위를 기관에 확인한 뒤 정한다(확인되지 않은 내용은 넣지 않는다)
