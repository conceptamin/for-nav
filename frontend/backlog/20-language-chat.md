# 20. 언어 선택 화면을 대화형으로, 폰 언어부터 추천

상태: 완료
의존: 16 (20개 언어), 18 (로고 화면 `.w-logo`)

## 목표
S-01은 지금 영어 제목 아래에 20개 언어 버튼이 2열 격자로 놓여 있다(backlog 16). 근로자는 20개 중 자기 언어를 눈으로 찾아야 하고, 첫 문장이 영어라 영어를 못 읽으면 처음에 멈칫한다. 안내원이 근로자의 폰 언어로 먼저 말을 걸고, 근로자는 자기 언어로 된 대답 말풍선을 누르는 대화형으로 바꾼다. 폰 언어와 그에 가까운 언어를 위에 크게 추천하고, 나머지는 그 아래에 모두 보인다.

## 결정이 필요한 것

1. **"가까운 언어"를 무엇으로 정하나.** → **A로 결정(2026-10-30).**
   - **A. 손으로 쓴 가까운 언어 표(권장).** 언어마다 "이 언어를 쓰는 사람이 함께 읽을 가능성이 높은 언어"를 2~3개 적는다. 근거는 제2언어와 서로 알아듣는 정도다(예: 카자흐어·키르기스어·우즈베크어·몽골어 → 러시아어, 간체 ↔ 번체, 크메르어 → 태국어, 아랍어 → 프랑스어·영어, 그 밖의 대부분 → 영어). 20줄짜리 표라 원어민·센터 상담원이 읽고 고칠 수 있고, 결과가 늘 같다.
   - **B. 언어 임베딩(언어 유형 벡터, 예: URIEL/lang2vec) 거리.** 언어학적 거리는 "같이 읽을 수 있나"와 다르다. 네팔어와 싱할라어, 미얀마어와 중국어는 계통상 가깝지만 서로 읽지 못하고, 실제로 함께 읽을 언어(러시아어·영어)는 계통상 멀다. 20개 언어에 쓰기에는 모델·데이터 의존성도 크다(`CLAUDE.md` "의존성을 더할 때는 backlog에 이유").
2. **폰 언어가 20개에 없을 때.** 말레이어→인도네시아어, 라오어→태국어, 힌디어→네팔어, 우크라이나어·벨라루스어·타지크어→러시아어, `fil`→필리핀어, `zh-HK`·`zh-Hant`→번체처럼 가장 가까운 지원 언어로 옮겨 1번 표의 출발점으로 쓴다. 옮길 곳이 없으면 질문은 영어, 추천은 영어·한국어. 권장: 그대로.
3. **자동으로 넘기지 않는다.** 근로자가 받은 폰이나 한국에서 산 폰은 설정이 한국어인 경우가 많다. 추천은 위에 놓기만 하고, 누르기 전에는 언어를 정하지 않는다. 권장: 그대로.

## 범위
- 하는 것
  - 폰 언어 목록(`navigator.languages`, 사용자가 정한 순서)을 지원 언어로 맞추는 순수 함수와 가까운 언어 표(1번 A, 2번 표)
  - 추천 순서: ① 폰 언어 목록에서 지원되는 것(순서대로) ② 첫 언어의 가까운 언어 ③ 영어. 중복을 빼고 최대 4개. 나머지 언어는 지금 `LANGUAGE_OPTIONS` 순서
  - S-01 배치: 위에 로고 + 안내원 말풍선(첫 추천 언어로 된 질문, 그 언어가 영어가 아니면 아래 작은 영어 한 줄) → 오른쪽 정렬 대답 말풍선(추천 언어마다 그 언어로 된 대답 문장 + 작은 영어 이름) → "다른 언어" 줄바꿈 칩 묶음(모국어 이름만, 나머지 언어 전부, 늘 보임)
  - 새 문구 키 3개: `langAsk`(안내원 질문, 예: "어떤 언어로 이야기할까요?"), `langReply`(그 언어로 하는 대답, 예: "한국어로 할게요"), `langOther`("다른 언어" 묶음 제목). 20개 언어 파일 모두. 쓰이지 않던 `langHint`("나중에 화면 위에서 바꿀 수 있어요")를 질문 언어로 화면 아래에 보인다
  - `design.md`에 말풍선 두 가지(안내원: 떠 있는 면 `--clay`, 대답: 누르는 면 `--clay-sm` + `--brand-2` 바탕)를 먼저 적는다
  - `README.md` 화면 구성 표의 S-01 설명("2열 격자")을 고친다
- 하지 않는 것
  - 말풍선이 하나씩 나타나는 애니메이션·타이핑 효과(`CLAUDE.md` "애니메이션은 만들지 않는다")
  - 고른 언어를 서버로 보내기, 폰 언어를 저장하기(누른 언어만 지금처럼 `AppState`에 저장)
  - 앱 바·`/my`의 언어 `select` 순서(그대로)
  - 언어 임베딩 모델·라이브러리 추가(1번에서 B를 고르면 이 항목을 다시 쓴다)

## 화면·파일
- 화면: S-01 `/`
- 새 파일: `src/i18n/suggest.ts` — `suggestLangs(deviceLangs, order): { first: Lang | null; suggested: Lang[]; rest: Lang[] }`, `matchLang(tag)`. 폰 언어는 화면이 `navigator.languages`로 읽어 넘긴다(순수 함수)
- 수정: `src/pages/worker/Onboarding.tsx`(`LanguagePage`), `src/i18n/*.ts`(20개, 키 3개), `src/styles.css`(`.w-chat`, `.w-chat .ask`, `.w-chat .reply`, 기존 `.w-langs` 대체), `design.md`, `README.md`
- 부르는 API: 없음

## 결과
- `npm ci && npm run build` → 통과(타입 검사 + 빌드. 500kB 넘는 청크 경고는 이전부터 있던 것)
- `suggestLangs` 직접 실행(rolldown 번들 → node): vi-VN → vi,en / kk-KZ → kk,ru,ky,uz / ms-MY → id,en / de-DE → (질문 영어) en,ko / zh-HK·zh-Hant-TW → zh-TW,zh-CN,en / vi-VN+ko-KR → vi,ko,en / fil-PH → tl,en / ar-AE → ar,fr,en / 빈 목록 → en,ko. 추천 + 나머지 = 20개
- 브라우저: `vite preview`(빌드 결과) + Playwright Chromium, 360×780, 폰 언어(locale)를 vi-VN·kk-KZ·ms-MY·de-DE·ar-AE·my-MM·ru-RU·ko-KR·en-US로 바꿔 `/` 확인. 9개 모두 가로 넘침 없음(scrollWidth 360), 질문·첫 말풍선이 폰 언어, 나머지 언어가 칩으로 모두 보임. ar-AE는 화면이 RTL로 뒤집혀 안내원이 오른쪽, 대답이 왼쪽
- 누르기: vi-VN에서 첫 대답 말풍선 → `/consent`, `<html lang="vi">` / 칩 "Русский" → `/consent`, `<html lang="ru">`
- 결정
  - 추천 함수는 `domain/`이 아니라 `i18n/suggest.ts`에 뒀다. 백엔드가 옮기는 규칙이 아니고, README가 화면은 `domain/`을 직접 부르지 않는다고 정해서다
  - 폰 언어가 아랍어면 화면 뿌리에만 `dir="rtl"`을 붙인다. 언어를 고르기 전이라 `<html dir>`(AppState가 정함)는 그대로 둔다
  - 질문 언어가 영어가 아니면 질문 아래에 영어 한 줄을 붙인다. 폰 언어 추천이 틀렸을 때(한국에서 산 폰 등) 영어로라도 무엇을 묻는지 알게 하려고
  - 영어 폰은 추천이 영어 하나뿐이다. 영어로 설정한 네팔·스리랑카·필리핀 근로자가 있을 수 있어도, 그들의 언어는 바로 아래 칩에 있다
- 남은 문제: 실제 iOS·Android 기기에서 `navigator.languages`가 기기 설정 순서대로 오는지는 보지 않았다(데스크톱 Chromium의 locale 설정으로만 확인)

## 메모
- `langAsk`·`langReply`의 en·vi·ko를 뺀 17개 언어는 기계 번역 초안이다. 원어민 검수가 필요하다(backlog 16과 같음).
- 가까운 언어 표도 원어민·센터 상담원 검토 대상이다. 울산 근로자 실제 제2언어 분포를 알게 되면 표를 고친다.
