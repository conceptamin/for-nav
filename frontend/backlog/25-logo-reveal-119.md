# 25. 모든 화면 공통: 좌측 상단 로고, 스크롤 등장 효과, 작고 반투명한 119 버튼

상태: 완료("동작 줄이기" 확인은 PR 검토에서)
의존: 없음(24 위에서 한다)

## 목표
2026-10-30 사용자 요청: "우리 앱 모든 페이지에서 좌측 상단에 우리 로고가 뜨게 해. 그리고 모든 페이지에서 scroll reveal 효과 적용해. 119 박스 크기 줄이고 빨간색 투명도 높여줘." 지금 로고는 홈 앱 바에만 있고, 화면 요소는 효과 없이 바로 보이며, 119 버튼은 화면 폭을 꽉 채운 진한 빨강이다. 세 가지 모두 레이아웃(`WorkerLayout`·`CenterLayout`)과 `styles.css` 공통 규칙으로 처리한다.

## 범위
- 하는 것
  - **로고(`/logo.png`)를 모든 화면 좌측 상단에**
    | 화면 | 지금 | 바뀐 뒤 |
    |---|---|---|
    | 홈 `/home` | 로고 + 앱 이름 | 그대로 |
    | 그 밖의 근로자 화면(앱 바 있음) | ← 하나 | ← 오른쪽에 로고 28px(← 가 맨 왼쪽이어야 엄지로 누르기 쉽다). 회원·비회원이 정해졌으면 로고를 누르면 `/home` |
    | 앱 바가 없는 화면: S-01 언어, S-03 로그인, 분석 중 | 없음 | 앱 바 없이 좌측 상단에 로고 28px 하나(누를 수 없음) |
    | 스플래시 | 가운데 큰 로고 | 그대로(화면 자체가 로고) |
    | 센터 화면 `/center*` | 글자 브랜드 | 글자 앞에 로고 24px |
  - **스크롤 등장(scroll reveal)**: 화면 요소가 화면 안으로 들어올 때 아래에서 16px 올라오며 나타난다(투명 → 불투명). 300ms(`duration-d6`), `easing-enter`, 한 번만. 함께 들어오는 것끼리는 40ms씩 차례로(최대 200ms)
    - 대상: 각 화면 뿌리의 덩어리(카드, h1, 목록 등)와 목록·격자의 항목(언어 칸, 홈 기능 목록 줄, 리포트 행 등). 화면이 바뀌거나 단계가 바뀌어 새로 생긴 요소도 같다
    - **예외(바로 보인다)**: 응급 화면 `/emergency` 전체, 하단 119 버튼, 바닥 주 동작 버튼(`.w-footer`), 앱 바. 119·응급 안내는 지연 없이 보여야 한다
    - 기기 설정이 "동작 줄이기"(`prefers-reduced-motion: reduce`)면 효과 없이 바로 보인다. `IntersectionObserver`가 없는 브라우저도 바로 보인다(숨긴 채 멈추지 않는다)
    - `frontend/CLAUDE.md`의 "애니메이션은 만들지 않는다"에 이 효과를 예외로 적고, `design.md` "Motion"에 이 프로젝트의 규칙으로 적는다
  - **119 버튼**
    - 크기: 높이 52 → 44px, 글자 18 → 16px, 화면 폭 꽉 채움 → 글자 길이만큼(가운데, 좌우 여백 24px). 버튼 자리 `--bar-119` 72 → 64px
    - 색: 불투명 빨강 → 85% 빨강(새 토큰 `--danger-glass`) + 뒤 흐림. 흰 글자 대비는 가장 밝은 바탕 위에서 약 4.7:1로 4.5:1 기준을 넘는다. 80%로 내리면 4.4:1이라 기준 아래로 떨어진다
    - `design.md`의 "색이 있는 면은 불투명하다"에 119 버튼 예외를 적는다
- 하지 않는 것
  - 로고 이미지 변경, 페이지 전환 효과, 버튼 누름 효과 등 다른 애니메이션
  - 응급 화면의 전화 버튼(`.em-call`) 변경

## 결과
- 실행(2026-10-30, 브랜치 `frontend/layout-logo-reveal-119`)
  - `npm run build` → 통과
  - 앱 브라우저 창을 보이게 한 상태에서(숨긴 창은 스크롤 관찰이 멈춘다) 360px로 확인
    - `/guide`(ko): ← 오른쪽에 로고(홈 링크). 처음 화면 안의 h1·카드 다섯은 열릴 때 차례로 나타나고(i0~i4), 화면 아래 카드 넷은 기다리다가 스크롤하면 차례로 나타난다
    - `/emergency`: 등장 표시가 붙은 요소 0개(모두 바로 보인다)
    - `/home`(ar, RTL): 로고 + 앱 이름이 오른쪽 위, ← 와 겹침 없음. `/my`(vi): ← + 로고 + 언어 선택 한 줄
    - S-01: 앱 바 없이 좌측 상단 로고 하나, 언어 칸 20개가 등장 효과로 나타난다
    - 119 버튼: 높이 44px, 폭은 글자만큼(ko 198px, vi 211px, en 279px), 배경 `rgba(202, 29, 19, 0.85)`. 가로 넘침 0
    - 1280px `/center`: 머리글 글자 앞 로고, 접수함 덩어리 4개에 등장 효과, 오류 없음
- 결정 사항
  - 앱 바의 로고를 홈·그 밖 모두 28px로 맞췄다(홈은 24px이었다). 센터 머리글은 높이 60px 띠라 24px
  - 개발 모드(React StrictMode)는 효과를 두 번 붙였다 뗀다. 처음 구현은 뗄 때 기다리던 요소를 "나타남"으로 바꿔, 화면 밖 요소까지 열자마자 나타나 버렸다. 뗄 때는 표시만 지우도록 고쳤다(응급 화면으로 가며 꺼질 때도 지운 요소는 바로 보인다)
  - 아주 긴 요소도 나타나도록 "10% 보이면" 대신 "화면 아래 10% 안쪽에 닿으면"으로 잡았다
  - 차례(40ms 간격)는 인라인 `style`이 아니라 `data-reveal-i` 속성 + CSS 규칙 다섯 줄로 준다(인라인 `style`을 더하지 않는 규칙)
- 확인하지 못한 것: "동작 줄이기" 설정, S-03 로그인·분석 중 화면의 모서리 로고(S-01과 같은 코드 경로), 실제 휴대폰
