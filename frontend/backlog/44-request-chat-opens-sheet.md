# 44. 센터 요청을 보내면 채팅 시트가 열리게

상태: 완료
의존: 39 센터 채팅 시트

## 목표
2026-10-31 사용자 결정: 제도 결과의 "이 내용으로 센터에 문의"로 S-12(`/center-request`)에 들어와 요청을 보내면, 페이지 안 채팅 대신 하단 채팅 아이콘이 여는 센터 채팅 시트(backlog 39)가 열려 방금 보낸 요청의 채팅을 보인다. 시트 머리의 📞로 통화로 바꿀 수 있으므로 S-12에서 연락 방법(통화·대화)을 따로 묻지 않고, 시트 안에서 통화도 된다고 안내한다.

## 범위
- 하는 것
  - `WorkerLayout`이 시트를 여는 함수를 context로 내준다(`useOpenCenterSheet()`). 하단 채팅 아이콘과 같은 시트·같은 상태를 쓰므로 열리면 아이콘이 눌린 모양(`aria-expanded=true`)이 된다
  - S-12 입력 화면에서 "센터가 어떻게 연락할까요?"(통화·대화 고르기)를 지운다. 흐름은 종류 → 보낼 내용 → 전송 동의 → 보내기
  - S-12 보내기가 성공하면 시트를 연다. 시트는 가장 최근 요청, 곧 방금 보낸 요청의 채팅을 보인다
  - 전송 완료 화면의 통화·채팅 고르기와 페이지 안 통화·채팅 패널을 지우고, 시트를 다시 여는 `💬 센터와 대화` 버튼 하나를 둔다(같은 요청의 연결이 두 개 생기지 않게)
  - 시트: 통화를 쓸 수 있으면 요청 번호 줄 아래에 "📞을 누르면 센터와 통화한다"는 안내 말풍선(`chatCallHint`)을 채팅일 때 보인다
  - 시트가 자기 안에서 보낸 요청보다 새 요청이 생기면(S-12에서 보냄) 새 요청의 채팅을 보인다
  - 단독 모드(토큰 없음)는 시트를 열지 않고 지금처럼 페이지에 `talkOffline` 한 줄
  - i18n: 새 키 `chatCallHint`를 20개 언어에 넣는다
- 하지 않는 것
  - 시트 모양·동작(backlog 39), 하단 독, 119 버튼
  - 통화 흐름, 백엔드 계약(`contactMethod`는 지금도 늘 `null`), `domain/`

## 결과
- `cd frontend && npm run build` → 통과(청크 크기 경고만 기존과 같다), `cd app-front && npm run build` → 통과
- 브라우저 확인: Playwright 헤드리스 Chromium, 360×780, 저장소에 데모 계정·프로필을 넣어 시작
  - API 모드(dev 5201 + 로컬 백엔드 :8000, `WORKER_AUTH` off) en·vi·ko: `/center-request?type=policy`(제도 결과 "이 내용으로 센터에 문의"가 가는 주소)의 입력 화면에 라벨이 "무엇이 필요하세요?" 하나뿐(연락 방법 없음). 동의 → 보내기 → `POST /api/center/cases` 1번, 주소 `/center-request` 그대로, 시트가 열리고 `.bar-chat` `aria-expanded=true`. 시트에 `chatIntro` → 요청 번호 → `chatCallHint` 말풍선 → 채팅 패널. 페이지 본문에 채팅 패널 0개. 📞 → 제목 "센터와 통화" + 안내 말풍선 사라짐, 💬 → 채팅. ✕로 닫고 전송 완료 화면의 `💬 센터와 대화` → 같은 요청 번호로 다시 열림. 가로 넘침 없음, 콘솔 오류 없음
  - 같은 앱 안에서 하단 아이콘 시트로 요청을 먼저 보낸 뒤 홈 메뉴로 S-12에 가서 또 보내면, 시트가 새 요청 번호의 채팅으로 바뀌고 이전 "보냈어요" 말풍선은 접힌다
  - 단독 모드(dev 5202) en: 보내면 시트가 열리지 않고(`aria-expanded=false`) `talkOffline` 한 줄
- 결정
  - 연락 방법을 묻지 않는다. 시트 머리의 📞로 언제든 통화로 바꿀 수 있어 미리 고르는 것이 겹친다(사용자 결정)
  - 전송 완료 화면에는 채팅·통화 패널을 두지 않는다. 시트와 페이지가 같은 요청에 연결을 둘 열지 않게 하려는 것이다
  - 단독 모드는 토큰이 없어 시트에 채팅을 붙일 수 없으므로 시트를 열지 않는다(열면 시트가 요청 종류부터 다시 묻는다)

## 메모
- 처음 문서는 "대화"를 누르는 순간 시트를 여는 안이었다. 사용자가 "요청을 보내면 그 창이 열리는 게" 낫고, 열린 창에서 전화도 고를 수 있게 안내하면 된다고 해서(2026-10-31) 연락 방법 질문을 지우는 안으로 바꿨다
- `cenContactMethod` 키는 이제 쓰는 곳이 없다. 20개 언어 파일에서 지우는 것은 따로 한다
- 새 키 `chatCallHint`의 vi 문구는 원어민 검수가 필요하다. en·vi를 뺀 17개 언어는 기계 번역 초안이다(backlog 16)
