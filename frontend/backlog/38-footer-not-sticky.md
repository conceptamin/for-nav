# 38. 바닥 주 동작 버튼을 본문 맨 끝으로 내리기

상태: 완료
의존: 없음

## 목표
2026-10-31 사용자 결정: "저장하고 계속"·"보내기" 같은 주 동작 버튼이 119·채팅 독과 함께 화면 위에 떠 있을 필요가 없다. 페이지 맨 아래에 있으면 된다. 위 입력을 다 채워야 켜지는 버튼이라, 그 전에는 꺼진 채 화면 아래를 가리고 독과 두 층으로 떠서 폰에서 입력할 자리를 줄인다. 화면 위에 계속 떠 있는 것은 언제든 눌러야 하는 119·채팅 독뿐으로 둔다.

## 범위
- 하는 것
  - `.w-footer`의 `position: sticky; bottom: 0`을 뺀다
  - 배경 띠(`::before`의 `--card` 채움·흐림·위쪽 1px 선)도 뺀다. 떠 있지 않으니 뒤 내용을 가릴 일이 없어 버튼만 둔다(2026-10-31 사용자 결정: "버튼만 있어도 된다"). 띠를 독 자리까지 늘리던 음수 여백도 함께 지운다
  - 띠를 화면 폭(100vw)으로 그려 생기던 가로 넘침을 자르던 `html:has(.w-shell) { overflow-x: clip }`을 지운다. 그 띠가 마지막 사용처였다
  - `.w-footer`를 쓰는 다섯 곳이 모두 바뀐다(사용자 결정: 다섯 곳 모두): S-02 동의(`Onboarding.tsx`), S-03 프로필 "저장하고 계속"(`Onboarding.tsx`), S-05 증상 입력(`Intake.tsx`), S-11 항목 선택(`Report.tsx`), S-12 센터 요청 "보내기"(`CenterRequest.tsx`)
  - `design.md`의 `.w-footer` 설명을 고친다
- 하지 않는 것
  - 본문이 짧은 화면의 배치. `.w-screen`의 `margin-top: auto`가 그대로 화면 바닥으로 민다
  - 119·채팅 독(`.bar-119`)

## 결과
- `cd frontend && npm run build` → 통과
- 브라우저(단독 모드, Playwright Chromium 헤드리스, ko, 데모 로그인)
  - 360×640 S-12 `/center-request`: 맨 위에서는 "보내기"가 화면 밖이고, 끝까지 내리면 본문 끝에 있다
  - 360×640, 끝까지 내렸을 때 S-02·S-03·S-05·S-11·S-12 모두 버튼 488~552(위 16px 여백 포함), 독 578~630. 버튼과 독 사이 26px, 겹치지 않는다
  - 360×640 S-02 동의: 본문이 짧아 버튼이 독 바로 위 바닥에 있다
  - 1280×800 `/home`·`/center-request`·`/intake`·`/report/new`·`/my`: `scrollWidth` = `clientWidth` = 1280, 가로 넘침 없음
- 결정: 위 간격은 `margin-top`이 아니라 `padding-top: 16px`로 둔다. `.w-screen .w-footer`의 `margin-top: auto`는 본문이 길면 0이 되어, S-05 부위 칩 바로 밑에 버튼이 붙었다
