# 23. 홈(S-04)을 심토미 홈 배치로

상태: 완료
의존: 없음(12·15·21 위에서 한다)

## 목표
2026-10-30 사용자 요청: "for-nav 앱의 홈화면을 만들어줘. simtomi 앱을 참고해줘"(심토미 홈 캡처 세 장). 지금 홈 `/home`은 인사 h1 → 나 한 줄 → `아파요 / 다쳤어요` → 같은 모양의 메뉴 카드 네 개가 세로로 쌓여 있어, 주 동작과 나머지가 크기만 다르고 덩어리가 나뉘어 보이지 않는다. 심토미 홈처럼 **나(프로필) → 큰 시작 카드 → 보조 기능 목록 → 최근 기록** 네 덩어리로 나눈다. 15와 같이 **글래스모피즘은 유지하고 배치만 고친다.**

## 심토미 홈과 대응
| 심토미 (위에서 아래로) | 우리 홈 | 비고 |
|---|---|---|
| 앱 바: 로고 + `Simtomi` | 앱 바: 로고 + 앱 이름 + 언어 선택 | 그대로 |
| `지니 ∨` (누르면 프로필 목록 시트) | **나 줄**: 회원 `여성 · 1997 ›` → `/my`, 비회원 `비회원 · 프로필 만들기 ›` → `/signup` | 이름을 받지 않으므로 성별·출생 연도(12의 결정). 시트는 만들지 않는다(모달·시트 금지). 인사 h1 `무엇을 도와드릴까요?`는 지운다 — 심토미에 없고, 시작 카드가 그 질문의 답이다 |
| 파란 큰 카드 `증상 체크 / 왜 아픈지 궁금할 때 / [시작하기]` | **시작 카드** `.home-hero` → `/intake`: 제목 `아파요 / 다쳤어요`(`menuSick`), 부제 `어느 진료과로 가야 하는지 찾기`(`menuSickSub`), 안쪽 알약 `시작하기`(새 키 `homeStart`) | 브랜드색 채움 카드. 카드 전체가 링크 하나(알약은 모양만, 따로 누르는 버튼이 아니다). 오른쪽 장식 도형은 CSS 그라데이션 한 겹, 이미지 없음 |
| `인기 키워드` 칩 가로 스크롤(두통·기침·콧물·열이 남…) | 하지 않는다 | "정할 것 1"에서 A로 정했다(2026-10-30) |
| 목록 줄: 아이콘 · 작은 회색 분류 위 + 큰 제목 아래 · › (`내 기록`, `통역하기`) | **기능 목록** `.home-list`: `병원 이용 방법`, `보험과 지원`, `지원센터에 문의`, `내 정보` 네 줄. 아이콘 · 작은 부제(`menu*Sub`) 위 + 제목 아래 · › | 카드 네 장 대신 한 유리판 안의 줄 네 개(줄 사이 구분선). 문구 키는 그대로 |
| `최근 리포트` h2 + 카드(제목 `속쓰림`, `동반 증상: …`, 🕓 날짜) | **최근 메모** h2(`homeRecent`) + 카드 → `/report/:id`: 증상 글자(`valueNative`), 🕓 날짜 | `app.reports[0]` 하나. 없으면 h2째 없다(12와 같다). 판정·진료과는 보이지 않는다 |
| `내 근처 약국 · 병원` 탭 + 목록 + 새로고침 | 하지 않는다 | 위치·약국 데이터가 없고, 확인되지 않은 주소를 넣지 않는다(`README.md` "확인이 필요한 값") |
| 하단 탭 바(홈·대화·지도·더보기) | 하지 않는다 | 바닥은 119 띠 자리다(제품 규칙) |

## 범위
- 하는 것
  - `design.md`에 홈 배치 표(위 대응 표의 오른쪽 열)와 새 클래스(`.home-me`, `.home-hero`, `.home-list`, `.home-recent`)를 먼저 적는다. 면은 기존 세 면 규칙을 따른다: 시작 카드는 떠 있음(브랜드 채움), 기능 목록은 떠 있는 유리판 하나에 안쪽 줄은 평평, 최근 메모 카드는 떠 있음
  - `HomePage`(`src/pages/worker/Onboarding.tsx`)를 위 순서로 다시 그린다
  - 새 문구 키 `homeStart`(시작하기)를 20개 언어에 넣는다
  - `README.md` 화면 구성 표의 홈 설명(`홈(나 한 줄 → 아파요/다쳤어요 → 최근 메모 → 메뉴)`)을 새 순서로 고친다
- 하지 않는 것
  - 프로필 목록 시트·여러 프로필(가족 프로필). 프로필은 하나다
  - 근처 약국·병원, 지도, 새로고침
  - 하단 탭 바. 119 띠 그대로
  - 글래스모피즘·색 토큰 변경. 심토미의 흰 평면 대신 지금 유리 면을 쓴다
  - `/my`(S-13) 변경
  - 진단 표현. 칩·최근 메모에 병명을 쓰지 않는다

## 정할 것
1. **`인기 키워드` 칩.** 우리에게는 "인기" 통계가 없다. 접수 S-05는 부위 → 증상 순서로 한 문제씩 묻는다.
   - **A(결정, 2026-10-30 사용자).** 넣지 않는다. 시작 카드 하나로 `/intake`에 들어간다
   - B. `자주 찾는 증상`(새 키 `homeSymptoms`) 칩 대여섯 개(열·기침·어지러움·통증·부기 등, `term(SYMPTOMS[…])`)를 넣고, 누르면 `/intake?symptom=fever`로 그 증상을 미리 고른 채 시작한다. `IntakePage`가 쿼리를 읽도록 고쳐야 하고, 부위 질문과의 순서를 정해야 해서 범위가 커진다

## 결과
- 실행(2026-10-30, 브랜치 `frontend/home-simtomi`)
  - `npm run build` → 통과(기존 청크 크기 경고만)
  - 앱 브라우저 창(360×800)에서 세션·기기 저장소를 넣어 가드를 통과시킨 뒤 `/home`을 여섯 경우로 확인했다: vi 회원+메모, en 회원+메모, ko 비회원·메모 없음, ar 회원+메모(RTL), my 회원+메모, ru 비회원+메모. 모두 가로 넘침 0px, 기능 목록 링크 `/guide,/coverage,/center-request,/my`, 시작 카드 `/intake`, 나 줄은 회원 `/my`·비회원 `/signup`. 메모가 없으면 h2·카드가 없다
  - ko·vi·ar은 화면을 찍어 봤다. ar에서 ›가 ‹로 뒤집히고 장식 판이 시작 카드의 반대쪽(왼쪽 아래)으로 간다
  - ar 화면에서 시작 카드를 눌러 `/intake`로 가는 것을 확인했다
- 결정 사항
  - 칩은 넣지 않았다(정할 것 1 → A)
  - 인사 h1과 나 줄의 👤를 뺐다. 심토미처럼 나 줄 글자를 크게(`--t8` 굵게) 해 화면 머리로 쓴다. 인사 키 `homeHello`는 쓰는 곳이 없어져 20개 언어에서 지웠다
  - 기능 목록은 줄 사이 구분선 없이 판 하나에 담았다(SEED menu: Menu Item 사이 Divider 금지, 심토미 목록도 선이 없다). 안의 줄은 평평이라 눌림은 그림자 대신 `--bg-2` 바탕으로 보인다
  - 최근 메모 카드는 심토미 리포트 카드처럼 세 줄: 증상, `부위: …`(리포트에 부위 행이 있을 때만), 🕓 연·월·일. 증상 행을 리포트에서 뺐으면 첫 행 값을 제목으로 쓴다
  - 시작 카드 장식은 이미지 없이 `::before`·`::after` 두 장(`--on-brand-soft`)이다. 그림자·색 토큰은 새로 만들지 않았다
  - `.menu` CSS는 홈에서만 쓰였으므로 지웠다. `--radius-lg`는 이제 응급 전화 버튼·하단 119 버튼만 쓴다(`design.md` 둥글기 표를 고쳤다)
- 남은 문제
  - 없음. 근처 약국·병원과 증상 칩은 하지 않기로 했다(범위)
