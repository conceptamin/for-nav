# 42. 센터 통계를 센터 보고 형식(월별·분야별·국적별)으로

상태: 완료
의존: 41(분야). backend 25가 같은 집계를 돌려준다. 프론트가 원본이므로 이 항목을 먼저 한다

## 목표
센터 회신(2026-10-31)은 의료 상담을 **월별**(5월 16건 → 9월 97건 → 10월 65건, 8~10월이 75.1%), **분야별**(의료·보건 / 건강보험·공공의료 / 의료비 지원), **국적별**(12개국, 상위 5개국이 87.2%)로 보고한다. C-03 `/center/stats`는 업종·언어·보험·시간외를 30/90/180일 합계로만 보여 월별 추이도 분야도 국적도 없다. 센터가 보고서에 그대로 옮길 수 있는 집계로 바꾼다.

## 범위
- 하는 것
  - C-03에 칸 셋 추가: "월별 요청 수"(최근 6개월 막대), "분야별 요청 수"(41의 `category`), "국적별 요청 수"(상위부터, 5건 미만은 지금처럼 `<5`). 기간(30/90/180일)·구군 필터는 그대로 두되 월별 막대는 기간과 무관하게 최근 6개월이다
  - "언어별 요청 수"를 20개 언어 전부로 센다(지금은 `vi`·`en`만 집계한다)
  - 국적 `nationality`: 근로자가 S-03 프로필에서 **선택으로** 고른다(ISO 3166-1 alpha-2, 센터 회신 12개국을 앞에 두고 "그 밖"). 센터 전송 동의 항목에 "국적"이 들어가고, 동의하지 않으면 보내지 않는다. `Profile.nationality: string | null`, `CenterCase.nationality: string | null`, `StatRecord.nationality`
  - `data/mock.ts`의 통계 원천 420건
    - 날짜: 지금은 180일 균등이다. 같은 난수값을 센터 회신의 월별 비율(16·25·41·85·97·65)로 옮겨 8~10월 봉우리를 만든다. 뽑는 난수 수가 같아 뒤 항목 값은 바뀌지 않는다
    - 국적: 센터 회신 건수 그대로(329건, 12개국)를 두 번째 시드(`rng(78)`)로 섞어 나눈다(Fisher–Yates, 끝에서부터). 언어는 회신에 없으므로 국적의 모국어로 정한다(사용자 결정 2026-10-31, 아래 메모). 첫 시드의 언어 자리 난수는 그대로 소비해 뒤 항목 값이 바뀌지 않게 한다. mock 사례 24건은 `LANG_W`를 그대로 두고 국적은 `null`이다
    - `category`는 두 번째 시드로 국적 다음에 뽑는다(의료·보건 70 / 건강보험·공공의료 20 / 의료비 지원 10, 회신에 건수가 없어 가정값)
  - `getStats` 응답 `CenterStats`에 `byMonth`(`{ key: 'YYYY-MM', n }`)·`byCategory`·`byNationality` 추가. 단독 모드 집계는 `centerStore`가, API 모드는 서버가 한다
  - `README.md` C-03 설명과 "상태의 경계"(국적이 프로필에 들어간다)
- 하지 않는 것
  - 센터 전체 상담(비의료 포함) 집계. 앱은 의료 상담만 다룬다
  - 표 내보내기(CSV·엑셀). 후속으로 남긴다
  - 언어로 국적을 추정하기(메모)

## 결정이 필요한 것
1. **국적을 받을지.** A. 프로필에서 선택으로 받는다(권장: 센터 보고 단위가 국적이고, 러시아어 사용자는 러시아·카자흐스탄·우즈베키스탄·키르기스스탄·타지키스탄 어느 쪽인지 언어로는 알 수 없다). B. 받지 않고 언어별만 보인다(국적별 칸은 빼고, 센터 보고 형식과는 어긋난다)
2. **mock 월별 분포를 센터 회신 모양으로 맞출지.** 권장: 맞춘다. 규모는 지금 420건/180일(월 70건 안팎)이 센터의 월 55건과 비슷하므로 건수는 그대로 둔다

## 결과
- `npm run build` → 통과(청크 크기 경고만). `cd app-front && npm run build` → 통과(바뀐 공유 파일 `Onboarding.tsx`·`CenterSheet.tsx`·`i18n`을 import한다)
- `parity.json` 재생성 → 바뀐 키는 `statRecords`(국적·분야 추가, 언어가 국적에서 정해짐), `mockCases`(`nationality: null`만 추가), `generatedAt`. 통계 원천의 날짜·구군·업종·보험·시간외·요청 종류·업무 관련은 바꾸기 전 덤프와 329건 모두 같다
- 통계 원천 분포(`NOW` 2026-10-26 기준): 국적 인도네시아 81·러시아 61·카자흐스탄 57·스리랑카 48·필리핀 40·우즈베키스탄 24·베트남 6·한국 5·키르기스스탄 2·동티모르 2·타지키스탄 2·모로코 1(회신과 같다). 언어 인도네시아어 81·러시아어 63·카자흐어 57·싱할라어 48·영어 26·우즈베크어 24·필리핀어 16·베트남어 6·한국어 5·키르기스어 2·아랍어 1. 분야 227·68·34
- 단독 모드 1280px `/center/stats`(Playwright): 월별 막대 6칸(2026년 5월~10월, 8~10월이 높다), 30일로 좁혀도 월별은 같다. 분야별 세 칸, 국적별은 인도네시아가 맨 위이고 5건 미만(한국·키르기스스탄·타지키스탄·동티모르·모로코)은 `<5`. 언어별에 `vi`·`en` 밖 언어가 센다(인도네시아어가 가장 많다, 아래 결정)
- 360px S-03 `/signup` en·vi·ko·ru: 국적 칸이 공통 입력(`select.input`, 높이 48px) 한 칸으로 들어가고 가로 스크롤 없다. 첫 칸은 화면 언어 이름(Indonesia·인도네시아·Индонезия)
- 360px S-12 `/center-request`(en, 프로필 국적 KZ): 전송 동의 아래 "Also send my nationality … Kazakhstan" 한 줄. 동의하면 사례 `nationality: "KZ"`·동의 항목에 "국적", 동의하지 않으면 전송 본문에 `nationality` 키가 없고 사례는 `null`
- 결정
  - 언어별 1위가 러시아어가 아니라 인도네시아어다. 완료 기준 "러시아어가 가장 많다"는 국적을 러시아어권으로 묶던 `STAT_LANG_W` 기준이었고, 사용자 결정(국적에 맞춘다, 언어는 국적의 모국어)으로 바뀌었다
  - 나라 이름은 `Intl.DisplayNames`로 화면 언어에 맞춰 보인다(20개 언어 국가명 번역 표를 두지 않는다). 센터 화면은 `ko-KR`
  - 국적 칸은 공통 select 하나(앞 12개국 + `optgroup` "그 밖" 237개국)로 했다. 칩으로 하면 360px에 12개가 넘친다
  - 국적 순서·"모름"·가림: 있는 국적만 많은 순(같으면 코드 순)이고 국적이 없는 사례는 `unknown`. 가린 칸은 수가 작아 끝에 온다
  - `Profile.nationality`는 선택 필드(`?`)다. 이 칸 전에 저장한 프로필과 `parity.json`의 `PROFILES`를 바꾸지 않으려고
  - mock 사례 24건의 국적은 `null`(국적을 보내지 않은 사례)로 두었다. 언어에서 국적을 거꾸로 추정하지 않는다
- 완료 기준 "국적을 고르지 않고 보낸 사례는 … 통계의 '모름' 칸에 들어간다"의 뒤 절은 지키지 못했다: 통계는 지금 단독·API 모드 모두 원천 레코드만 세고 실제 전송 사례를 넣지 않는다. 이 항목은 집계 방식을 바꾸지 않았고, '모름' 칸은 국적 없는 레코드가 있을 때 생긴다(세는 코드는 있다). 앞 절(`nationality: null`)은 확인했다
- 남은 것: backend 25(서버 집계·`nationality` 저장, 같은 원천). 그전까지 `backend`의 `uv run pytest`는 `statRecords`·`mockCases` 비교에서 실패한다. 새 문구 3개(`nationalityQ`·`nationalityOther`·`consentNationality`)는 en·ko 밖 18개 언어가 기계 번역 초안이라 원어민 검수가 필요하다

## 메모
- 2026-10-31 사용자 결정: 통계 mock은 국적을 회신 건수 그대로 두고, 상담 언어 데이터가 없으므로 언어는 국적의 모국어로 정한다(카자흐스탄 → 카자흐어, 우즈베키스탄 → 우즈베크어, 키르기스스탄 → 키르기스어, 필리핀 → 영어 2 : 필리핀어 1, 앱에 없는 타지크어 → 러시아어, 테툼어 → 영어, 모로코 → 아랍어). 이전 `STAT_LANG_W`(러시아어권 묶음 44%)를 대신한다
- 센터 회신 국적별(329건): 인도네시아 81, 러시아 61, 카자흐스탄 57, 스리랑카 48, 필리핀 40, 우즈베키스탄 24, 베트남 6, 한국 5, 키르기스스탄·동티모르·타지키스탄 각 2, 모로코 1. 상위 5개국 287건(87.2%)
- 센터 회신 월별(의료 상담): 5월 16, 6월 25, 7월 41, 8월 85, 9월 97, 10월 65. 월평균 55건. 센터 전체 상담 2,559건 중 의료 329건(12.9%)
- 센터 통계는 센터에 접수된 건수라 울산 전체 외국인근로자의 의료 이용 현황이 아니다(회신 1항). 통계 화면 아래 주석에 같은 말을 둔다
- 국적은 민감할 수 있어 통계에서만 쓰고 C-01 목록에는 보이지 않는다. C-02 상세에는 동의한 항목일 때만 보인다
- API 계약이 바뀐다(backend 25). 서버가 맞추기 전 API 모드 C-03은 새 칸이 비어 보이고, 기존 네 칸은 그대로다
- mock 통계 원천의 날짜·언어·구군·시간외 분포와 언어 20개 집계는 51에서 먼저 했다(329건). 이 항목에서는 칸 추가·국적·분야만 남는다
