# 50. 홈 밖의 화면에서 여는 메뉴 서랍

상태: 완료
의존: 없음

## 목표
지금은 `병원 이용 방법` 같은 메뉴에 들어가면 다른 메뉴로 가려면 ←나 로고로 홈에 돌아가야 한다. 홈 밖의 화면에서도 홈의 메뉴로 바로 옮겨 갈 수 있게, 끝 쪽(오른쪽)에서 밀려 들어오는 메뉴 서랍(drawer)을 둔다. 서랍이 있다는 것은 화면 끝 쪽 가장자리의 작은 손잡이로만 알린다(2026-10-31 사용자 요청).

## 결정 (2026-10-31 사용자)
1. 자리: 화면 **오른쪽**에서 연다. RTL(ar)에서는 이 앱의 다른 끝 쪽 요소(독, 언어 버튼)처럼 왼쪽으로 뒤집는다
2. 표시: 오른쪽 가장자리 가운데에 뜬 작은 손잡이. 누르거나 안쪽으로 밀면 열린다. 앱 바는 그대로 둔다
3. 항목: 홈 + 홈의 메뉴 다섯 개(아파요/다쳤어요, 병원 이용 방법, 보험과 지원, 센터에 요청, 내 정보). 지금 화면은 눌린 모양
4. 움직임: 0.2초 밀려 들어오고 막이 옅게 깔린다. 기기가 움직임 줄이기를 켰으면 움직임 없이 바로 뜬다. design.md의 "모달·애니메이션 없음"에 두는 예외다

## 범위
- 하는 것
  - `components/WorkerDrawer.tsx`: 손잡이 + 막 + 서랍. Esc·막·✕·메뉴를 누르면 닫히고, 열면 서랍으로 초점이 가고 뒤 화면은 스크롤되지 않는다(센터 채팅 시트와 같다)
  - `components/workerMenu.ts`: 홈 목록과 서랍이 같은 메뉴 표를 쓴다
  - 손잡이는 로그인하고 프로필까지 있고, 홈(`/home`)·첫 화면(`/`)이 아니고, 앱 바를 숨긴 화면이 아니고, 센터 채팅 시트가 닫혀 있을 때만 보인다. 서랍과 시트는 하나만 열린다
  - 119 독은 서랍·막 위에 그대로 보이고 눌린다. 서랍은 독 위에서 끝난다
  - 새 문구 키 `menu`(손잡이·서랍 이름) 20개 언어
- 하지 않는 것
  - 앱 바에 ☰ 버튼 두기(사용자 결정 2)
  - 서랍 안 프로필·최근 리포트·언어 변경
  - app-front의 Android 뒤로 가기가 열린 서랍을 먼저 닫게 하기(`app-front/src/bridge/back.ts`, 아래 메모)

## 결과
- `cd frontend && npm run build` → 통과, `cd app-front && npm run build` → 통과
- 단독 모드 360px, 데모 계정으로 확인
  - en `/guide`: 손잡이(28×80 누르는 자리, 14×56 탭)가 오른쪽 가장자리 가운데. 누르면 서랍이 x 60~348, y 12~688(독 위 698 전)에 열리고 `How to use a hospital`이 `aria-current`. 초점은 서랍, 뒤 화면 `overflow: hidden`, 독 자리 맨 위 요소가 `.bar-dock`
  - 서랍 `Insurance & support` → `/coverage`, 서랍 닫힘·스크롤 풀림. 다시 열면 그 메뉴가 눌린 모양. Esc·막·✕로 닫히고 Esc·✕ 뒤 초점은 손잡이
  - 손잡이를 안쪽으로 8px 밀면 그대로, 26px 밀면 열림. 센터 채팅 시트를 열면 손잡이가 사라지고 닫으면 돌아온다
  - `/home`·`/consent`: 손잡이·서랍 없음. 홈 목록과 시작 카드는 메뉴 표로 바꾼 뒤에도 문구·순서가 같다
  - vi `/center-request`: 여섯 줄 모두 52px 한 줄, 가로 넘침 없음, `Hỏi trung tâm hỗ trợ`가 눌린 모양. ko `/my`: `내 정보`가 눌린 모양, 손잡이 이름 "메뉴"
  - ar `/guide`: 손잡이 x 0~28, 열린 서랍 x 12~300(왼쪽), 닫힐 때는 왼쪽 밖으로 나간다
  - 콘솔 오류 없음
- app-front(5192, 호스트 없음) `/coverage`: 손잡이가 보이고 열면 `Insurance & support`가 눌린 모양
- 결정: 서랍 열림 상태는 `WorkerLayout`이 갖고(시트와 하나만 열리게), 화면이 바뀌면 닫는다. 닫힌 서랍은 `visibility: hidden`이라 초점·읽기 도구에 잡히지 않는다. 앱 바는 바꾸지 않았으므로 app-front의 `.w-header button.back` 선택자는 그대로다

## 메모
- app-front의 Android 뒤로 가기(`backPolicy`)는 앱 바 ←를 누른다. 서랍이 열려 있으면 화면이 바뀌면서 서랍이 닫히므로 깨지지는 않지만, 흔한 앱처럼 뒤로 가기가 서랍만 먼저 닫게 하려면 app-front 쪽 작업이 따로 필요하다
- `menu` 문구는 en·ko 말고는 기계 번역 초안이다. vi는 원어민 검수가 필요하다(backlog 16)
