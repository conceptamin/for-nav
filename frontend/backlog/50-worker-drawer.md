# 50. 홈 밖의 화면에서 여는 메뉴 서랍

상태: 완료
의존: 없음

## 목표
지금은 `병원 이용 방법` 같은 메뉴에 들어가면 다른 메뉴로 가려면 ←나 로고로 홈에 돌아가야 한다. 홈 밖의 화면에서도 홈의 메뉴로 바로 옮겨 갈 수 있게, 끝 쪽(오른쪽)에서 밀려 들어오는 메뉴 서랍(drawer)을 둔다. 서랍은 앱 바 언어 버튼 옆의 메뉴 버튼으로 연다(2026-10-31 사용자 요청).

## 결정 (2026-10-31 사용자)
1. 자리: 화면 **오른쪽**에서 연다. RTL(ar)에서는 이 앱의 다른 끝 쪽 요소(독, 언어 버튼)처럼 왼쪽으로 뒤집는다
2. 표시: 앱 바 언어 버튼의 오른쪽(끝 쪽) 옆에 같은 모양의 메뉴 버튼(☰). 처음에는 화면 오른쪽 가장자리 가운데의 작은 손잡이로 했지만 "사이드바 불편해, 아이콘을 언어 선택 아이콘 오른쪽에"라는 의견으로 바꿨다
3. 항목: 홈 + 홈의 메뉴 다섯 개(아파요/다쳤어요, 병원 이용 방법, 보험과 지원, 센터에 요청, 내 정보). 지금 화면은 눌린 모양
4. 움직임: 0.2초 밀려 들어오고 막이 옅게 깔린다. 기기가 움직임 줄이기를 켰으면 움직임 없이 바로 뜬다. design.md의 "모달·애니메이션 없음"에 두는 예외다

## 범위
- 하는 것
  - `components/WorkerDrawer.tsx`: 앱 바 메뉴 버튼(`MenuButton`) + 막 + 서랍. Esc·막·✕·메뉴를 누르면 닫히고, 열면 서랍으로 초점이 가고 뒤 화면은 스크롤되지 않는다(센터 채팅 시트와 같다). Esc·막·✕로 닫으면 초점이 메뉴 버튼으로 돌아간다
  - `components/workerMenu.ts`: 홈 목록과 서랍이 같은 메뉴 표를 쓴다
  - 메뉴 버튼은 로그인하고 프로필까지 있고, 홈(`/home`)·첫 화면(`/`)이 아니고, 앱 바를 숨긴 화면이 아닐 때만 보인다. 서랍과 센터 채팅 시트는 하나만 열린다
  - 119 독은 서랍·막 위에 그대로 보이고 눌린다. 서랍은 독 위에서 끝난다
  - 새 문구 키 `menu`(메뉴 버튼·서랍 이름) 20개 언어
- 하지 않는 것
  - 화면 가장자리 손잡이·밀어서 열기(결정 2로 뺐다)
  - 서랍 안 프로필·최근 리포트·언어 변경
  - app-front의 Android 뒤로 가기가 열린 서랍을 먼저 닫게 하기(`app-front/src/bridge/back.ts`, 아래 메모)

## 결과
- `cd frontend && npm run build` → 통과, `cd app-front && npm run build` → 통과
- 단독 모드 360px, 데모 계정으로 확인
  - en `/guide`: 앱 바 왼쪽 알약, 언어 버튼 x 219~292, 메뉴 버튼 x 300~344(둘 다 위 6px·높이 44px, 사이 8px, 끝 여백 16px). 누르면 서랍이 x 60~348, y 12~688(독 위)에 열리고 `How to use a hospital`이 `aria-current`, 메뉴 버튼 `aria-expanded="true"`. 초점은 서랍, 뒤 화면 `overflow: hidden`
  - Esc·✕로 닫으면 초점이 메뉴 버튼. 서랍 `Insurance & support` → `/coverage`, 서랍 닫힘·스크롤 풀림. 서랍 `Home` → `/home`, 메뉴 버튼 없음
  - zh-CN `/coverage`: 알약 16~114, 언어 버튼 198~292, 메뉴 버튼 300~344, 가로 넘침 없음
  - vi `/center-request`: 여섯 줄 모두 52px 한 줄, 가로 넘침 없음. ko `/my`: `내 정보`가 눌린 모양, 이름 "메뉴"
  - ar `/guide`: 메뉴 버튼 x 16~60(맨 왼쪽), 언어 버튼 68~141, 알약 246~344. 서랍은 x 12~300(왼쪽)에서 열린다
  - 콘솔 오류 없음
- app-front(5192, 호스트 없음) `/coverage`: 서랍이 열리고 `Insurance & support`가 눌린 모양(손잡이 때 확인, 메뉴 버튼은 같은 `WorkerLayout`이라 빌드로 확인)
- 결정: 서랍 열림 상태는 `WorkerLayout`이 갖고(시트와 하나만 열리게), 화면이 바뀌면 닫는다. 닫힌 서랍은 `visibility: hidden`이라 초점·읽기 도구에 잡히지 않는다. 메뉴 버튼은 앱 바 안에 더했을 뿐 ← 버튼과 `.w-header button.back` 선택자는 그대로라 app-front 뒤로 가기는 바뀌지 않는다

## 메모
- app-front의 Android 뒤로 가기(`backPolicy`)는 앱 바 ←를 누른다. 서랍이 열려 있으면 화면이 바뀌면서 서랍이 닫히므로 깨지지는 않지만, 흔한 앱처럼 뒤로 가기가 서랍만 먼저 닫게 하려면 app-front 쪽 작업이 따로 필요하다
- `menu` 문구는 en·ko 말고는 기계 번역 초안이다. vi는 원어민 검수가 필요하다(backlog 16)
