# 35. S-05 "아파요/다쳤어요" 흐름을 덜 정신없고 덜 부담스럽게

상태: 완료
의존: 09 (질문 하나씩 화면), 34-multi-profile-birthdate (지금 프로필의 생년월일·성별)

## 목표
S-05 `/intake`는 실제로 12~13화면인데 숫자 원은 1~4뿐이라, 4번에서 질문이 아홉 번 이어지는 동안 "언제 끝나는지" 보이지 않는다. 또 프로필에 이미 있는 나이·성별을 다시 묻고, 하나만 고르는 질문도 고른 뒤 `다음`을 한 번 더 눌러야 해서 누르는 횟수가 많다. 화면마다 진행이 정직하게 보이고, 묻는 수와 누르는 수가 줄고, 한 화면에 보이는 것이 정돈되게 한다.

## 지금 화면에서 본 것 (360px, ko, 2026-10-31)
1. 숫자 원 1~4: 1 부위 · 2 증상 · 3 자유 입력 · 4 추가 질문. 4에 질문 8~9개(발생 시점·통증·다침·업무 관련·(업무 종류)·나이대·성별·업종·구군)가 들어 있어 4가 9화면 동안 켜져 있다
2. 나이대·성별은 지금 프로필(`Profile.birthDate`·`sex`, 로그인 필수라 늘 있다)과 같은 정보를 다시 묻는다
3. 하나만 고르는 질문(발생 시점·다침·업무 관련·업무 종류·나이대·성별·업종·구군)은 고르기 + `다음` 두 번 눌러야 넘어간다(09에서 "자동으로 넘기지 않는다"로 정한 것)
4. 부위·증상 칩이 글자 길이대로 폭이 들쭉날쭉하게 줄바꿈되어 눈이 흩어진다. 증상 화면 안내 문구가 부위용 "해당하는 곳을 모두 고르세요"(`stepBodyHint`)를 그대로 쓴다
5. 질문 제목(h1) 바로 밑에 첫 선택지가 붙어 있다(간격 없음). 다침 질문만 예/아니요가 바닥 버튼 위에 있어 가운데가 텅 빈다
6. 스크롤하면 내용이 앱 바 알약(←·언어) 밑으로 그대로 지나가 겹쳐 보인다
7. 바닥에 `다음` 띠와 119 독이 두 층으로 쌓여 360×760에서 아래 약 25%를 차지한다
8. 구군 선택지가 ko에서 `중구 · 중구`처럼 같은 말을 두 번 보인다

## 범위
- 하는 것
  - **진행 표시**: 숫자 원(`Steps`)을 얇은 진행 막대 + `3 / 10` 글자로 바꾼다. 분모는 실제 화면 수(부위·증상·자유 입력 + 이번에 물을 질문 수)이고, 업무 관련이 "예"가 되어 업무 종류가 끼면 분모가 하나 는다. 스크린리더에도 "10단계 중 3단계"로 읽힌다(지금은 `aria-hidden`)
  - **프로필로 나이대·성별 채우기**: 지금 프로필의 생년월일→나이대(`domain/`에 순수 함수, 판정일 기준 만 나이), 성별을 `Intake.ageGroup`·`sex`에 넣고 두 질문 화면을 건너뛴다. 프로필이 없거나 생년월일이 비면 지금처럼 묻는다
  - **하나만 고르는 질문은 누르면 바로 다음 화면**: 발생 시점·다침·업무 관련·업무 종류·업종·구군. 바닥 버튼은 아무것도 안 골랐을 때 `건너뛰기`, 이미 고른 채로 돌아왔을 때 `다음`. ←로 돌아오면 고른 값이 그대로 눌려 있다. 통증 슬라이더와 부위·증상(여럿 고르기)·자유 입력은 지금처럼 `다음`을 눌러야 넘어간다
  - **칩을 같은 폭 타일로**: 부위·증상 칩을 2열(가로 360px 기준) 같은 폭 격자로 두고, 묶음 제목은 작게. 증상 화면 안내 문구 키 `stepSymptomHint`를 새로 둔다
  - **간격·배치**: 질문 h1과 선택지 사이 간격을 다른 화면 제목과 같게. 다침 예/아니요를 다른 질문처럼 h1 아래 목록으로 옮긴다(자동 넘김이라 바닥에 붙일 이유가 없어진다)
  - **앱 바 겹침**: 내용이 스크롤되어 앱 바 밑으로 들어가면 앱 바 뒤에 `--card` 흐림 띠가 생겨 글자가 겹쳐 보이지 않게 한다(`.w-footer`와 같은 유리 띠 규칙)
  - **바닥 두 층**: `.w-footer` 띠가 119 독 자리까지 내려와 한 장의 면이 되게 하고(띠 안 위쪽에 주 버튼, 아래쪽에 독), 그 사이 틈을 없앤다. 119 독의 모양·자리·색은 그대로다
  - 구군 선택지는 ko에서 한 번만 보인다
  - `design.md`의 단계 표시·칩·질문 화면·고정 띠 절을 같이 고친다
- 하지 않는 것
  - 질문 추가·삭제, 문구 의미 변경, 열거값(`vocab.ts`) 변경. 답하지 않으면 키가 없는 규칙도 그대로(프로필로 채운 값은 "답한 것"으로 본다)
  - 응급 감지·추출·판정 호출 시점. 증상 다음·자유 입력 다음·마지막 질문 다음에 지금과 같이 돈다
  - 119 독의 모양·문구·자리(backlog 31·33·34 결정), 홈·결과 화면(결과 화면은 36)
  - 애니메이션(진행 막대도 전환 효과 없이 바로 바뀐다)

## 화면·파일
- 화면: S-05 `/intake`. 경로·API 변경 없음. `checkTriage`에 넘기는 `Intake`에 프로필에서 온 `ageGroup`·`sex`가 들어간다(지금도 답하면 들어가는 같은 키)
- 수정: `src/pages/worker/Intake.tsx`, `src/components/common.tsx`(`Steps` → `Progress`), `src/components/WorkerLayout.tsx`(앱 바 스크롤 띠), `src/domain/triage.ts`(`ageGroupFromBirthDate`, `profileAnswers`), `src/styles.css`, `src/i18n/*.ts` 20개, `design.md`
- 새 문구 키: `stepSymptomHint` 하나. 진행은 기본 `progress` 요소(`aria-label` = `intakeTitle`)라 스크린리더가 값을 읽으므로 `stepOf` 키는 두지 않았다

정한 것
- 프로필 값은 최종 판정(`checkTriage`)에만 붙이고 추출(`/api/extract`)에는 보내지 않는다. 서버로 가는 값을 가능한 적게 둔다
- 통증 슬라이더는 끌어 가는 도중이라 자동으로 넘기지 않는다. 답하지 않았으면 바닥 버튼이 `건너뛰기`다
- 구군 이름이 ko에서 `중구 · 중구`로 두 번 보이던 것을 한 번으로 고쳤다
- 바닥 띠 변경은 `.w-footer`를 쓰는 모든 화면(S-02 동의, S-03 프로필, S-11 리포트, S-12 센터 요청)에 함께 적용된다

남은 문제
- 묶음이 바뀔 때 스크롤 등장(backlog 25) 때문에 본문이 잠깐 흐리게 보였다 나타난다. 이 항목 전부터 있던 동작이다

## 메모
- 09의 "자동으로 넘기지 않는다"를 바꾸는 항목이다. ←로 되돌릴 수 있으므로 잘못 누름은 한 번 더 눌러 고친다(2026-10-31 사용자 결정)
- 프로필로 채운 나이대·성별은 API 모드에서 `/api/triage` 본문에 들어간다(지금도 근로자가 답하면 들어가는 키). 서버로 가는 값이 늘어나는 것이라 사용자에게 물었고, 채우기로 정했다(2026-10-31). 요청 형태(키·값)는 그대로라 백엔드 변경은 없다
- 진행 표시는 막대 + `n / N`으로 정했다(2026-10-31 사용자 결정. 숫자 원을 화면 수만큼 늘리는 안, 1~4 원 + 안쪽 `n / N` 안과 비교)
- 앱 바 띠는 backlog 32 "앱 바는 띠 없이 투명"을 스크롤했을 때만 바꾼다. 맨 위에서는 그대로 투명하다
- 새 문구(`stepSymptomHint`, `stepOf`)의 vi는 원어민 검수가 필요하고, en·vi 밖 17개 언어는 기계 번역 초안이다
