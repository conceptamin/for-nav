# 45. 채팅 시트를 흔한 메신저 모양으로, 읽음 표시

상태: 완료
의존: 39 센터 채팅 시트, 44 요청 후 시트 열기, backend 27(읽음 프레임). 한 PR로 낸다

## 목표
2026-10-31 사용자 요청: 하단 채팅 아이콘이 여는 시트가 흔한 채팅 앱과 달라 어색하다. 지금은 시트 안에 들어간 상자(`.chat-log`)가 또 있고, 말풍선마다 "Me · 17:33"이 붙고, 입력줄이 대화와 함께 스크롤되어 아래로 밀려난다. 카카오톡·WhatsApp처럼 머리 / 대화 한 줄기 / 아래에 붙은 입력줄로 바꾸고, 내 글을 상대가 읽었는지 보이게 한다.

## 범위
- 하는 것
  - 시트 틀(`.sheet`)
    - 높이를 내용만큼이 아니라 남은 화면 높이로 고정한다(위로 앱 바 자리만 남긴다). 머리와 입력줄은 고정, 가운데 대화만 스크롤한다
    - 머리: 센터 마크(`/mark.png`) 둥근 36px + 제목(`chatTitle`) + 그 아래 작은 줄(요청 번호 `C-xxxxx`). 📞·💬·✕ 이모지를 독 채팅 아이콘과 같은 선 아이콘 SVG로 바꾼다
    - 요청 번호는 대화 가운데 줄에서 머리 작은 줄로 옮긴다
  - 대화 한 줄기
    - 안내·요청 대화(종류 칩, 보낼 내용, 동의, 보내기)와 채팅 메시지가 같은 스크롤 안에 이어진다. 시트 안에서는 채팅 목록의 들어간 상자를 없앤다(센터 C-02 패널 안은 지금처럼 들어간 상자)
    - "✅ 센터에 보냈어요"·📞 안내·단독 모드 안내는 가운데 정렬 시스템 줄(`.chat-sys`)로 바꾼다. 운영 시간 안내는 색이 뜻을 가지므로 `notice` 그대로 둔다
    - 날짜가 바뀌면 가운데 날짜 줄(언어별 날짜 표기, 새 문구 키 없음)
  - 말풍선(`ChatPanel`, 시트와 센터 C-02 둘 다)
    - 말풍선 위 "나 · 시각"을 지운다. 시각은 말풍선 옆 아래(내 글은 시작 쪽, 상대 글은 끝 쪽)에 작게
    - 같은 사람이 같은 분에 이어 보낸 글은 묶어, 시각·읽음은 묶음 마지막에만. 묶음 마지막 말풍선의 꼬리 쪽 모서리만 작게(4px) 둥글린다
  - 읽음 표시(backend 27)
    - 내 글 묶음 옆 시각 위에 `읽음`(`--brand-fg`) 또는 `안 읽음`(`--ink-2`). 근로자 새 키 `chatRead`·`chatUnread`, 센터는 한국어 고정
    - 내가 읽는 때: 근로자는 시트가 열려 있고 채팅 화면(통화 아님)이고 문서가 보일 때, 센터는 C-02가 보일 때. 그때 상대의 마지막 글 id를 `{type:"read", upTo}`로 보낸다(값이 바뀔 때만)
    - `api/chat.ts`의 `useChat`이 `history.read`와 `read` 프레임으로 `peerReadUpTo`를 들고, `markRead(id)`를 내준다
  - 입력줄: 한 줄짜리 둥근 입력란(글이 길면 4줄까지 늘어난다) + 끝 쪽 44px 둥근 보내기 아이콘 버튼(`aria-label`은 `chatSend`). Enter·Shift+Enter·조합 규칙은 그대로
  - `design.md` "상담 채팅"·"센터 채팅 시트" 표와 "읽음 표시는 없다" 줄을 고친다
  - i18n: 새 키 `chatRead`, `chatUnread`를 20개 언어에
- 하지 않는 것
  - 하단 채팅 아이콘의 안 읽은 수 배지(시트를 한 번 열기 전에는 연결이 없어 따로 정해야 한다)
  - 입력 중 표시, 보내는 중 표시, 메시지 지우기·답장, 사진 보내기
  - 시트 열고 닫는 움직임(애니메이션)
  - 통화 패널 모양(`CallPanel`), S-12 페이지

## 결과
- `cd frontend && npm run build` → 통과(청크 크기 경고만 기존과 같다), `cd app-front && npm run build` → 통과, `cd backend && uv run pytest` → 2849 통과
- 브라우저 확인: Playwright 헤드리스 Chromium, 근로자 360×740, 센터 C-02 1280×860, 저장소에 데모 계정·프로필을 넣어 시작
  - API 모드(dev 5231 + 로컬 백엔드 :8000) en·vi·ko·ar·my·ru: 홈 → 채팅 아이콘 → 종류 → 동의 → 보내기 → 머리 작은 줄에 요청 번호, 아래 칸에 입력줄. 근로자가 두 글을 보내면 한 묶음(시각·읽음 1번) + `안 읽음` → 센터가 `/center/cases/<id>`를 열면 근로자 시트에서 `읽음`. 근로자가 시트를 닫고 센터가 글을 보내면 C-02에 `안 읽음` → 근로자가 시트를 열면 `읽음`. 글 8개를 더 보내도 머리(위 72px)·아래 칸(독 위)이 제자리이고 대화만 스크롤되며 맨 아래가 보인다. 6줄을 쓰면 입력란이 4줄 높이(116px)에서 멈춘다. 새로 고침 뒤 다시 열어도 읽음 상태가 같다. 가로 넘침 없음, 콘솔 오류 없음
  - ar: 말풍선·시각·보내기·머리 버튼 좌우와 줄인 모서리가 뒤집힌다. vi: 제목이 두 줄로 접히고 넘치지 않는다
  - 단독 모드(dev 5232) en: 시트 안 전송 → 머리에 요청 번호, 아래 칸 없음, `talkOffline` 시스템 줄, 대화가 아래에 붙는다
  - C-02 1280px: 패널 안 들어간 목록 + 날짜 줄 + 묶인 말풍선 + `읽음`/`안 읽음` + 둥근 입력줄이 깨지지 않는다
- 결정
  - 채팅 입력줄은 `ChatPanel`이 시트 아래 칸에 포털로 그린다. 요청 대화와 메시지가 한 스크롤에 이어지면서 입력줄만 고정하려는 것이다. C-02는 지금처럼 목록 바로 아래
  - 연결 상태 줄은 머리가 아니라 입력줄 위(아래 칸)에 둔다. 상태와 막히는 보내기 버튼이 한곳에 있어야 이유가 보인다
  - 내 말풍선을 `--brand-2`에서 `--brand`(+ `--on-brand`)로 바꿨다. 옅은 민트는 유리 위에서 상대 말풍선과 잘 갈리지 않았다
  - 읽음 문구는 메신저마다 다른 "1"이나 체크 아이콘 대신 글자(`읽음`/`안 읽음`)로 쓴다. 20개 언어 사용자가 같은 뜻으로 읽게 하려는 것이다
  - 보낸 사람(`chatMe`·`chatCenter`)은 화면에서 빼고 화면 읽기 프로그램용 `.sr-only`로 남겼다
- 남은 문제
  - `field-sizing: content`가 없는 브라우저(옛 Safari)에서는 입력란이 한 줄 높이에서 안쪽 스크롤로 동작한다

## 메모
- design.md는 "말풍선에 꼬리를 달지 않는다", "읽음 표시는 없다"고 정했다. 묶음 끝 모서리를 작게 둥글리는 것과 읽음 표시는 이번 사용자 요청으로 바꾸는 것이다
- 새 키 `chatRead`·`chatUnread`의 vi 문구는 원어민 검수가 필요하다. en·vi를 뺀 17개 언어는 기계 번역 초안이다(backlog 16)
- 서버 쪽은 backend 27. frontend 작업이 backend를 고치지 않는다는 규칙의 예외로, backend 26 ↔ frontend 43처럼 한 PR에 함께 낸다
