# 28. 로고와 앱 이름을 유리 질감 그림으로 바꾼다

상태: 완료
의존: 없음(18·25 위에서 한다)

## 목표
2026-10-31 사용자 요청 "로고 변경하자"와 함께 새 로고 이미지 두 장(마크 1254×1254, 마크 + `for nav` 워드마크 2000×667, 둘 다 WebP)을 받았다. 모양은 지금 마크와 같은 둥근 십자 + 화살표이고, 십자 면이 한 색 틸에서 밝은 틸 그러데이션의 유리 질감으로 바뀌었다. 파비콘·로고 화면·앱 바·스플래시·센터 머리글이 모두 `/logo.png` 한 파일을 쓰므로 그 파일을 갈아 끼운다. 같은 날 사용자 요청 "for nav 글씨도 바껴야지"에 따라, 앱 이름 글자도 워드마크의 유리 질감 둥근 글자 그림으로 바꾼다.

## 범위
- 하는 것
  - 받은 마크 이미지에서 바깥 흐린 바탕(틸·하늘색 구름)과 아래 반사광을 걷어 내고 십자만 남긴 투명 PNG를 만든다. 화살표 자리는 지금처럼 투명이라 놓인 바탕색이 비친다
    - 십자 면은 빨강 채널이 낮고(≤160) 바탕 구름·반사광은 높다(≥190). 빨강 채널 178 미만을 십자로 보고, 가장 큰 덩어리만 남기고, 하이라이트로 생긴 작은 구멍을 메우고, 아래 팔 테두리(원본 y≈1036) 밑의 반사광 띠를 버린다
    - 십자에 딱 맞춰 정사각으로 자르고, 알파를 곱한 채로 384×384로 줄여 가장자리가 계단 지지 않게 한다(스플래시 96px을 3배 화면에서도 선명하게. 지금 256px)
  - `public/logo.png`를 새 파일로 바꾼다. 경로·이름이 같아 코드 참조는 고치지 않는다
  - 워드마크 이미지에서 마크를 뺀 `for nav` 글자만 같은 방법으로 따내 `public/wordmark.png`(487×128, 투명)를 만든다. 글자 바닥(원본 y≈511) 밑의 반사광은 버리고, o·a 속 빈 자리는 투명으로 남긴다
  - 앱 이름 글자가 보이는 세 곳을 이 그림으로 바꾼다. `alt`는 지금 글자(`appName`)라 화면 읽기 프로그램에는 그대로 "for nav"로 읽힌다. 앱 이름은 모든 언어에서 번역하지 않는 고유 이름이라(18) 그림 하나로 된다
    | 자리 | 높이 |
    |---|---|
    | 스플래시 `.w-splash h1` | 36px |
    | S-03 로고 화면 `.w-logo h1` | 28px |
    | 홈 앱 바 `.w-header .title` | 20px |
  - `styles.css`에 `.wordmark`(블록, 크기는 `img`의 `width`·`height` 속성), `design.md` 브랜드 단락·`.w-splash` 설명, `README.md`·`CLAUDE.md`의 `public/` 목록을 고친다
- 하지 않는 것
  - 브라우저 탭 제목(`document.title`)·센터 머리글 글자는 그대로 글자다(그림을 넣을 수 없거나 기관 이름이 주인인 자리)
  - 웹폰트로 글자를 그리는 방법(웹폰트 내려받기를 하지 않는다)
  - 브랜드 색 토큰(`--brand` `#12979A`)·`theme-color` 변경. 새 마크는 그보다 밝은 틸(`#4dd6cf` 안팎)이지만, 토큰은 글자·버튼 대비 계산이 걸려 있어 따로 본다(`## 메모`)
  - 크기·자리·`alt` 변경, SVG 전환(SVG 원본이 아직 없다)

## 결과
- 실행(2026-10-31, 브랜치 `frontend/logo-refresh`)
  - `npm run build` → 통과(기존 500kB 청크 경고만). `dist/logo.png` 384×384 RGBA
  - `npm run preview`를 헤드리스 Chromium으로 열어 확인(Claude in Chrome 확장이 연결되지 않아 대신 썼다)
    - 360px 스플래시: 가운데 96px 새 마크, 바깥 흐린 바탕·반사광 띠 없음, 화살표 자리로 바닥 그러데이션이 비친다
    - 360px S-01 `/`: 좌측 상단 28px 새 마크(`naturalWidth` 384)
    - 1280px `/center`: 머리글 글자 앞 24px 새 마크
    - 파비콘: `<link rel="icon">`이 `/logo.png`(200)를 가리킨다
- 결정 사항
  - 화살표 자리는 받은 그림처럼 흰색으로 칠하지 않고 지금처럼 투명으로 둔다(18의 규칙, 어느 바탕에서나 바탕색이 비친다)
  - 크기를 256 → 384px로 올렸다(스플래시 96px × 3배 화면). 파일은 18KB → 81KB
- 워드마크(같은 날 추가)
  - `npm run build` → 통과
  - Tailscale 주소로 띄운 `npm run dev`를 헤드리스 Chromium 360px로 확인: 스플래시(36px), `/signup` ko(28px, 아래 `appTag` 줄 그대로), `/home` ko·vi·ar(20px, 마크 오른쪽. ar은 오른쪽 위에 마크 + 글자 그림, 언어 선택과 겹치지 않음). 모두 `naturalWidth` 487, `scrollWidth` 360
  - #124 병합 뒤 최신 main(로그인해야 `/home`에 들어간다)으로 옮겨 다시 확인: `npm run build`·app-front 빌드 통과, 스플래시·`/signup` 워드마크 그대로. `/home` 앱 바는 Google 로그인이 있어야 들어가 새 기반에서는 다시 보지 못했다(앱 바 코드는 링크 조건만 다르다)

## 메모
- 원본(WebP 두 장)은 채팅으로 받았고 저장소에 넣지 않았다. 배경 제거는 Pillow·NumPy·SciPy 일회성 스크립트로 했다(의존성 추가 없음)
- 새 마크가 `--brand`보다 밝아, 28px 앱 바에서는 흰 바닥 위 윤곽이 지금보다 옅다. 브랜드 색을 마크 쪽으로 옮길지는 대비 계산과 함께 따로 정한다
