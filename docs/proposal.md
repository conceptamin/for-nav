# 콘셉타민 서비스 기획안

기준일: 2026-10-24 · 상태: 목표 기획, 구현 완료를 뜻하지 않음

## 1. 서비스와 목적

콘셉타민은 외국인 주민이 자신의 언어로 의료이용의 어려움을 상담하고, 정리된 내용을 센터 상담사에게 전달해 실제 지원으로 이어지게 하는 AI 기반 상담 서비스다. for-nav는 이 서비스를 구현하는 저장소다.

사용자는 텍스트 채팅으로 상황을 설명하고, AI는 필요한 정보를 추가로 확인한다. 상담사는 원문·한국어 요약·보험 확인 상태를 받아 상담과 기관 연계를 이어간다. 외국인의 의료이용 장벽을 낮추고 센터의 반복적인 정보 수집·번역·기록 업무를 줄이는 것이 목적이다.

## 2. 대상과 문제

대상은 의료이용에 도움이 필요한 외국인 주민이다. 부상자나 근로자로 제한하지 않는다. 울산 센터 업무를 출발점으로 삼되 실제 운영 주체와 지원 지역은 센터와 확인한다.

사용자는 한국어로 상황을 설명하거나 예약·접수·필요서류·보험 정보를 이해하기 어렵다. 상담사는 초기 질문, 번역, 누락 정보 확인과 기록을 반복해야 한다.

| 상담 유형 | 요청 예시 |
|---|---|
| 병원 이용 | 병원에 가고 싶은데 접수 방법을 모르겠어요 |
| 예약·서류 | 처음 방문할 때 무엇을 가져가야 하나요? |
| 통역 | 진료받을 때 한국어로 설명하기 어려워요 |
| 보험 확인 | 제가 어떤 보험에 가입했는지 모르겠어요 |
| 비용·지원 | 병원비가 부담돼서 상담받고 싶어요 |
| 증상·상황 전달 | 몸이 불편한 상황을 상담사에게 설명하고 싶어요 |

## 3. 사용자 흐름

언어 선택 → 텍스트 채팅 → 필요한 정보 확인 → 요약 검토·수정 → 전달 동의 → 센터 접수 → 추가 상담·기관 연계 → 결과 확인.

1. 선호 언어를 선택하고 “어떤 도움이 필요하세요?”로 시작한다. 자유 입력과 상담 유형 선택 버튼을 함께 제공한다.
2. AI는 이미 답한 내용을 활용하고 필요한 질문을 한 번에 하나씩 한다. ‘모르겠어요’, ‘건너뛰기’, 답변 수정을 제공한다.
3. 상담 목적에 필요한 정보만 수집한다. 가입 시 키·몸무게·흡연·음주 등의 건강정보를 일괄 요구하지 않는다. 호칭·연락처 등은 상담 저장·회신에 필요한 시점에 요청한다.
4. 보험 확인이 도움이 되는 경우 조회 또는 정보 제출을 제안한다. 모든 사용자에게 세 보험 확인을 강제하지 않는다.
5. 사용자는 자신의 언어로 정리된 내용을 읽고 수정하며 전달할 항목을 확인한다. 보험 조회, 외부 AI 전송, 센터 전달은 각각 목적을 구분해 동의받는다.
6. 상담사는 원문과 한국어 요약을 바탕으로 이어서 상담한다. 사용자는 같은 상담 화면에서 직원의 질문과 처리 상태를 확인한다. AI와 직원의 메시지는 명확히 구분한다.
7. 간단한 안내로 해결되면 종료할 수 있다. 센터 지원이 필요한 경우에 접수·인계하며, 긴급 도움 경로는 로그인이나 긴 문답 완료에 종속시키지 않는다.

## 4. 보험 확인 범위

첫 버전은 보장 분석보다 상담에 필요한 가입·자격 확인 상태 정리에 집중한다. 특정 사고나 치료에 적용되는지, 보험금이 지급되는지는 판단하지 않는다.

| 보험 | 확인 목표 | 제약 |
|---|---|---|
| 건강보험 | 자격·가입 확인 상태 | 제공받는 항목과 조회 시점의 의미를 확인해야 함 |
| 산재보험 | 사업장 가입 확인 상태와 필요한 근로 관련 정보 | 개인보험과 같은 개인 가입 여부로 단순화하지 않음. 조회 단위·항목 별도 검증 |
| 개인보험 | 가입 확인 여부, 확보 가능한 보험사·상품명 | 전체 보험사 조회인지 일부 조회인지 확인 범위 표시 |

각 결과에는 출처(사용자 답변 / 제출 서류 / 연동 조회 / 상담자 확인), 확인 날짜, 확인 범위와 미확인 사항을 함께 둔다. 사용자 진술을 조회로 검증된 사실처럼 표시하지 않는다. 조회 실패·인증 불가·지원하지 않는 대상·사용자 모름은 미가입이 아니다.

예시(합성): 건강보험 ‘가입했다고 답변함 · 사용자 입력’, 산재보험 ‘미확인’, 개인보험 ‘예시보험 가입 내역 확인 · 제출 서류 기준’.

자동 조회는 아직 가능성이 검증되지 않았다. 이용 자격, 제공 항목, 외국인 본인인증 수단, 비용·계약 조건을 확인한 뒤 포함 여부를 결정한다. 조회가 안 되거나 사용자가 거절해도 상담은 계속한다. 인증 비밀번호나 인증번호를 채팅으로 받지 않는다.

## 5. 화면과 상담사 리포트

| 화면 | 기능 |
|---|---|
| 언어 선택·시작 | 언어 설정, 상담 유형 선택, 자유 입력 |
| 사용자 채팅 | 텍스트·선택 버튼, 수정, 추가 질문, 직원 응대 |
| 요약·보험 카드 | 정리된 정보, 출처·날짜·범위, 미확인 항목 |
| 전달 확인 | 내용 수정, 전달 항목·동의 확인, 접수 |
| 상담사 목록 | 상담 유형, 담당자, 처리 상태 |
| 상담사 상세 | 한국어 요약, 원문·번역, 보험 확인 상태, 추가 질문, 처리 기록 |

리포트는 기본정보(필요한 호칭·언어·연락·지역), 핵심 요청, 상황 요약, 출처가 표시된 정보, 관련 보험 확인 상태, 추가 확인 항목, 원문·번역, 담당자와 처리 결과로 구성한다. AI 추정을 사실로 채우지 않으며 상담사가 수정할 수 있어야 한다.

처리 상태의 초안은 ‘작성 중 → 접수 → 검토 중 ↔ 추가 확인 필요 → 연계 완료/상담 종결’이다. 안내만으로 종결한 건과 실제 기관 연계 완료를 구분한다. 배정·전환 권한과 상세 상태값은 API 설계 시 확정한다.

## 6. 역할과 데이터 설계 원칙

| 담당 | 역할 |
|---|---|
| AI | 다국어 이해·번역, 상황 구조화, 추가 질문, 요약 |
| 일반 시스템 | 인증·동의, 저장·전달, 담당자·상태 관리, 알림 |
| 데이터 연동 | 허용된 범위의 보험 조회, 출처·확인 시점 기록 |
| 상담사 | 불명확한 내용 확인, 상담, 기관 연계, 결과 기록 |

대화 기록과 별도로 상담 건의 구조화된 상태를 유지한다. 질문과 요약·리포트가 같은 상태를 사용하고, 정보가 어느 발언·자료에서 나왔는지 추적 가능하게 한다. 모델이 접수 완료나 조회 성공을 임의로 선언하지 않도록 실제 처리 결과를 사용한다.

센터 인계와 후속 상담에는 서버 저장 및 사용자·상담사 접근 제어가 필요하다. 보관·삭제 기준, 수집 범위, 동의 철회 처리, 본인 상담 접근 방식은 구현 전 확정한다. 요청 본문·인증정보를 일반 로그에 남기지 않는다. 외부 AI에는 필요한 항목만 보내며 서비스 사용자 자료를 학습 데이터로 전용하지 않는다. 개발·데모에는 합성 데이터를 사용한다.

## 7. MVP와 제외 범위

필수 흐름은 모국어 채팅 → 정보 구조화 → 사용자 검토·동의 → 센터 접수 → 상담사 추가 질문 → 처리 결과 기록이다.

포함: 우선 지원 언어의 텍스트 채팅, 선택 버튼, 요약·수정, 보험 확인 상태와 출처, 센터 접수·담당자·상태 관리, 후속 상담·연계 기록.

연동 검증 후 결정: 건강보험·산재보험·개인보험 자동 조회. 연동 전에는 사용자 답변·제출 자료·상담자 확인으로 진행하며 mock은 예시임을 표시한다.

초기 제외: 질병 진단, 보험 적용·보험금 지급 판단, 전체 약관·보장 상세 분석, 병원 자동예약, 실제 진료비 산정, 음성 상담. 별도 응급 모델 학습은 필수 MVP로 확정하지 않는다. 긴급 도움 경로와 안전 대응은 유지하되 구체적인 감지·운영 기준은 별도 검증한다.

## 8. 검증과 성과

| 지표 | 방법 |
|---|---|
| 초기 상황 파악 시간 | 기존 상담과 도입 후 소요시간 비교 |
| 반복 질문 | 이미 받은 답을 상담사가 다시 묻는 빈도 |
| 정보 누락 | 상담 시작 시 목적별 필요한 정보 누락 |
| 요약 품질 | 사실 오류, 상담사 수정량, 미확인 정보 보존 |
| 접근성 | 언어별 완료율과 이탈, 건너뛰기·인증 실패 후 상담 지속 |
| 지원 연결 | 접수 후 상담 완료와 실제 기관 연계 완료를 각각 측정 |

부상 사례 외에 예약·서류·통역·보험 문의를 포함한다. 조회 실패, 사용자 거절, 잘못된 번역 수정, 상담사 추가 질문, 외부 AI 실패도 검증한다. 목표 수치와 표본은 센터와 정하고 측정 전 성과를 주장하지 않는다.

## 9. 구현 전 확정할 사항

- 센터의 접수·필수 확인·담당자 배정·종결 업무와 실제 운영 주체.
- 우선 지원 언어와 번역 검수 담당. 기존 en·vi는 후보이며 지원 확정으로 간주하지 않는다.
- 보험별 원본 제공처, 직접 연동 조건, 민간 대안, 외국인 인증, 반환 항목·조회 범위.
- 상담 가능 시간, 응답 기준, 회신·알림 수단.
- 인증, 역할별 접근 권한, 보관·삭제·동의 철회 정책.

## 10. 기존 문서와 구현 전환

이 문서가 2026-10-24 이후 제품 기획의 기준이다. 영역별 책임은 [프론트](../frontend/docs/proposal.md), [백엔드](../backend/docs/proposal.md), [모델링](../modeling/docs/proposal.md)에 둔다.

[API v1](api-contract.md)은 이전 산업보건 내비게이터 기획의 계약 초안이다. 이번 문서 개정은 API 스키마·코드·fixtures를 변경하지 않는다. 기존 무인증·서버 미저장 계약으로 새 상담 시스템이 구현된 것으로 간주하지 않는다.

기존 frontend/backend phase-01 실행 기반 기록은 보존한다. frontend/backend phase-02와 modeling phase-01 계획은 이전 범위로 보존하고 새 구현의 지시서로 사용하지 않는다. 다음 구현 전에 새 인증·상담 저장·인계 API 계약과 영역별 phase를 작성하고, 계약 변경 시 코드·fixtures를 함께 갱신한다. 날짜별 기능 일정은 재산정한다.
