# 조선소 대형차 AI 운행 지원 서비스 기술 기획서

### 구간 소요 시간 예측·온디바이스 온라인 보정·경로 탐색 및 통행 조정

**문서 범위:** 서비스 구현을 위한 모델 구성, 데이터 설계, 처리 흐름 및 검증 계획  
**구현 목표:** 가상 조선소에서 차량 이동 시간을 예측하고, 차량별 운행 특성을 반영해 경로와 통과 순서를 안내하는 해커톤 MVP

## 1. 기술 목표

본 시스템은 참여 차량의 위치와 이동 정보를 활용해 다음 기능을 구현한다.

1. 차량 조건과 도로 통제를 반영한 경로 탐색
2. 협소 구간 입구까지의 도착 소요 시간과 구간 통과 시간 예측
3. 실제 운행 결과에 따른 차량별 예측 오차 보정
4. 반대 방향 차량의 예상 구간 점유 시간 비교
5. 현장 운영 규칙에 따른 대기 위치와 통과 순서 안내

도착까지 남은 시간은 **도착 소요 시간**, Test-Time Adaptation과의 혼동을 피하기 위해 차량별 학습 방식은 **온디바이스 온라인 적응**으로 표기한다.

## 2. 시스템 구성

```text
[가상 차량 / 위치 수집 장치]
위치·속도·방향·구간 진입·이탈 정보
                │
                ▼
[차량 단말기]
입력 정보 생성
→ CatBoost 기본 시간 예측
→ 차량별 온라인 오차 보정
                │
                │ 현재 상태 + 보정된 예상 시간
                ▼
[사업장 내부 관제 서버]
지도·도로 통제 관리
→ 다익스트라 경로 탐색
→ 구간 점유 시간 중첩 확인
→ 통과 순서·대기 위치 결정
                │
                ▼
[운전자 화면]
경로 / 반대편 접근 / 대기 안내 / 안내 확인
```

| 구성 요소 | 역할 |
|---|---|
| 차량 단말기 | 자기 차량의 상태 처리, 시간 예측, 운행 기록 저장, 온라인 보정 |
| 내부 관제 서버 | 전체 차량 상태 통합, 경로 탐색, 협소 구간 예약 관리 |
| 관리자 화면 | 도로 통제, 작업 우선순위 설정, 차량 상태 확인 |
| 시뮬레이터 | 가상 차량 이동, 위치 이벤트, 실제 소요 시간 생성 |

온라인 적응을 단말기에서 수행하더라도 차량 간 통행 조정에는 내부 정보 공유가 필요하다.

## 3. 모델 및 알고리즘 선정

| 기능 | 선정 방식 | 적용 목적 |
|---|---|---|
| 기본 소요 시간 예측 | **CatBoostRegressor** | 거리·속도·회전·차량 조건에 따른 비선형 시간 예측 |
| 차량별 오차 보정 | **온라인 선형회귀** | 완료된 운행 결과를 이용한 점진적 보정 |
| 경로 탐색 | **다익스트라 알고리즘** | 통행 가능한 도로 중 최소 비용 경로 탐색 |
| 마주침 판단 | **시간 구간 중첩 검사** | 협소 구간의 반대 방향 점유 가능성 확인 |
| 통행 조정 | **규칙 기반 구간 예약** | 진입 상태·대기 공간·작업 우선순위에 따른 순서 결정 |

CatBoost는 첫 구현 후보이며, 랜덤포레스트 회귀 및 단순 시간 계산과 비교해 채택 여부를 결정한다. 예측 성능과 단말기 실행 비용을 측정하기 전에는 우수성을 확정하지 않는다.

## 4. 데이터 설계

### 4.1. 지도·운영 데이터

가상 지도를 그래프로 표현한다. 교차로·대기 지점·목적지는 노드, 도로 구간은 간선으로 구성한다.

| 데이터 | 주요 항목 |
|---|---|
| 노드 | ID, 좌표, 종류, 대기 가능 여부 |
| 도로 구간 | 시작·종료 노드, 길이, 폭, 방향, 통제 여부 |
| 통행 제약 | 차량·화물 크기 제한, 회전 제한 |
| 협소 구간 | 구간 ID, 양쪽 진입 지점, 대기 지점 |
| 작업 정보 | 차량 ID, 작업 우선순위, 목적지 |

지도상 물리적 통행 가능 여부와 운영상 우선순위는 별도 속성으로 관리한다.

### 4.2. 실시간 차량 데이터

| 항목 | 용도 |
|---|---|
| 차량 ID | 상태·모델·기록 연결 |
| 측정 시각과 수신 시각 | 정보 지연 및 유효성 판단 |
| 현재 구간·위치·진행 방향 | 접근 구간과 경로 확인 |
| 현재 속도·최근 속도 이력 | 이동 시간 예측 |
| 차량·화물 크기 | 통행 제약 적용 |
| 목적지·예정 경로 | 입력된 경우 이후 이동 예측 |
| 접근·진입·이탈 이벤트 | 구간 예약 상태 변경 |
| 안내 수신·대기 확인 상태 | 양쪽 차량의 안내 이행 확인 |

GPS 등 연속 위치 정보를 사용하는 방식과 구간 감지 이벤트를 사용하는 방식을 구분한다. 후자는 정보 해상도가 낮으므로 동일한 도착 시간 정밀도를 가정하지 않는다.

### 4.3. 학습 데이터

학습 단위는 **특정 시점의 차량 상태와 목표 지점까지 실제로 걸린 시간**이다.

```text
입력:
남은 거리, 현재 속도, 최근 평균 속도,
최근 가속·감속, 회전 여부, 차량 종류·크기

정답:
관측 시점부터 목표 지점 도달까지 실제 소요 시간
```

입력에는 예측 시점에 알 수 있는 정보만 사용한다. 실제 전체 구간 평균 속도처럼 운행 종료 후에야 알 수 있는 값은 입력에서 제외한다.

통행 조정으로 발생한 대기 시간은 이동 시간과 별도로 기록한다. 이를 차량의 기본 이동 특성으로 학습하지 않도록 한다.

### 4.4. 데이터 확보 방식

- **공개 차량 궤적 데이터:** 기본 예측 모델의 개발·평가에 사용
- **가상 조선소 데이터:** 협소 구간, 차량 우선순위, 통제 상황의 통합 시험에 사용
- **현장 경험:** 시뮬레이션 조건과 운영 규칙의 현실성 검토에 사용

공개 데이터의 실제 제공 항목을 확인한 뒤 입력 변수를 확정한다. 공개 도로에서의 예측 성능과 가상 조선소에서의 서비스 동작 결과는 구분해 보고한다.

## 5. 기본 소요 시간 예측

### 5.1. 예측 대상

동일한 시간 예측 모듈을 활용하되 다음 두 값을 구분한다.

- **접근 시간:** 현재 위치에서 협소 구간 입구까지 남은 시간
- **통과 시간:** 협소 구간 진입 후 이탈까지 필요한 시간

목적지까지의 예상 시간은 경로상 구간별 이동 시간과 계획된 대기 시간을 합산한다.

### 5.2. CatBoost 모델

수치형 운행 정보와 차량 종류·회전 유형 등의 범주형 정보를 입력받아 소요 시간을 예측한다.

초기에는 작은 모델로 시작하고 트리 깊이·개수 등을 제한한다. 모델 크기는 예측 오차, 추론 지연, 메모리 사용량을 함께 측정해 결정한다.

학습 완료 모델은 버전을 부여해 배포하며, 차량 단말기에서 기본 모델 자체를 계속 재학습하지 않는다.

### 5.3. 예측 불확실성 처리

예측값을 정확한 도착 보장으로 사용하지 않는다. 검증 데이터의 오차를 바탕으로 여유 시간을 설정하고, 차량 상태와 데이터 품질에 따라 적용한다.

다음 상황에서는 초 단위 안내를 제한한다.

- 차량이 정지했고 출발 시점을 알 수 없는 경우
- 위치 정보 갱신이 중단된 경우
- 목적지 미입력으로 이후 진행 방향이 불확실한 경우
- 모델이 학습한 조건에서 크게 벗어난 경우

## 6. 온디바이스 온라인 오차 보정

### 6.1. 보정 구조

기본 예측에 차량별 보정값을 더한다.

```text
최종 예상 소요 시간 = 기본 예상 소요 시간 + 차량별 예상 오차 보정값
```

- **기본 예상 소요 시간:** CatBoost가 예측한 소요 시간
- **차량별 예상 오차 보정값:** 온라인 선형회귀가 예측한 오차 보정값

기본 예측이 30초이고 보정값이 +6초이면 최종 예측은 36초가 된다. 이는 설명용 예시다.

### 6.2. 학습 순서

1. 예측 당시 입력과 기본 예측값을 저장한다.
2. 현재 보정 모델로 최종 시간을 예측한다.
3. 목표 지점 도달 후 실제 소요 시간을 확인한다.
4. **업데이트 전 예측**으로 성능을 평가한다.
5. `실제 소요 시간 - 당시 기본 예측`을 정답으로 보정 모델을 업데이트한다.

같은 운행 결과를 먼저 학습한 뒤 예측 성능을 평가하지 않는다.

### 6.3. 초기 보정 입력

데이터가 적은 초기에는 보정 모델의 입력을 제한한다.

- 기본 예측 시간
- 최근 평균 속도
- 남은 거리
- 회전 여부

차량별 기록이 적으면 보정값을 0으로 시작하거나 적용 비중을 낮춘다. 범주별 모델을 지나치게 세분화하지 않는다.

### 6.4. 보정 제어

- 학습률과 보정값의 범위를 제한한다.
- 오류가 있는 위치·시간 기록은 학습에서 제외한다.
- 단말기 재시작 후에도 보정 상태를 복원할 수 있게 저장한다.
- 보정 전후 오차를 함께 추적한다.
- 성능 악화가 지속되면 보정을 중단하고 기본 모델로 복귀한다.

이 방식은 실제 결과가 뒤늦게 제공되는 **온라인 지도학습**이며, 정답 없는 비지도 TTA와 구분한다.

## 7. 경로 탐색

### 7.1. 탐색 전 제약 적용

다음 도로는 해당 차량의 탐색 대상에서 제외한다.

- 차량·화물이 통과할 수 없는 폭의 도로
- 회전 조건을 만족하지 못하는 도로
- 통제 중인 도로
- 진행 방향이 허용되지 않는 도로

### 7.2. 도로 비용

초기 MVP에서는 도로별 비용을 다음처럼 정의한다.

```text
도로 비용 = 보정된 예상 이동 시간 + 현재 계획된 대기 시간
```

비용은 음수가 되지 않도록 처리한다. 이를 이용해 다익스트라로 경로를 계산한다.

대기 시간은 차량 도착 시점과 다른 예약에 따라 달라질 수 있으므로, MVP는 **현재 상태를 기준으로 비용을 고정해 탐색하는 근사 방식**을 사용한다. 전체 차량의 동적 최적 경로를 보장한다고 주장하지 않는다.

도로 통제나 예약 변경이 발생하면 재탐색하되, 운전자 안내가 지나치게 자주 바뀌지 않도록 변경 조건을 둔다.

## 8. 마주침 판단 및 통행 조정

### 8.1. 예상 점유 시간

현재 시각에 접근 시간과 통과 시간을 더해 협소 구간의 예상 진입·이탈 시각을 계산한다.

반대 방향 차량의 예상 점유 시간이 여유 시간을 포함해 겹치면 통행 조정 대상으로 분류한다.

| 차량 | 예상 진입 | 예상 이탈 |
|---|---:|---:|
| A | 현재부터 20초 후 | 50초 후 |
| B | 현재부터 35초 후 | 60초 후 |

위 예시에서는 점유 시간이 겹치므로 진입 전에 순서를 조정한다.

### 8.2. 구간 예약 상태

```text
비어 있음 → 예약됨 → 진입 확인 → 점유 중 → 이탈 확인 → 비어 있음
```

한 구간에 서로 충돌하는 예약이 동시에 확정되지 않도록 관제 서버가 상태 변경을 일괄 관리한다.

### 8.3. 통과 순서 결정

1. 이미 진입한 차량과 구간 점유 상태 확인
2. 양쪽 차량이 안전하게 대기할 수 있는지 확인
3. 차량·화물의 이동 제약 반영
4. 관리자가 지정한 작업 우선순위 반영
5. 대기 시간과 반복 양보 여부 반영

예측 시간이 지났다는 이유만으로 구간을 해제하지 않는다. 실제 이탈이 확인되지 않으면 확인 필요 상태를 유지한다.

운전자 안내는 물리적 진입을 막는 장치가 아니므로, 안내 미확인·미이행 상황도 별도로 처리한다.

## 9. 해커톤 구현 환경

| 영역 | 초기 구현안 |
|---|---|
| 모델 학습 | Python, CatBoost, 비교용 scikit-learn |
| 온라인 보정 | River 기반 온라인 선형회귀 |
| 관제 API | FastAPI |
| 실시간 상태 전달 | WebSocket |
| 경로 탐색 | Python 그래프 로직 또는 NetworkX |
| 운전자·관제 화면 | 웹 기반 지도와 상태 UI |
| 기록 저장 | SQLite 및 CSV |
| 시뮬레이터 | 시간 단계별 차량 이동 및 이벤트 생성 |

노트북에서 차량별 독립 프로세스로 단말기를 모사할 수 있다. 이 경우 결과는 **온디바이스 구조를 모사한 데모**로 표현한다. 실제 휴대폰이나 차량 단말기에 배포하기 전에는 해당 장치에서 모델 실행·업데이트 비용을 별도로 확인한다.

## 10. 검증 계획

### 10.1. 모델 비교

| 비교군 | 목적 |
|---|---|
| 거리·속도 기반 계산 | 학습 없는 기준 성능 |
| 랜덤포레스트 회귀 | 기본 비교 모델 |
| CatBoost 회귀 | 기본 예측 모델 후보 평가 |
| CatBoost + 이동평균 보정 | 단순 보정의 효과 확인 |
| CatBoost + 온라인 선형회귀 | 조건별 온라인 적응의 추가 효과 확인 |

온라인 선형회귀가 이동평균보다 유의미하게 낫지 않으면 단순 보정 방식을 채택한다.

### 10.2. 데이터 분리

같은 운행의 인접 시점 기록이 학습·평가 양쪽에 섞이지 않도록 운행·차량·기록 세션 단위로 분리한다.

온라인 보정은 시간순으로 **예측 → 평가 → 업데이트**한다. 이미 본 차량의 적응 성능과 처음 보는 차량의 성능을 별도로 측정한다.

### 10.3. 평가 지표

| 영역 | 지표 |
|---|---|
| 시간 예측 | 평균 절대 오차, 큰 오차의 분포, 도착 시간을 과소 추정한 오차 |
| 온라인 적응 | 보정 전후 오차, 성능 악화 빈도, 적응에 필요한 기록 수 |
| 단말기 비용 | 추론 시간, 업데이트 시간, 모델 크기, 메모리 |
| 통행 조정 | 반대 방향 동시 진입 횟수, 후진 횟수, 차량별 대기 시간 |
| 전체 효율 | 운행 완료 시간, 반복 대기 차량 발생 여부 |

### 10.4. 예외 상황

- 차량이 협소 구간 내부에서 멈춤
- 위치 정보가 늦게 도착하거나 끊김
- 대기 공간이 사용 불가능함
- 운전자가 안내와 다르게 이동함
- 목적지 없는 차량이 분기점에서 회전함
- 우선 작업 차량이 연속 접근함
- 온라인 보정 후 예측 오차가 커짐

예외 상황에서 불확실성을 숨기지 않고, 안내 제한·상태 확인·기본 모델 복귀가 작동하는지 확인한다.

## 11. 구현 순서와 산출물

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 가상 지도·차량 시뮬레이터 | 접근·진입·이탈 기록 생성 |
| 2 | 다익스트라·통행 규칙 | 학습 없이 길 안내와 순서 조정 작동 |
| 3 | 기본 시간 예측 모델 | 독립 평가 데이터에서 기준 계산과 비교 |
| 4 | 차량별 온라인 보정 | 시간순 평가와 성능 악화 대응 작동 |
| 5 | 화면·관제 통합 | 경로·접근·대기 안내 일관성 확인 |
| 6 | 비교 데모 | 모델 오차와 통행 결과를 함께 표시 |

최종 산출물은 가상 지도와 시나리오 설정, 예측 모델, 차량별 보정 모듈, 관제·운전자 화면, 평가 결과표로 구성한다.

## 기술 제안 요약

> 사전 학습한 회귀 모델로 구간 소요 시간을 예측하고, 차량 단말기가 실제 운행 결과로 오차를 점진적으로 보정한다. 내부 관제는 보정된 예상 시간과 도로 상태를 이용해 경로를 탐색하고 협소 구간의 통과 순서를 조정한다.
