# for-nav 모델링 기획서

작성일: 2026-10-21 · 기준 문서: 울산 외국인 근로자 산업보건 내비게이터 기획안(보완판 2)

## 1. 목적

근로자가 모국어로 쓴 증상 문장이 응급인지 가려내는 이진 분류 모델을 직접 만든다. 백엔드는 이 모델과 키워드 규칙 중 하나라도 응급이면 119 안내를 띄운다. 모델이 놓친 응급을 규칙이 잡고, 규칙에 없는 표현을 모델이 잡는 구조다.

- [공통 API 계약](../../docs/api-contract.md) 3장 `emergency`
- [백엔드 기획서](../../backend/docs/proposal.md)

자체 모델을 쓰는 이유: 응급 기준을 팀이 통제하고 설명할 수 있고, 호출 비용이 들지 않으며, 가벼워서 나중에 기기 안으로 옮길 수 있다. MVP에서는 FastAPI 서버에서 실행한다.

하지 않는 일: 작업 관련성 분류(산재 판정으로 오해될 수 있어 제외), 진료과 분류(규칙 대응 표로 대체).

## 2. 모델

| 항목 | 내용 |
|---|---|
| 유형 | 이진 분류 (응급 / 비응급) |
| 주요 지표 | 재현율 최우선, 그다음 정밀도 |
| 기본 모델 | TF-IDF + 로지스틱 회귀 |
| 비교 | 다국어 임베딩 + 분류기, LLM 제로샷(참고) |
| 개선 방법 | 오분류 분석(검증셋), 울산 시나리오 보강, 임계값 조정 |
| 언어 | `en`, `vi` |

## 3. 데이터

| 구분 | 출처 | 용도 |
|---|---|---|
| 재해 사례 | 안전보건공단(KOSHA) 재해 사례 | 울산 산업별 사고 유형 파악, 시나리오 작성 |
| 합성 문장 | LLM으로 만든 다국어 증상 문장 | 학습 데이터 보강 |
| 외부 공개 데이터 | 사용 조건을 확인한 공개 데이터셋(후보와 라이선스는 [phase-01](phase-01.md)) | 학습·검증 보강. 테스트셋에는 넣지 않음 |
| 사람이 쓴 문장 | 팀원이 직접 쓴 영어 문장 80~100개(비원어민 말투), 이 중 응급 30개 이상. 베트남어는 번역 후 역번역 검사 | 검증·최종 테스트셋 |

울산 시나리오:

| 지역 | 주요 산업 | 예시 |
|---|---|---|
| 동구 | 조선 | 용접 후 눈 통증, 도장 작업 중 두통·구역, 고소작업 추락, 끼임 |
| 북구 | 자동차 부품 | 프레스 작업 중 손 부상, 반복작업 손목·어깨 통증 |
| 공통 응급 신호 | 밀폐공간·화학물질 작업 | 작업 중 어지럼·호흡곤란, 의식 저하 |

분할 규칙: 사람이 쓴 문장을 검증셋과 최종 테스트셋으로 나눈다. 최종 테스트셋은 2026-10-22에 고정하고 개선 과정에서 열람하지 않는다. 같은 시나리오에서 나온 문장 변형(번역본 포함)은 같은 쪽에 둔다.

## 4. 평가와 발표

| 지표 | 측정 방법 | 목표(예시) |
|---|---|---|
| 응급 감지 재현율 | 사람이 쓴 테스트 문장 중 응급 30개 이상, 모델 + 규칙 합산. 분자·분모 함께 | 95% 이상 |
| 응급 오탐률 | 비응급 문장을 응급으로 판정한 비율. 너무 높으면 근로자가 119 안내를 무시하게 됨 | 측정 후 보고 |
| 번역 품질 | 역번역 의미 일치율 | 90% 이상 |

- 모델 단독과 모델 + 규칙 합산을 둘 다 적는다. 규칙 합산 평가는 백엔드 규칙 목록을 같은 버전으로 불러와 계산한다.
- 합성 문장, 팀원이 쓴 문장, 외부 데이터 기준의 차이를 숨기지 않는다.
- 테스트셋 규모와 응급 문장 수를 수치 옆에 항상 적는다.
- 목표치는 예시이며 측정 후 실제 값으로 바꾼다.

## 5. 내보내기

백엔드가 코드를 실행하지 않고 읽을 수 있는 형식으로 내보낸다. TF-IDF + 로지스틱 회귀는 어휘, IDF, 가중치, 절편, 임계값, 전처리 설정을 JSON 하나에 담을 수 있다. 파일에는 `model_version`, 학습 데이터 해시, seed, 생성일을 넣는다. 백엔드는 같은 전처리를 다시 구현하므로, 모델링은 입력 문장 몇 개와 기대 점수를 함께 내보내 백엔드 테스트가 일치를 확인하게 한다.
