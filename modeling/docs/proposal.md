# for-nav 모델링·평가 기획서

기준일: 2026-10-24 · 목표 기획 · 기준: [공통 기획서](../../docs/proposal.md)

## 1. 목적과 역할

다국어 상담의 정보 추출·추가 질문·번역·요약이 상담사 인계에 유용한지 평가한다. 독립 응급 분류 모델 학습을 서비스의 필수 중심 기능으로 고정하지 않는다. 모델 학습이 필요한지는 실제 실패 사례와 비교 평가를 바탕으로 정한다. 백엔드는 LLM 호출과 서비스 서빙, 모델링 영역은 평가 기준·데이터·품질 분석을 담당한다.

## 2. 평가 대상

| 대상 | 확인할 내용 |
|---|---|
| 상담 정보 추출 | 요청·상황·명시한 사실의 정확성, 근거 연결 |
| 질문 | 이미 답한 내용 반복 여부, 필요한 누락만 질문하는지 |
| 번역 | 원문의 의미·불확실성·숫자·보험사명 보존 |
| 요약 | 없는 사실 생성, 중요 정보 누락, 상담사 수정량 |
| 보험 상태 표현 | 사용자 진술/서류/조회 구분, 미확인·실패를 미가입으로 바꾸지 않음 |
| 인계 | 사용자 제외 항목 미포함, 상담사가 이어서 처리할 수 있는지 |
| 긴급 도움 | 도움 경로를 가리는 응답이나 근거 없는 안심 표현이 없는지 |

보험 가입이나 적용 여부를 모델이 추론해 정답처럼 채우지 않는다. 비부상 상담(예약·서류·통역·보험 문의)을 포함한다.

## 3. 데이터와 평가 원칙

개발용 합성 시나리오와 팀원이 작성한 평가 사례를 사용한다. 실제 서비스 사용자 자료를 학습·평가 데이터로 전용하지 않는다. 외부 데이터는 사용 조건·식별정보 제거·출처를 확인해야 한다.

새 상담 평가셋은 기존 응급 감지 테스트셋과 별도로 설계한다. 기존 `modeling/data/test/`는 열람·수정하거나 프롬프트 조정에 사용하지 않는다. 번역본·문장 변형은 같은 시나리오 그룹으로 묶고 개발용과 최종 평가용을 분리한다. 평가 항목·담당자·언어·표본·판정 기준은 새 phase에서 확정한다.

원어민 검수가 없는 언어는 검수 완료로 표기하지 않는다. 언어·상담 유형별 표본 수, 맞은 수/전체 수, 사실 오류와 상담사 수정량을 보고한다. 성능 목표를 달성 결과처럼 쓰지 않는다.

## 4. 기존 모델 연구와 전환

[이전 phase-01](phase-01.md)의 TF-IDF·로지스틱 회귀 응급 분류 연구 계획은 과거 범위로 보존한다. 실제 산출물 존재나 성능을 주장하지 않는다. 해당 연구를 계속 사용할지는 별도로 정하며, 이번 문서 변경으로 학습·데이터 다운로드·테스트셋 변경을 실행하지 않는다.

다음 단계는 센터와 요약 품질 기준 합의 → 비부상 사례를 포함한 평가 설계 → 백엔드 구조화 출력과 맞춘 사례 작성 → 새 phase에서 평가 명령·완료 조건 확정이다. 운영 성과(상담 시간·실제 연계 완료)는 공통 기획서 8장에 따라 센터와 측정한다.
