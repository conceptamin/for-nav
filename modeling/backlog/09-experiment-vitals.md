# 09. 발표용 실험: 활력징후 포함 모델 vs 버튼 피처 모델

상태: 완료
의존: 04

## 목표
같은 데이터·분할에서 활력징후를 넣은 모델과 버튼 피처만 쓴 모델의 응급도 성능을 비교해, 버튼만으로 어디까지 되는지와 한계를 발표 자료로 정리한다. 서빙 모델에는 영향을 주지 않는다.

## 범위
- 하는 것
  - `features/vitals.py`: 수축기·이완기 혈압, 심박수, 호흡수, 체온, 산소포화도. 결측 처리 방식 기록
  - `scripts/experiment_vitals.py`: 버튼 전용 / 버튼+활력징후 두 모델을 같은 seed·분할로 학습, 검증셋 비교(응급 재현율, 클래스별 지표, 혼동행렬)
  - `reports/experiment_vitals.md`와 그림(혼동행렬 2개, 재현율 비교 막대)
- 하지 않는 것
  - 활력징후 모델 내보내기, 서빙 경로 변경

## 입력·출력
- 입력: `data/processed/triage.parquet`, `data/splits/triage_*`, `models/acuity.py`
- 출력: `reports/experiment_vitals.md`, `reports/figures/`

## 완료 기준
- [x] 두 모델의 검증 지표가 분자·분모와 함께 한 표에 있음
- [x] 차이가 어디서 나는지(어느 클래스, 어느 피처) SHAP으로 한 단락 설명
- [x] `features/vitals.py`가 `predict.py`에서 import되지 않음(테스트)
- [x] 테스트셋은 쓰지 않음(검증셋 비교로 끝낸다)

## 결과
- 실행(2026-10-29). `main`(d215b11)에서 만든 `modeling/experiment-vitals` 브랜치
  - `uv run python scripts/download_data.py --verify` → 세 출처 해시 일치. `uv run python scripts/make_splits.py` → `data/splits/` 변경 없음
  - `uv run python scripts/experiment_vitals.py` → 3.7초. `reports/experiment_vitals.{json,md}`, `reports/figures/experiment_vitals_{confusion,recall}.png`. 두 번 돌려 다섯 파일 sha256이 같음을 확인했다
  - `uv run ruff check . && uv run ruff format --check .` → `All checks passed!`. `uv run pytest` → `180 passed`(기존 176 + `tests/test_experiment_vitals.py` 4)
- 만든 것
  - `src/fornav_modeling/experiment_vitals.py`: 피처 행렬(버튼 피처 34개 뒤에 활력징후 6개), 학습, 검증셋 비교, SHAP 요약, 보고서·그림. 모델은 내보내지 않는다
  - `scripts/experiment_vitals.py`: 위 함수를 부르기만 하는 명령
  - `features/vitals.py`는 그대로 쓴다(이미 있었다). `tests/test_experiment_vitals.py`가 `predict` import 시 `features.vitals`·`experiment_vitals`가 올라오지 않는지, 피처 행렬 순서·결측, 같은 seed → 같은 모델을 확인한다
- 설정
  - 같은 train(823)·valid(190) 분할, `acuity.LGBM_PARAMS`, seed `20261028`, 라운드 수는 train 안 층화 5겹 교차검증 조기 종료(04와 같은 규칙). 로지스틱 비교는 하지 않았다
  - **버튼 전용 쪽은 응급도 v0 LightGBM과 같다**: 모델 sha256이 `models/acuity/v0/metadata.json`과 같고 라운드 86, 임계값 0.0738도 같다
  - 결측: 활력징후의 "측불"(측정 불가)·빈칸은 NaN 그대로 LightGBM에 넘긴다(분기마다 결측 방향을 학습). 채우지 않았다. train 결측: sbp 11 / 823, dbp 15 / 823, hr 8 / 823, rr 10 / 823, bt 9 / 823, **saturation 446 / 823**. valid: saturation 112 / 190, 나머지 5~10 / 190
  - 임계값은 설정마다 따로 valid에서 정했다(응급 재현율 ≥ 95% 중 정밀도 최대, 04와 같은 규칙). 버튼 0.0738, 버튼 + 활력징후 0.0500
- **valid(190건, 실제 응급 37건)**. 칸은 분자 / 분모

| 설정·규칙 | 응급 재현율 | 응급으로 본 건수 | 오늘 병원 재현율 | 외래 재현율 | 정확도 |
|---|---|---|---|---|---|
| 버튼 argmax | 25 / 37 | 34 / 190 | 47 / 73 | 66 / 80 | 138 / 190 |
| 버튼 + 활력징후 argmax | 23 / 37 | 34 / 190 | 49 / 73 | 61 / 80 | 133 / 190 |
| 버튼 임계값 | 36 / 37 | 99 / 190 | 26 / 73 | 50 / 80 | 112 / 190 |
| 버튼 + 활력징후 임계값 | 36 / 37 | **124 / 190** | 16 / 73 | 42 / 80 | 94 / 190 |

- 참고: train+valid 층화 5겹 교차검증(1,013건, 응급 197건). 임계값은 valid로 정한 값이라 valid 행에 낙관적이다

| 설정·규칙 | 응급 재현율 | 응급으로 본 건수 | 정확도 |
|---|---|---|---|
| 버튼 argmax | 119 / 197 | 165 / 1,013 | 738 / 1,013 |
| 버튼 + 활력징후 argmax | **128 / 197** | 171 / 1,013 | 737 / 1,013 |
| 버튼 임계값 | 184 / 197 | 500 / 1,013 | 616 / 1,013 |
| 버튼 + 활력징후 임계값 | 190 / 197 | 588 / 1,013 | 554 / 1,013 |

- **결론: 이 데이터에서는 활력징후를 더해도 응급도가 뚜렷이 나아지지 않았다.** valid에서는 오히려 나빴다. 응급 재현율 95%를 맞추려면 응급으로 보는 건수가 99 → 124 / 190으로 늘고, 그만큼 오늘 병원(26 → 16 / 73)·외래(50 → 42 / 80)를 응급으로 올린다. 교차검증 argmax에서는 응급 재현율이 119 → 128 / 197로 조금 오르지만, 응급 재현율 95% 근처의 운영점에서는 응급으로 보는 건수가 함께 늘어(500 → 588) 거짓 경보를 줄이지 못한다. valid 응급이 37건이라 1건이 2.7%p여서, 두 설정의 차이는 표본 흔들림 안에 있다고 본다
- **SHAP(valid, 클래스별 평균 |SHAP|)**: 버튼 + 활력징후 모델은 응급 클래스 판단의 **43.3%**를 활력징후에 둔다(sbp 0.245, saturation 0.205, hr 0.184, bt 0.145). 오늘 병원·외래는 26.3%·25.8%. 활력징후가 들어오면 버튼 피처 중 나이대(0.358 → 0.266), 통증 점수(0.297 → 0.160), 의식 상태(0.223 → 0.146)의 몫이 줄어든다. 가슴 부위(0.386 → 0.310)는 그대로 1위다. 즉 모델은 활력징후를 많이 쓰지만, 그 정보가 나이·통증·의식 같은 버튼 피처와 겹쳐 새로 가르는 행이 적다. 또 saturation은 train의 절반 이상(446 / 823)이 결측인데 **측정한 행의 응급 비율이 103 / 377, 결측 행은 57 / 446**이다. saturation 기여의 일부는 값이 아니라 "의료진이 재기로 했는가"라는 판단에서 온다. 앱 사용자는 이 값을 줄 수 없다
- 발표에 쓸 말: 버튼 입력만으로도 활력징후를 더한 모델과 응급도 성능이 비슷했다. 버튼 입력의 한계(test 응급 재현율 85.7%, 04·10)는 활력징후가 없어서라기보다 데이터가 작고(응급 train 160건) 주증상 매핑이 거친 데서 온다. 놓치는 응급은 레드플래그 119 규칙이 모델 앞에서 먼저 잡는다
- 남은 문제
  - 실험이 valid 190건(응급 37건)에 기댄다. 차이를 단정하려면 더 큰 데이터(README의 MIMIC-IV-ED 선택 항목)가 필요하다
  - 활력징후 결측 여부를 따로 피처로 넣거나 채우는 비교는 하지 않았다(범위 밖)

## 메모
- 결과가 "활력징후가 훨씬 낫다"로 나와도 그대로 적는다. 발표에서는 버튼 입력의 한계와 119 규칙으로 보완하는 구조를 함께 설명한다
