# 모델링 작업 규칙

루트 `CLAUDE.md`, [모델링 기획서](docs/proposal.md), [공통 계약](../docs/api-contract.md) 3장, [백엔드 기획서](../backend/docs/proposal.md)를 먼저 읽는다. phase 문서는 `modeling/docs/phase-XX.md`에 쓴다. 지정된 phase의 범위만 구현하고 검증 결과를 같은 문서에 남긴다. 다른 영역에 의존하면 그 영역의 phase 문서 경로를 적는다. 아직 코드·데이터·실행 명령이 없으며 [phase-01](docs/phase-01.md)에서 준비한다.

## 범위와 스택

`modeling/`의 응급 감지 이진 분류 모델(응급 / 비응급), 학습 데이터, 최종 테스트셋, 평가, 모델 내보내기를 담당한다. 모델을 불러와 API로 서빙하는 일과 응급 키워드 규칙은 백엔드 책임이다.

Python 3.11, uv(`pyproject.toml`, `uv.lock`), scikit-learn(TF-IDF + 로지스틱 회귀), pandas를 기준으로 한다. 다국어 임베딩 + 분류기와 LLM 제로샷은 비교용이다. 버전은 phase-01에서 공식 문서·PyPI로 확인해 고정한다.

## 데이터 폴더

```text
modeling/data/synthetic/  LLM으로 만든 다국어 증상 문장 (학습 보강)
modeling/data/human/      팀원이 직접 쓴 문장 중 검증셋 (임계값·오류 분석용)
modeling/data/external/   사용 조건을 확인한 외부 공개 데이터 (학습·검증용, 출처별 하위 폴더, git에 올리지 않음)
modeling/data/test/       최종 테스트셋 (2026-10-22 고정, 열람 금지)
```

## 불변 조건

- `modeling/data/test/`는 2026-10-22에 분리·고정한 뒤 학습, 임계값 조정, 오류 분석, 프롬프트 작성에 쓰지 않는다. 파일을 열어 보지도 않는다. 이 폴더를 읽는 코드는 평가 명령 하나뿐이다. 테스트셋을 바꿔야 하면 사람에게 묻고 이유를 phase 문서에 남긴다.
- 테스트셋은 팀원이 쓴 문장만 담고 응급 문장을 30개 이상 넣는다. 합성 문장과 외부 데이터는 테스트셋에 넣지 않는다.
- 임계값은 검증셋으로만 정한다. 재현율(recall)을 최우선으로 하고 그다음 정밀도를 본다.
- 성능은 항상 분자·분모와 함께 적는다(예: 응급 30개 중 29개). 합성 문장, 팀원이 쓴 문장, 외부 데이터(출처별) 기준을 나눠 적는다. 개선 라운드별(v0 → 1라운드 → 최종) 수치를 남긴다.
- LLM 제로샷이 더 좋게 나와도 결과를 숨기지 않는다.
- 학습·평가 데이터는 합성 문장, 팀원이 쓴 문장, 사용 조건을 확인한 외부 공개 데이터다.
- 외부 데이터는 실제 사람이 쓴 기록이어도 아래를 모두 만족하면 쓴다. 라이선스가 학습·평가 사용을 허락한다(비상업 조건이면 비상업 용도에만). 이름·연락처·사업장명 같은 식별 정보가 없거나 지운 뒤 넣는다. 출처 URL, 라이선스, 확인 날짜, 내려받은 파일의 sha256, 라벨 변환 규칙을 phase 문서에 남긴다. 라이선스 표시가 없는 데이터는 쓰지 않는다.
- LLM이 만든 외부 데이터는 합성 문장으로 분류한다.
- 우리 서비스 사용자의 입력은 어떤 경우에도 넣지 않는다(서버는 저장하지 않는다).
- 내보내는 모델은 불러올 때 코드를 실행하지 않는 형식이다(예: 어휘·가중치를 담은 JSON). pickle·joblib을 쓰지 않는다. 모델 버전, 학습 데이터 해시, seed, 임계값을 함께 기록한다.
- 측정 전 우수성을 적지 않는다.

## 검증 기준

같은 seed로 학습을 두 번 돌려 같은 모델 해시가 나오는지, 평가 명령이 `data/test/` 외의 데이터를 평가에 섞지 않는지, 학습 명령이 `data/test/`를 읽지 않는지(파일 열기를 막은 상태에서 학습이 끝나는지) 테스트한다. 평가 결과에는 재현율·정밀도·오탐률과 각각의 분자·분모, 데이터 출처별 분리 수치가 있어야 한다.
